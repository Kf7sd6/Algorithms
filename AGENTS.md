# Инструкции ассистентам: индивидуальный курс алгоритмов

## Читать при входе

1. `CURRENT_PROGRESS.md` — единственный актуальный учёт знаний пользователя.
2. `ai/context.md` — устойчивые цели и границы.
3. Последнюю подходящую запись `ai/sessions/`, указанную в прогрессе.
4. Файл текущей темы в `topics/` и её входные требования.

При подготовке конспектов дополнительно читать `ai/materials/README.md`, ближайший пакет в `ai/materials/status.md` и его карточку в `ai/materials/module-map.md`. Редакционный учёт готовности текстов не заменяет учебный прогресс.

Не перечитывать весь архив и все источники на каждой сессии, если текущая задача этого не требует. При вопросе о действующих учебных требованиях сверять текущие страницы преподавателя, особенно если с момента проверки прошло время или пользователь сообщил об изменениях.

## Как учить

- Начальный уровень по алгоритмам нулевой; даже структуры данных объясняются с нуля. Знание термина не предполагается.
- Сначала конкретные данные, действия и ручной пример; затем определение, обоснование и код. Новые обозначения вводить явно.
- Использовать русские математические термины и аккуратную общепринятую запись. Не требовать англоязычную терминологию вместо смысла.
- Не давать несколько крупных новых тем за одно занятие. При усталости уменьшать шаг.
- Новую учебную сессию начинать с короткого воспроизведения нужного предыдущего материала. Проверять вопросами/примером; не превращать это автоматически в большой экзамен.
- Сложность проговаривать с параметром размера, случаем и моделью. Не смешивать ожидаемую, амортизированную и худшую оценки.
- На задаче сначала давать собственную попытку; помощь повышать постепенно. Полный ответ по прямой просьбе пользователя допустим, но потом нужна новая проверка самостоятельного владения.
- C++ — рабочий выбор из курса преподавателя, владение им пока не подтверждено. До кода допустимы русский алгоритм и псевдокод. Не навязывать второй язык или переустановку среды.

## Подготовка полноценных учебных материалов

Пользователь поручил подготовить план создания достаточно полных конспектов по источникам и разнообразной практики, включая доказательства, с ростом сложности без перегрузки. План находится в `ai/materials/README.md`, карта M00–M21 — в `ai/materials/module-map.md`, шаблон — в `ai/templates/material.md`.

- Писать самостоятельное объяснение: постановка → конкретный пример → идея/состояние → точный алгоритм → корректность/завершение → вывод времени/памяти → границы применения. В начале курса формальность наращивается постепенно.
- Использовать действительно прочитанные фрагменты первичных источников; оглавление или страница издателя не подтверждает проверку доказательства. Недоступное и замены фиксировать честно.
- Сохранять паспорта `topics/` и ID исходных упражнений. Новые полные пакеты писать в `materials/Mxx/`: конспект, практика, отдельная помощь и разборы. Ссылки добавлять после создания файлов.
- Различать основной проход, согласованное продолжение темы и необязательное углубление. Не терять трудные операции/доказательства за отметкой «первый проход готов».
- На основной проход обычного модуля выбирать 4–6 небольших обязательных заданий всего, в широком модуле 6–8, разнесённых по частям. Переиспользовать исходные задачи, дробить составные с сохранением происхождения; не прибавлять новый набор поверх старого. На занятие обычно 1–2 задачи.
- Перед готовностью решить обязательные упражнения, проверить ответы, доказательства, примеры и включённый код. Результат подготовки передавать через `ai/materials/status.md` и новую запись сессии; учебные статусы без занятия не менять.

Следующая авторская задача — пилотный M01. Его выпуск проверяет формат перед расширением остальных модулей; учебный порядок M00/M01 по диагностике сохраняется. Детали ближайшего шага находятся в редакционном учёте, а не поддерживаются второй копией здесь.

## Приоритеты и порядок

Отмечены главы второго издания Кормена 4,7,8,9,10,11,12,16,18,19,20,22,23,24,32,34. Карта — `roadmap/04-priorities-and-editions.md`. В третьем издании номера сложных куч отличаются. Всегда проверять название темы, а не только номер.

Не добавлять целиком неотмеченные главы только потому, что они есть в другой программе. Если нужна предпосылка, объяснить её назначение, ограничить объём и записать изменение. Текущие связки — базовый анализ, простые сортировки, вероятность для ожидания, двоичная куча, DSU для Краскала и потенциал для фибоначчиевой кучи.

Числа M00–M21 задают рекомендуемую последовательность. Для веток использовать таблицу зависимостей, а не выдумывать условие «сначала все предыдущие файлы». Учебный темп, сроки и результаты не придумывать.

## После каждой учебной сессии

1. Сначала восстановить, что пользователь реально сделал и с какой помощью.
2. Добавить новую запись в `ai/sessions/` по `ai/templates/session.md`; не переписывать прежние записи.
3. Обновить `CURRENT_PROGRESS.md`: модуль, статус, проверенное свидетельство, долг, повторение и следующий маленький шаг; сослаться на новую запись.
4. При изменении маршрута добавить запись в `ai/decisions.md`, затем изменить затронутые документы. Ненужную повторную копию прогресса не создавать.
5. Убедиться, что связанные относительные ссылки ведут к существующим файлам.

Прочитанный конспект и созданная учебная программа не являются освоенной темой. Для B-дерева явно различать поиск, вставку и удаление; для сложных куч — механику, доказательство оценок и проверенный код; для NP-полноты — обзор опорной теоремы и самостоятельное сведение.

Перед новым изменением читать актуальную ветку, проверять существующие файлы и вложенные `AGENTS.md`. Не использовать устаревший архив как источник текущего учебного прогресса. Не перезаписывать параллельные изменения: публикация коммита должна сохранять историю и проверять исходную вершину ветки.
