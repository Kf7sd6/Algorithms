## Объяснение и порядок разбора

Очередь с приоритетом выдаёт элемент с наименьшим или наибольшим ключом, а не самый ранний по времени добавления. Зафиксируем **минимальную кучу**: ключ родителя не больше ключа каждого ребёнка. При таком свойстве минимум находится в корне; произвольный элемент не обязан занимать позицию согласно общему порядку.

В двоичной куче дерево полное по уровням, последний уровень заполняется слева. Это позволяет хранить его в массиве: для индекса i дети имеют индексы `2i+1` и `2i+2`, а родитель при i>0 — `(i−1)/2`. Высота O(log n) получается из формы дерева. Это другое условие, чем порядок левого и правого поддеревьев у BST.

Добавление помещает элемент в конец и просеивает вверх. Извлечение минимума заменяет корень последним элементом, уменьшает размер и просеивает вниз, выбирая меньшего ребёнка. Обе операции имеют O(log n) работы; чтение минимума O(1). При динамическом массиве учитываем возможное расширение; оценки самой процедуры просеивания и всей операции с выделением памяти разделяем.

Построение кучей снизу за O(n) сначала выглядит неожиданно. Причина: большинство узлов находятся близко к листьям и проходят очень короткий путь. Оцениваем сумму работы по высотам, вместо грубого n·log n для n отдельных вставок.

Нужен также смысл `decrease_key`: уменьшить приоритет уже известного элемента и восстановить свойство. Для эффективного поиска позиции элемента потребуется дополнительное соответствие идентификатора и индекса; стандартная `priority_queue` C++ такого метода напрямую не предоставляет. В графовых задачах сначала можно хранить новые записи и пропускать устаревшие.

Полная глава о пирамидальной сортировке не является отдельным приоритетом. Саму сортировку кучей достаточно один раз вывести из операций, чтобы закрепить структуру. Главное здесь — подготовка к Приму, Дейкстре и сливаемым кучам.

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M11-P1.** Проверить массив [1,4,2,7,5,3] как минимальную кучу. Выполнить insert(0) и extract_min, записывая обмены.

**M11-P2.** Реализовать push, min, pop и build_heap. Сравнить последовательность извлечений с отсортированной копией входа.

**M11-P3.** Объяснить на уровнях дерева линейность build_heap. Сравнить с построением отдельными вставками.

**M11-P4.** Хранить k наибольших чисел потока, используя кучу размера k. Дать время через n и k и память через k.

## Когда можно двигаться дальше

- [ ] Не путаю форму дерева и порядок ключей.
- [ ] Сам просеиваю элемент вверх и вниз.
- [ ] Обосновываю build_heap за O(n) и знаю, что произвольный поиск в куче может быть линейным.

## Частые ошибки

- Считать весь массив кучи отсортированным.
- Пользоваться BST-логикой поиска в куче.
- Обновлять приоритет записи без восстановления свойства кучи.
