# M04. Подсказки и разборы

Открывай по одному блоку. После полного разбора проверь ту же идею на другом коротком входе. Код рассчитан на условия [практики](practice.md); заголовки и исполнимая программа — в [search.cpp](search.cpp).

## M04-P1

<details>
<summary>Подсказка 1</summary>

Первая середина всегда имеет индекс 2. Равенство с `x` относит середину к правой известной части: мы ищем первое подходящее место.

</details>

<details>
<summary>Подсказка 2</summary>

Если `a[mid] < x`, переноси `l` в `mid+1`. Иначе переноси `r` в `mid`. При `l = r` не читай элемент; равенство границ уже даёт ответ.

</details>

<details>
<summary>Полный разбор</summary>

Во всех четырёх трассах `a = [1,3,3,8]`, `n = 4`. Границы в таблице указаны **до** сравнения.

| `x` | `l` | `r` | `mid` | `a[mid]` | `a[mid] < x` | Новые `l, r` |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 0 | 4 | 2 | 3 | нет | 0, 2 |
| 0 | 0 | 2 | 1 | 3 | нет | 0, 1 |
| 0 | 0 | 1 | 0 | 1 | нет | 0, 0 |
| 3 | 0 | 4 | 2 | 3 | нет | 0, 2 |
| 3 | 0 | 2 | 1 | 3 | нет | 0, 1 |
| 3 | 0 | 1 | 0 | 1 | да | 1, 1 |
| 4 | 0 | 4 | 2 | 3 | да | 3, 4 |
| 4 | 3 | 4 | 3 | 8 | нет | 3, 3 |
| 9 | 0 | 4 | 2 | 3 | да | 3, 4 |
| 9 | 3 | 4 | 3 | 8 | да | 4, 4 |

| `x` | Состояние остановки `l = r` | Левая часть `< x` | Правая часть `≥ x` | Ответ |
| --- | --- | --- | --- | --- |
| 0 | 0 | пустая | весь массив | 0 |
| 3 | 1 | `[1]` | `[3,3,8]` | 1 |
| 4 | 3 | `[1,3,3]` | `[8]` | 3 |
| 9 | 4 | весь массив | пустая | 4 |

Для 3 нельзя остановиться на первой середине: индекс 2 содержит тройку, но первая тройка имеет индекс 1. Для 4 ответом является позиция восьмёрки; наличие четвёрки из этого не следует. Для 9 ответ равен `n`, обращения к `a[4]` нет.

Длины неизвестных частей: для 0 и 3 — `4 → 2 → 1 → 0`; для 4 и 9 — `4 → 1 → 0`. Поэтому сравнений соответственно 3, 3, 2, 2. В каждой трассе обе внешние части сохраняют нужные отношения к `x`.

</details>

## M04-P4

<details>
<summary>Подсказка 1</summary>

Проверь участок из единственного элемента, который меньше искомого значения. Чему равна середина участка длины 1?

</details>

<details>
<summary>Подсказка 2</summary>

При `r = l+1` середина равна `l`. Ошибочное присваивание `l = mid` не меняет ни одной границы. Как исключить уже проверенный элемент и сохранить все возможные подходящие позиции?

</details>

<details>
<summary>Полный разбор</summary>

Возьмём `a = [0]`, `x = 1`. В начале `l = 0`, `r = 1`, `mid = 0`. Сравнение `0 < 1` истинно, но присваивание `l = mid` снова записывает ноль. После итерации имеем то же состояние `(0,1)`. Оно повторяется бесконечно; мера `r−l` остаётся равной 1.

Правильная строка — `l = mid+1`. Элемент в середине уже оказался меньше `x`; он не может быть ответом. Для приведённого входа сразу получается `(1,1)`, ответ 1 — подходящего элемента нет.

В общем случае `l ≤ mid < r`. После `l = mid+1` новая левая граница строго больше старой и не больше `r`. После `r = mid` новая правая граница не меньше `l` и строго меньше старой `r`. В обеих ветвях неотрицательная целая длина строго убывает. Поэтому исправленный цикл заканчивается.

Строгое уменьшение доказывает завершение. Для правильности ответа дополнительно нужен инвариант внешних частей из §3: одно завершение само по себе ещё не доказывает результат.

</details>

## M04-P2

<details>
<summary>Подсказка 1</summary>

Напиши, какие значения уже известны слева от `l` и справа от `r`. Если значение в середине равно `x`, может ли до него находиться ещё одно такое же?

</details>

<details>
<summary>Подсказка 2</summary>

Первая функция возвращает позицию даже при отсутствии значения. Во второй сначала проверь, существует ли элемент на этой позиции, и только затем сравни его с `x`. Нужны две проверки с коротким вычислением `&&`.

</details>

<details>
<summary>Полный разбор</summary>

```cpp
int lower_bound_index(const std::vector<long long>& a, long long x) {
    int l = 0;
    int r = static_cast<int>(a.size());
    while (l < r) {
        const int mid = l + (r - l) / 2;
        if (a[mid] < x) {
            l = mid + 1;
        } else {
            r = mid;
        }
    }
    return l;
}

bool contains(const std::vector<long long>& a, long long x) {
    const int pos = lower_bound_index(a, x);
    const int n = static_cast<int>(a.size());
    return pos < n && a[pos] == x;
}
```

Инвариант: `0 ≤ l ≤ r ≤ n`; до `l` значения `< x`, начиная с `r` — `≥ x`. В начале обе известные части пусты. Если середина меньше `x`, неубывание распространяет это на всё слева до неё; переносим `l` за середину. Иначе всё от середины справа не меньше `x`; переносим `r` в середину. Границы остаются допустимыми.

При остановке `l = r = p`. До `p` подходящих элементов нет, а при `p < n` значение в позиции `p` уже подходит. Следовательно, найдено первое значение `≥ x`, либо `n`, если все значения меньше. Длина `r−l` строго убывает, как показано в P4.

Если `a[p] == x`, найдено вхождение. Если `p = n`, вхождений нет. Если существующий `a[p] > x`, все более ранние значения меньше `x`, все более поздние — не меньше `a[p]`, поэтому `x` отсутствует. В C++ проверка `pos < n` стоит первой и запрещает вычисление второй части при отсутствии элемента.

| Массив | `x` | Нижняя граница | Наличие |
| --- | --- | --- | --- |
| `[]` | 0 | 0 | `false` |
| `[0]` | −1 | 0 | `false` |
| `[0]` | 0 | 0 | `true` |
| `[0]` | 1 | 1 | `false` |
| `[−4,1,1,5]` | −9 | 0 | `false` |
| `[−4,1,1,5]` | −4 | 0 | `true` |
| `[−4,1,1,5]` | 1 | 1 | `true` |
| `[−4,1,1,5]` | 3 | 3 | `false` |
| `[−4,1,1,5]` | 5 | 3 | `true` |
| `[−4,1,1,5]` | 6 | 4 | `false` |
| `[−2,−2,−2]` | −2 | 0 | `true` |
| `[−2,−2,−2]` | 0 | 3 | `false` |

На каждом шаге неизвестная длина уменьшается как минимум вдвое с округлением вниз. Для `n ≥ 1` имеем не более `⌊log₂ n⌋+1` сравнений элементов в поиске границы; при пустоте их нет. Проверка наличия добавляет не более одного сравнения на равенство. Дополнительная память Θ(1): несколько машинных переменных без копии массива.

Ограничения длины позволяют хранить индекс в `int` используемой среды, значения до `10¹²` храним в `long long`. Середина не вычисляется через потенциально переполняющуюся сумму `l+r`.

</details>

## M04-P3

<details>
<summary>Подсказка 1</summary>

Нижняя граница отделяет значения `< x` от `≥ x`. Какое условие должно отделять значения `≤ x` от `> x`? Что означает длина полуинтервала между этими границами?

</details>

<details>
<summary>Подсказка 2</summary>

В верхнем поиске первая ветвь должна срабатывать также при равенстве. Затем вычти нижнюю границу из верхней. Отдельно докажи, что между ними не может стоять значение меньше или больше `x`.

</details>

<details>
<summary>Полный разбор</summary>

Нижний поиск берём из P2. Новый код:

```cpp
int upper_bound_index(const std::vector<long long>& a, long long x) {
    int l = 0;
    int r = static_cast<int>(a.size());
    while (l < r) {
        const int mid = l + (r - l) / 2;
        if (a[mid] <= x) {
            l = mid + 1;
        } else {
            r = mid;
        }
    }
    return l;
}

int count_equal(const std::vector<long long>& a, long long x) {
    const int left = lower_bound_index(a, x);
    const int right = upper_bound_index(a, x);
    return right - left;
}
```

Верхний поиск сохраняет утверждение: до `l` значения `≤ x`, начиная с `r` — `> x`. Начало, доступность середины и строгое уменьшение длины совпадают с P2. В первой ветви все значения до середины включительно `≤ x`; во второй все начиная с середины `> x`. Поэтому при остановке получена первая позиция `> x` либо `n`.

Нижняя граница `L` не правее верхней `U`: каждое значение `> x` одновременно `≥ x`. Для любого существующего индекса `i` из `[L,U)` нижний поиск гарантирует `a[i] ≥ x`, а верхний — `a[i] ≤ x`. Значит, `a[i] = x`. Вне этого полуинтервала либо `< x`, либо `> x`, совпадений нет. Длина `[L,U)` равна `U−L` — это и есть искомое количество.

| Массив | `x` | `L` | `U` | Число |
| --- | --- | --- | --- | --- |
| `[−6,2,2,2,10]` | 2 | 1 | 4 | 3 |
| `[−6,2,2,2,10]` | −6 | 0 | 1 | 1 |
| `[−6,2,2,2,10]` | 0 | 1 | 1 | 0 |
| `[−6,2,2,2,10]` | 11 | 5 | 5 | 0 |
| `[]` | 2 | 0 | 0 | 0 |
| `[−3]` | −3 | 0 | 1 | 1 |
| `[−3]` | −4 | 0 | 0 | 0 |
| `[−3]` | 0 | 1 | 1 | 0 |
| `[−3,−3,−3,−3]` | −3 | 0 | 4 | 4 |
| `[−3,−3,−3,−3]` | −2 | 4 | 4 | 0 |

При отсутствии 0 в первом массиве обе границы внутри массива, равны 1. Это не ошибка: после −6 значения сразу перескакивают к 2, и участок совпадений пуст.

Два поиска выполняются последовательно. Для `n ≥ 1` общее число сравнений элементов не больше `2(⌊log₂ n⌋+1)`, плюс постоянная работа с результатами. При `n ≥ 2` время O(log n), при `n = 0/1` — Θ(1). Дополнительная память Θ(1), состояния двух циклов не требуют ни новых массивов, ни растущего стека.

Если вместо второго поиска идти по группе равных обычным циклом, группа может занимать весь массив. Даже начав с найденной двоичным поиском середины, проход к краям такой группы требует Θ(n) действий в худшем случае. Оценка всего запроса станет линейной, хотя начальный поиск был логарифмическим.

</details>
