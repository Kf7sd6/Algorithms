# M04. Линейный и двоичный поиск

Нужно ответить: встречается ли число в данных, где начинается группа равных чисел и сколько их? Сначала проверим элементы по одному. Затем используем их порядок, чтобы после каждой проверки исключать сразу большую часть позиций.

## Перед началом

Нужны индекс, длина и полуинтервал из [M01](../M01/README.md), цикл, инвариант и логарифм из [M02](../M02/README.md). Реализации списков M03 для входа не требуются. Для повторения: какие индексы входят в `[2,5)` и чему равна его длина? Это 2, 3, 4; длина 3.

Код использует `std::vector<long long>` — последовательность целых чисел, обращение `a[i]` и длину `a.size()`. Запись `const ...& a` даёт функции читать исходную последовательность без изменения и копирования. `bool` хранит `true` или `false`. Если синтаксис мешает, сначала выполняй псевдокод.

## 1. Когда о порядке ничего не известно

В массиве `[9, −5, 9, 2]` ищем **первое** вхождение 2. Индекс начинается с нуля.

| Индекс | Прочитано | Равно 2? | Следующее действие |
| --- | --- | --- | --- |
| 0 | 9 | нет | проверить индекс 1 |
| 1 | −5 | нет | проверить индекс 2 |
| 2 | 9 | нет | проверить индекс 3 |
| 3 | 2 | да | вернуть 3 |

Так работает **линейный поиск**. Поиск 9 остановится уже на индексе 0. Чтобы объявить отсутствие 7, придётся проверить все четыре значения: без сведений о порядке любое пропущенное значение могло бы оказаться семёркой.

Во всём этом модуле обозначаем длину через `n`. Для функции линейного поиска договоримся возвращать `n`, если вхождения нет: допустимые индексы элементов только `0…n−1`. В M01 использовался другой явный договор — `−1`; алгоритм тот же, но признак отсутствия надо учитывать при вызове.

```text
linear_first(a, x):
    n ← длина a
    для i от 0 до n−1:
        если a[i] = x:
            вернуть i
    вернуть n
```

При `n = 0` тело цикла не выполняется. В псевдокоде `←` — присваивание, `=` в условии — сравнение.

```cpp
int linear_first(const std::vector<long long>& a, long long x) {
    const int n = static_cast<int>(a.size());
    for (int i = 0; i < n; ++i) {
        if (a[i] == x) {
            return i;
        }
    }
    return n;
}
```

Перед проверкой `i` все предыдущие элементы уже проверены и не равны `x`. Поэтому первое совпадение имеет наименьший индекс. Если цикл завершился без совпадения, проверен весь массив. Завершение следует из увеличения `i` до `n`.

Для первого совпадения на позиции `j` выполняется ровно `j+1` сравнений элементов с `x`; при отсутствии — `n`, при пустоте — 0. Лучший случай для непустого массива — Θ(1), худший — Θ(n). Средний случай без распределения запросов здесь не задаём. Дополнительная память — Θ(1): несколько машинных значений, без копии входа.

## 2. Что даёт порядок

Теперь массив другой: `a = [−5, 0, 0, 6, 9, 14]`. Он **отсортирован по неубыванию**: каждый следующий элемент не меньше предыдущего. Равенства разрешены; отрицательные числа и нули также разрешены.

Требуется найти первую позицию, где значение **не меньше** `x`. Для `x = 0` это индекс 1. Для `x = 4` — индекс 3, хотя самой четвёрки нет. Для `x = 20` такой элемент отсутствует; возвращаем `n = 6`. Для `x = −8` ответ 0.

Это **нижняя граница**, `lower_bound`. Её ответ — позиция между левой частью из значений `< x` и правой из значений `≥ x`. Позиция может совпадать с концом массива. В пустом массиве ответ 0: элементов нет, единственная позиция — его начало и конец.

### От одного сравнения к исключению целой части

Ищем нижнюю границу нуля. Сначала рассматриваем индексы `[0,6)`. Середина — 3, там 6. Всё правее тоже не меньше нуля. Значит, первую подходящую позицию нужно искать левее или взять саму позицию 3. Затем середина оставшегося участка — 1, там 0. Равенство ещё не разрешает остановку: раньше могут находиться другие нули.

Храним две границы, `l` и `r`:

- все индексы **до** `l` уже содержат значения `< x`;
- все индексы **начиная с** `r` уже содержат значения `≥ x`;
- `[l,r)` — ещё не классифицированные индексы элементов.

Первоначально `l = 0`, `r = n`: обе известные внешние части пусты. Массив не меняется; меняется только наше знание о нём.

| Шаг | `l` до | `r` до | `mid` | `a[mid]` | `a[mid] < 0` | Новые `l, r` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 6 | нет | 0, 3 |
| 2 | 0 | 3 | 1 | 0 | нет | 0, 1 |
| 3 | 0 | 1 | 0 | −5 | да | 1, 1 |

Неизвестных индексов больше нет. До позиции 1 лежат числа меньше нуля; с позиции 1 — числа не меньше нуля. Ответ 1.

**Тонкость:** неизвестные *элементы* имеют индексы в `[l,r)`, а искомая *позиция границы* может лежать в **`[l,r]`**, включая `r`. При `r = mid` позиция `mid` остаётся возможным ответом, хотя элемент с этим индексом уже классифицирован. При `r = n` это не означает существования `a[n]`.

Остановка: выполни [M04-P1](practice.md), пока без написания программы. Для каждого нового запроса снова начни с `l = 0`, `r = n`.

## 3. Один точный алгоритм и его доказательство

Если `a[mid] < x`, из неубывания следует: все элементы с индексами не больше `mid` также меньше `x`. Их можно отнести к левой части, установив `l = mid + 1`.

Иначе `a[mid] ≥ x`. Все элементы с индексами не меньше `mid` также не меньше `x`. Относим их к правой части: `r = mid`. Здесь `+1` не нужен: `mid` может оказаться первой подходящей позицией.

```text
lower_bound_index(a, x):
    l ← 0
    r ← длина a
    пока l < r:
        mid ← l + (r−l) div 2
        если a[mid] < x:
            l ← mid + 1
        иначе:
            r ← mid
    вернуть l
```

`div 2` — целочисленное деление неотрицательного числа на 2 с отбрасыванием дробной части.

```cpp
int lower_bound_index(const std::vector<long long>& a, long long x) {
    int l = 0;
    int r = static_cast<int>(a.size());
    while (l < r) {
        const int mid = l + (r - l) / 2;
        if (a[mid] < x) {
            l = mid + 1;
        } else {
            r = mid;
        }
    }
    return l;
}
```

`static_cast<int>` явно переводит длину в выбранный тип индекса. Это допустимо при оговорённых ниже ограничениях; произвольный размер `vector` в `int` переводить без проверки нельзя.

### Инвариант: что остаётся истинным

Перед каждой проверкой цикла:

1. `0 ≤ l ≤ r ≤ n`;
2. для каждого индекса `i < l` верно `a[i] < x`;
3. для каждого индекса `i ≥ r`, принадлежащего массиву, верно `a[i] ≥ x`.

**Начало.** `l = 0`, `r = n`; индексов во внешних частях нет, поэтому утверждения о них выполнены.

**Шаг.** При `l < r` середина удовлетворяет `l ≤ mid < r`. Значит, `a[mid]` существует. В первой ветви неубывание позволяет расширить левую известную часть до `mid` включительно. Во второй — правую известную часть от `mid` включительно. Старые известные части не меняются. Границы остаются в допустимом порядке.

**Ответ.** При остановке `l = r = p`. По инварианту все элементы до `p` меньше `x`, а все от `p` не меньше `x`. Если `p < n`, это первая подходящая позиция. Если `p = n`, все элементы меньше `x` и подходящего нет. Получен именно результат из условия.

**Завершение.** Мера — целое число `d = r−l ≥ 0`. В работающем цикле `d > 0`. В первой ветви `l` становится строго больше, во второй `r` становится строго меньше. Поэтому `d` уменьшается хотя бы на 1, оставаясь неотрицательным; бесконечное выполнение невозможно. Количественную оценку дадим в §7.

## 4. Как одна строка ломает поиск

На `a = [2, 7, 12]`, `x = 12` первая середина имеет индекс 1. Верное обновление — `l = 2`. Если написать `l = mid`, получим `[1,3)`, затем середину 2 и `[1,2)`, затем середину 1 и снова `[1,2)`. Условие `l < r` остаётся истинным, состояние повторяется. Мера перестала убывать. Найди свой более короткий пример в [M04-P4](practice.md).

| Ошибка | Почему это проблема |
| --- | --- |
| `l = mid` при `a[mid] < x` | На участке длины 1 граница может не сдвинуться |
| `r = mid−1` во второй ветви при той же схеме | На `[2,7]`, `x = 7` первая середина 1; перенос `r` в 0 даёт ответ 0 вместо 1 |
| Немедленный возврат при равенстве | На `[0,0,0]`, `x = 0` первая середина 1, но нижняя граница 0 |
| Читать `a[p]` без проверки `p < n` | Для `x` больше всех элементов ответ `p = n`; такого элемента нет |
| Использовать алгоритм на произвольном массиве | На `[8,2,6]`, `x = 8` середина 2 заставляет отбросить настоящее вхождение слева |

Середину считаем как `l + (r−l)/2`. Сумма `l+r` в выражении `(l+r)/2` может переполнить тип, даже когда обе границы по отдельности в него помещаются. При `0 ≤ l ≤ r` разность и выбранная сумма остаются между 0 и `r`.

В S07 приведён поиск на **закрытом** участке с последним включённым индексом и обновлением `maxIndex = mid−1`. Там иное условие цикла. В нашем алгоритме `r` — первый индекс правой известной части, и используется `r = mid`. Переносить одну строку между этими схемами нельзя.

## 5. Из границы получаем наличие

В массиве `[−5,0,0,6,9,14]` нижняя граница для 4 равна 3. Элемент на позиции 3 — шестёрка: подходящее место для вставки четвёрки найдено, но самой четвёрки нет.

После поиска позиции `p` значение присутствует тогда и только тогда, когда **`p < n` и `a[p] == x`**. При `x = 0` это истина; при `x = 20` ответ границы равен 6, поэтому чтения элемента вообще быть не должно.

```text
contains(a, x):
    p ← lower_bound_index(a, x)
    если p = длина a:
        вернуть нет
    вернуть результат проверки a[p] = x
```

```cpp
bool contains(const std::vector<long long>& a, long long x) {
    const int pos = lower_bound_index(a, x);
    const int n = static_cast<int>(a.size());
    return pos < n && a[pos] == x;
}
```

Встроенное `&&` C++ проверяет левое условие первым. Если оно ложно, правая часть не вычисляется. Поэтому проверка размера защищает обращение к элементу, в том числе при пустоте. Самостоятельная функция `contains` здесь названа нами.

Почему достаточно проверить только `p`? Раньше значения меньше `x`. Если `a[p] > x`, все следующие значения тоже больше `x`. Если `p = n`, меньшими оказались все элементы. Других мест для совпадения не осталось.

Теперь выполни [M04-P2](practice.md): одну собственную реализацию границы и функцию наличия на её основе.

## 6. Верхняя граница и число повторов

В том же массиве `[−5,0,0,6,9,14]` нули занимают индексы 1 и 2. Нижняя граница нуля — 1. Нужна ещё первая позиция со значением **строго больше** нуля: 3. Это **верхняя граница**, `upper_bound`.

Её левая известная часть содержит значения `≤ x`, правая — значения `> x`. Середина, условие цикла и смысл полуинтервала сохраняются; меняется проверка.

| Шаг верхней границы для 0 | `l` | `r` | `mid` | `a[mid] ≤ 0` | Новые `l, r` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | нет, там 6 | 0, 3 |
| 2 | 0 | 3 | 1 | да, там 0 | 2, 3 |
| 3 | 2 | 3 | 2 | да, там 0 | 3, 3 |

```text
upper_bound_index(a, x):
    l ← 0
    r ← длина a
    пока l < r:
        mid ← l + (r−l) div 2
        если a[mid] ≤ x:
            l ← mid + 1
        иначе:
            r ← mid
    вернуть l
```

```cpp
int upper_bound_index(const std::vector<long long>& a, long long x) {
    int l = 0;
    int r = static_cast<int>(a.size());
    while (l < r) {
        const int mid = l + (r - l) / 2;
        if (a[mid] <= x) {
            l = mid + 1;
        } else {
            r = mid;
        }
    }
    return l;
}
```

Доказательство отдельно проверим по смыслу. В начале обе внешние части пусты. Если середина `≤ x`, все элементы до неё тоже `≤ x`, поэтому левую часть можно расширить. Иначе середина `> x`, и все следующие элементы `> x`, поэтому расширяется правая часть. Длина неизвестного участка строго уменьшается теми же обновлениями. При остановке получена первая позиция со значением `> x` либо `n`.

Пусть `L` — нижняя граница, `U` — верхняя. Тогда **вхождения `x` занимают ровно `[L,U)`**, а их количество равно `U−L`:

- до `L` значения `< x`, поэтому там совпадений нет;
- с `U` значения `> x`, поэтому там совпадений нет;
- между ними значения одновременно `≥ x` и `≤ x`, то есть равны `x`.

Имеем `L ≤ U`: первая позиция `> x` не может предшествовать первой позиции `≥ x`. Если `x` отсутствует, обе границы совпадают. Пустота также даёт `0−0 = 0`.

```text
count_equal(a, x):
    L ← lower_bound_index(a, x)
    U ← upper_bound_index(a, x)
    вернуть U−L
```

```cpp
int count_equal(const std::vector<long long>& a, long long x) {
    const int left = lower_bound_index(a, x);
    const int right = upper_bound_index(a, x);
    return right - left;
}
```

Для примера из начала раздела `x = 0`: `L = 1`, `U = 3`, количество 2. Для `x = 4` обе границы 3, количество 0. Для `[0,0,0]`, `x = 0` границы 0 и 3. Искать один ноль, а затем идти по соседним нулям — корректно для подсчёта, но на длинной группе это уже линейная работа.

Верхнюю границу вычисляем прямой проверкой `≤ x`: приём с поиском нижней границы `x+1` может переполнить тип для максимального представимого `x`.

Остановка: [M04-P3](practice.md). К уже написанному нижнему поиску добавляется один вариант условия, затем короткое доказательство разности границ.

## 7. Сколько работы выполняется

Считаем сравнения значения середины с `x`. Доступ по индексу массива и действия с машинными целыми имеют постоянную цену. Выделение/заполнение входного массива в цену **одного запроса** не входит. Все версии итеративные.

### От уменьшения участка к логарифму

Пусть до шага длина неизвестной части `d > 0`. Тогда `mid = l + ⌊d/2⌋`. После переноса правой границы новая длина `⌊d/2⌋`. После переноса левой — `d−⌊d/2⌋−1`. Каждое из этих чисел не больше `⌊d/2⌋`.

Значит, после `k` шагов длина не больше `⌊n/2^k⌋`. Как только `2^k > n`, она равна нулю. Для `n ≥ 1` достаточно **`⌊log₂ n⌋+1` сравнений**; при `n = 0` сравнений элементов нет. Здесь `⌊t⌋` — наибольшее целое, не превосходящее `t`.

| `n` | Верхняя граница числа сравнений одного поиска границы |
| --- | --- |
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 6 | 3 |
| 1 000 000 | 20 |

Эта граница достигается, например, при поиске нижней границы значения не больше всех элементов: каждый раз выбирается `r = mid`. Получаем худший случай Θ(log n) для `n ≥ 2`. В нашей версии **нет раннего выхода по равенству**. Даже кратчайшая ветвь при росте `n` требует логарифмического числа шагов: минимальная новая длина равна `⌊(d−1)/2⌋`, и для превращения `n` в ноль также нужно порядка `log n` уменьшений. Поэтому лучший случай этой версии тоже Θ(log n) при `n ≥ 2`. У другого алгоритма, ищущего любое совпадение с ранним возвратом, лучший случай может быть Θ(1).

Чтобы аккуратно включать пустоту и единичную длину, общую цену запроса можно записывать как Θ(1 + log₂(n+1)). Обычно её сокращают до O(log n), подразумевая непустые большие входы. `contains` добавляет не более одного сравнения на равенство после границы. Два поиска для числа повторов удваивают верхнюю оценку сравнений, но постоянный множитель не меняет порядок.

| Алгоритм | Условие | Время запроса | Дополнительная память |
| --- | --- | --- | --- |
| Линейный поиск первого | Любой порядок | Θ(1) в лучшем непустом случае; Θ(n) в худшем | Θ(1) |
| Нижняя/верхняя граница | Неубывающий массив, быстрый доступ по индексу | Θ(1 + log(n+1)) для выбранного цикла | Θ(1) |
| Наличие через нижнюю границу | То же | Θ(1 + log(n+1)) | Θ(1) |
| Число вхождений | То же, два поиска | Θ(1 + log(n+1)) | Θ(1) |

Память входа — Θ(n) машинных значений. Она не превращает дополнительную память поиска в Θ(n): функции читают тот же массив, новых массивов и рекурсивных вызовов нет.

### Доступ, подготовка и много запросов

В связном списке нельзя за постоянное время получить узел с нужным номером. Библиотечный `lower_bound` допускает последовательные итераторы: сравнений значений будет O(log n), но переходов между узлами — O(n) в худшем случае. Это не логарифмическое время всей операции. Если заново проходить список от головы к каждой середине, возможна даже Θ(n log n) работа: на поиске числа больше всех элементов почти каждый такой проход имеет длину порядка `n`.

Сам поиск не проверяет отсортированность. Полная проверка порядка требует Θ(n) работы, если выполнить её перед каждым запросом, такая цена станет частью каждого запроса. В готовой программе порядок проверяется один раз при чтении входа.

Если данные уже отсортированы и запросов `q`, чтение и проверка массива требуют Θ(n), запросы — O(q(1+log(n+1))). Вместе с их вводом/выводом: O(n + q(1+log(n+1))). Для произвольного массива можно сначала применить подходящую сортировку за O(n log n), которую изучим в M06, и прибавить эту подготовку. Для одного запроса линейный поиск обычно позволяет обойтись без сортировки. Если нужны исходные позиции, сортировка должна сохранять связь с ними; индекс в отсортированной копии сам по себе исходной позицией не является.

## 8. Продолжение: библиотека и условие вне массива

### Стандартные функции C++17

Наши функции возвращают целочисленные индексы. `std::lower_bound` и `std::upper_bound` из `<algorithm>` возвращают **итераторы** — позиции в последовательности. `a.begin()` задаёт начало, `a.end()` — позицию сразу после последнего элемента; её нельзя разыменовывать. Для `vector` разность итераторов даёт расстояние между ними за постоянное время.

После `a = [−5,0,0,6,9,14]` и `x = 0`:

```cpp
auto first = std::lower_bound(a.begin(), a.end(), x);
auto after = std::upper_bound(a.begin(), a.end(), x);
bool found = first != a.end() && *first == x;
auto count = after - first;
```

`auto` просит компилятор определить тип по правой части. `*first` читает значение в указанной позиции; до такого чтения проверяем, что это не конец. Здесь `first−a.begin()` равно 1, `after−a.begin()` равно 3, `found` — `true`, `count` — 2. На пустом массиве обе позиции равны концу, `found` — `false`, количество 0. `std::binary_search(a.begin(), a.end(), x)` сразу возвращает только наличие.

Библиотека требует разделённости диапазона относительно соответствующего сравнения. Неубывающий порядок обеспечивает это сразу для всех запросов `x`; полный общий порядок сильнее условия для одной конкретной нижней границы. Для наших функций используем простое единое предусловие — неубывание массива. Параметры собственного сравнения и другие виды итераторов здесь не вводим.

### Граница монотонного условия

Небольшая мастерская выпускает ровно 7 деталей за каждый полный день. Требуется хотя бы 64 детали. Допустимые числа прошедших дней — целые `k` от 0 до 17 включительно. Требуется наименьшее допустимое `k`, для которого `7k ≥ 64`. Девяти дней мало: 63; десяти достаточно: 70. Проверка меняется только от «нет» к «да».

Такое условие назовём **монотонным** на выбранном диапазоне: если оно стало истинным, при дальнейшем увеличении аргумента уже не становится ложным. Допустимы и постоянные случаи «всегда нет» или «всегда да». Сам массив не обязателен: можно вычислять результат проверки по номеру кандидата.

Пусть `D = 18`, кандидаты имеют номера `[0,D)`, а результат `D` обозначает отсутствие подходящего кандидата. В момент `D` условие не вычисляем и не считаем этот номер дополнительным кандидатом.

| `l` | `r` | `mid` | `7·mid` | Достаточно 64? | Новые `l, r` |
| --- | --- | --- | --- | --- | --- |
| 0 | 18 | 9 | 63 | нет | 10, 18 |
| 10 | 18 | 14 | 98 | да | 10, 14 |
| 10 | 14 | 12 | 84 | да | 10, 12 |
| 10 | 12 | 11 | 77 | да | 10, 11 |
| 10 | 11 | 10 | 70 | да | 10, 10 |

```text
first_sufficient(D, need):
    l ← 0
    r ← D
    пока l < r:
        mid ← l + (r−l) div 2
        если 7·mid < need:
            l ← mid + 1
        иначе:
            r ← mid
    вернуть l
```

```cpp
int first_sufficient(int days, long long need) {
    int l = 0;
    int r = days;
    while (l < r) {
        const int mid = l + (r - l) / 2;
        if (7LL * mid < need) {
            l = mid + 1;
        } else {
            r = mid;
        }
    }
    return l;
}
```

Здесь `0 ≤ days ≤ 200000`, `0 ≤ need ≤ 10¹²`. Суффикс `LL` у 7 заставляет выполнять умножение в `long long`. Слева от `l` все кандидаты недостаточны, справа от `r` все достаточны. Монотонность позволяет расширять эти части тем же способом, что порядок массива; мера `r−l` убывает. При остановке возвращается первый достаточный кандидат либо `days`.

При `days = 18`, `need = 0` ответ 0; при `need = 120` ответ 18, поскольку даже 17 дней дают лишь 119 деталей; при `days = 0` кандидатов нет, ответ 0 обозначает отсутствие. В этом простом примере ответ можно также вывести делением; поиск показывает перенос той же схемы на вычисляемое условие.

Если одна проверка стоит O(C), все проверки вместе стоят O(C log D) при `D ≥ 2`, плюс постоянная работа с границами на каждом шаге; в примере проверка постоянная. Для немонотонного условия, например «`k` чётное», отбрасывание целой стороны необоснованно. Большой набор задач поиска по ответу сейчас не нужен.

## 9. Исполнимый пример и самопроверка

[search.cpp](search.cpp) содержит все собственные функции этого конспекта и программу для нескольких запросов. Сборка:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic search.cpp -o search
```

Формат: сначала `n q`, затем `n` значений массива, затем `q` запросов. Пробелы и переводы строки равноценны. Ограничения: `0 ≤ n,q ≤ 200000`, значения и запросы от `−10¹²` до `10¹²`, массив неубывает. Пример предполагает тип `int`, вмещающий 200000; это проверяется при сборке. `long long` в C++17 имеет не менее 64 бит и вмещает указанные значения. В функциях не складываются сами значения, поэтому их количество не создаёт опасности переполнения суммы.

На каждый запрос выводятся: нижняя граница, верхняя граница, наличие (`1` или `0`), число вхождений.

```text
Ввод:
6 4
-5 0 0 6 9 14
0 4 -8 20

Вывод:
1 3 1 2
3 3 0 0
0 0 0 0
6 6 0 0
```

Для пустоты ввод `0 1`, затем запрос `0`, даёт `0 0 0 0`. Для `q = 0` строк ответов нет. В `main` две границы вычисляются один раз на запрос; наличие и количество берутся из них без повторных поисков. Функции `linear_first`, `contains`, `count_equal`, `first_sufficient` доступны в файле для отдельных вызовов.

К концу темы должно получаться:

- словами задать результат нижней/верхней границы, в том числе 0 и `n`;
- провести ручную трассу и объяснить, что известно вне `[l,r)`;
- доказать сохранение инварианта, ответ и завершение;
- безопасно проверить наличие и получить число повторов;
- отделить цену запроса от чтения, сортировки и доступа к середине;
- распознать одну границу монотонного условия и указать цену его проверки.

Это критерии самопроверки. Готовый конспект не означает, что задания уже решены.
