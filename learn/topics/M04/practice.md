## M04-P1. Найти границу вручную

Дан неубывающий массив `[1,3,3,8]`, индексы начинаются с нуля. Найди нижнюю границу для каждого запроса: **0, 3, 4, 9**. Запросы независимы.

Используй только схему `[l,r)` из конспекта: начни с `l = 0`, `r = 4`. На каждой итерации запиши `l`, `r`, `mid`, значение `a[mid]`, результат сравнения `a[mid] < x` и новые границы. Заверши строкой с ответом, когда `l = r`. Для этой строки середину и элемент не вычисляй.

Под каждой трассой коротко поясни, что известно об элементах слева и справа от найденной границы. Ответ может равняться длине 4. Полной программы и нового формального доказательства в этом задании не требуется.

Происхождение: исходное M04-P1; все четыре запроса и сам массив сохранены.

## M04-P4. Почему поиск может зациклиться

Разбирается следующий **ошибочный** псевдокод на неубывающем массиве:

```text
l ← 0
r ← длина a
пока l < r:
    mid ← l + (r−l) div 2
    если a[mid] < x:
        l ← mid       // ошибка
    иначе:
        r ← mid
вернуть l
```

1. Подбери короткий допустимый массив и `x`, на которых одни и те же границы повторяются бесконечно. Достаточно показать повторяющееся состояние; не запускай бесконечный цикл.
2. Объясни, что происходит с мерой `r−l` в этом состоянии.
3. Исправь одну строку. Объясни для обеих ветвей, почему новая длина строго меньше старой при `l < r`, а границы не пересекаются.

Происхождение: исходное M04-P4. В конспекте разобран массив длины 3; здесь подбери другой вход, например ещё короче.

## M04-P2. Нижняя граница и наличие

Напиши две функции C++17 либо сначала их полный псевдокод:

```cpp
int lower_bound_index(const std::vector<long long>& a, long long x);
bool contains(const std::vector<long long>& a, long long x);
```

Условия: `0 ≤ n ≤ 200000`, массив неубывает, элементы и `x` от `−10¹²` до `10¹²`. Среда должна позволять хранить 200000 в `int`. Пустота, повторы, нули и отрицательные значения допустимы. Функции не меняют и не копируют вход.

Первая функция возвращает первую позицию с `a[i] ≥ x` либо `n`, если такой позиции нет. Используй один цикл на `[l,r)` без библиотечного поиска. Вторая функция вызывает первую и возвращает наличие; обращение к элементу разрешено только для допустимого индекса.

Обычный пример договора: для `[−4,1,1,5]`, `x = 1` нижняя граница равна 1, наличие — `true`. Граничный пример: для `[]` при любом допустимом `x` граница 0, наличие `false`.

Проверь также один элемент, все равные, запрос меньше всех, равный первому/последнему, между существующими значениями и больше всех. Добавь хотя бы один вход с нулём и отрицательным числом. Не ограничивай проверку четырьмя запросами P1.

В объяснении укажи смысл внешних частей, почему первое подходящее место не теряется, почему цикл заканчивается и почему найденная граница сама по себе ещё не доказывает наличие. Достаточно опереться на схему доказательства из §3; переписывать конспект дословно не нужно.

Происхождение: исходное M04-P2; уточнены контракт и типы. Сложность берётся для уже прочитанного массива.

## M04-P3. Сколько раз встречается число

При тех же условиях на массив и типы напиши `count_equal(a, x)`, возвращающую число вхождений `x`. Используй **два поиска границ**. Нижняя граница из P2 уже написана; верхнюю получи изменением условия того же цикла. Готовые библиотечные поиски и проход по группе равных в этой реализации не используй.

Для `[−6,2,2,2,10]` независимо рассмотри `x = 2`, `x = −6`, `x = 0`, `x = 11`. Запиши для каждого `L`, `U`, результат `U−L`. Полные трассы всех итераций здесь не нужны.

Проверь пустой массив, единственный элемент и массив из одинаковых значений, включая отрицательное значение. Объясни:

1. почему элементы на `[L,U)` — все и только вхождения `x`;
2. почему при отсутствии значения получается ноль, даже если обе границы внутри массива;
3. почему два поиска дают O(log n) времени при `n ≥ 2` и Θ(1) дополнительной памяти в модели доступа к массиву;
4. что изменится в цене запроса, если после нахождения одного совпадения пересчитывать повторы обычным проходом.

Происхождение: исходное M04-P3; добавлены конкретные данные и явное обоснование. Для `n = 0/1` оцени постоянную работу отдельно, не подставляй ноль в логарифм.
