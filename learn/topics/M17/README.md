# M17. B-деревья и доступ блоками

**Место в программе:** Приоритет по зелёной стрелке.  
**Главы по изображению:** 18.  
**Вход:** [M10](../M10/README.md).  
**Ориентир:** 8–14 часов первичного разбора и практики; темп уточняется по работе.

## Объяснение и порядок разбора

BST полезно для понимания поиска, но при хранении на внешнем носителе отдельный переход к узлу может означать дорогой доступ к блоку. **B-дерево** хранит много ключей в одном узле и поддерживает малую высоту за счёт большого ветвления. Сначала меняем модель стоимости: считаем и вычисления внутри блока, и число обращений к блокам.

В классическом определении Кормена минимальная степень t≥2 задаёт ограничения: в обычном некорневом узле от t−1 до 2t−1 ключей; внутренний узел с k ключами имеет k+1 детей; все листья на одной глубине. Корень имеет отдельные допустимые границы. Ключи внутри узла упорядочены и разделяют диапазоны детей.

Поиск сначала находит подходящий диапазон в узле, затем спускается к одному ребёнку. Число блоков по пути O(log_t n) при непустом дереве и фиксированной степени; вычисления внутри узла зависят от линейного или двоичного поиска по его ключам. Оценку обращений к блокам не выдаём за весь процессорный счёт.

При **вставке** делим переполненный/полный узел в соответствии с выбранным алгоритмом: средний ключ поднимается в родителя, остальные образуют два узла. В варианте спуска сверху вниз заранее разбиваем полного ребёнка перед переходом в него. Деление корня может увеличить высоту на один.

При **удалении** надо сохранить нижнюю границу заполнения. Разбираем заимствование ключа через родителя у соседа, слияние соседей и случай уменьшения высоты корня. Нужны последовательные рисунки, после которых проверяются порядок, заполнение и одинаковая глубина листьев.

B-дерево, B+-дерево и двоичное дерево поиска — разные структуры. Реальную дисковую СУБД для этой темы не строим: учебное дерево может жить в оперативной памяти, а обращения к узлам можно считать как условные обращения к блокам. Полная реализация удаления — отдельная трудоёмкая часть; до неё модуль отмечаем как освоенный частично, даже если поиск и вставка уже понятны.

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M17-P1.** Проверить несколько рисунков B-деревьев при t=2: найти нарушение заполнения, порядка и глубины листьев. Самостоятельно нарисовать один допустимый пример.

**M17-P2.** Вставить по порядку 1…12 при t=2, рисуя каждое деление. Реализовать поиск и вставку с проверкой инвариантов после каждого изменения.

**M17-P3.** Подготовить примеры удаления с заимствованием, слиянием и уменьшением высоты корня. Затем реализовать выбранный алгоритм удаления либо явно оставить эту часть в долгах.

**M17-P4.** Сравнить число уровней обычного сбалансированного бинарного дерева и дерева большого ветвления для одного n. Указать, что именно измеряется.

## Когда можно двигаться дальше

- [ ] Формулирую инварианты через один выбранный параметр t.
- [ ] Объясняю деление и восстановление заполнения при удалении.
- [ ] Разделяю операции внутри блока и обращения к блокам.
- [ ] Не считаю удаление освоенным по одной прочитанной схеме.

## Частые ошибки

- Смешивать минимальную степень и «порядок» дерева из разных источников.
- Терять отдельное условие на корень.
- Называть любое широкое дерево B-деревом.
