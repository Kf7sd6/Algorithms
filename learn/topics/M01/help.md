# M01. Подсказки и разборы

Сначала можно открыть один намёк. Если его мало — второй или полный разбор. После полного разбора полезно повторить действие на другом коротком входе, чтобы проверить самостоятельность.

Код использует `std::array<int, 8>`: это восемь целочисленных ячеек. Отдельное `n` задаёт, сколько первых ячеек входит в последовательность. Во всех функциях предполагается `0 ≤ n ≤ 8`.

В записи параметров `const ...& a` означает «дать функции читать тот же массив, без копирования и изменения»; `...& a` разрешает менять этот массив, `int& n` — менять длину у вызывающего кода. В примерах `CAPACITY` — заранее заданная константа 8. Если синтаксис пока мешает, сначала проверь алгоритм в словах и псевдокоде.

Полная исполнимая программа — [array_examples.cpp](array_examples.cpp). Ниже приведены только функции к соответствующим упражнениям.

## M01-P1.a

<details>
<summary>Подсказка 1</summary>

Четыре элемента получают четыре индекса начиная с нуля. Число, записанное в ячейке, не определяет её индекс.

</details>

<details>
<summary>Подсказка 2</summary>

Участок `[1, 3)` включает индекс 1 и следующий за ним, но останавливается перед индексом 3. При поиске числа 8 проверь, не встречается ли оно несколько раз.

</details>

<details>
<summary>Полный разбор</summary>

Пары «индекс — значение»: `(0, 8)`, `(1, 3)`, `(2, 8)`, `(3, 1)`.

`a[2] = 8`. Все позиции со значением 8 — 0 и 2. В первом вопросе уже известна позиция, во втором требуется найти позиции по значению.

Последний допустимый индекс — 3. Участок `[1, 3)` содержит индексы 1 и 2, то есть значения 3 и 8; его длина `3 − 1 = 2`.

</details>

## M01-P2

<details>
<summary>Подсказка 1</summary>

Какое утверждение о проверенной левой части позволяет закончить поиск сразу при первом совпадении?

</details>

<details>
<summary>Подсказка 2</summary>

Обходи индексы от 0, пока индекс меньше `n`. При совпадении сразу возвращай индекс. Отсутствие можно объявить после окончания всего цикла.

</details>

<details>
<summary>Полный разбор</summary>

```cpp
int find_first(const std::array<int, CAPACITY>& a, int n, int x) {
    for (int i = 0; i < n; ++i) {
        if (a[i] == x) {
            return i;
        }
    }
    return -1;
}
```

Для последовательности `[5, −2, 5, 0]`:

| Запрос | Ответ | Сравнений элементов с `x` |
| --- | --- | --- |
| `x = 5` | 0 | 1 |
| `x = −2` | 1 | 2 |
| `x = 9` | −1 | 4 |
| Пустая последовательность, `x = 0` | −1 | 0 |

Перед проверкой позиции `i` во всех ранее проверенных позициях `x` отсутствует. Поэтому первое обнаруженное совпадение имеет наименьший индекс. Если цикл закончился без совпадения, проверены все действующие элементы. Индекс увеличивается и ограничен `n`, значит цикл заканчивается.

При первом совпадении на позиции `j` имеем `j + 1` сравнений, при отсутствии — `n`. Используется одна дополнительная переменная индекса; нового массива нет.

Особая проверка границы: пусть все восемь физических ячеек заполнены нулями, но `n = 0`. Поиск 0 всё равно обязан вернуть `−1`: физические ячейки не являются элементами пустой последовательности.

</details>

## M01-P1.b

<details>
<summary>Подсказка 1</summary>

Для вставки сначала перенеси последний элемент в свободную ячейку справа. Последующее удаление начинается уже с массива длины 5.

</details>

<details>
<summary>Подсказка 2</summary>

При вставке на позицию 1 двигай старые элементы с индексов 3, 2, 1. При удалении первого сдвигаются элементы с индексов 1, 2, 3, 4.

</details>

<details>
<summary>Полный разбор</summary>

Вставка 6 в `[8, 3, 8, 1]`:

| Действие | Первые пять физических ячеек |
| --- | --- |
| Исходно | `[8, 3, 8, 1, —]` |
| `a[4] = a[3]` | `[8, 3, 8, 1, 1]` |
| `a[3] = a[2]` | `[8, 3, 8, 8, 1]` |
| `a[2] = a[1]` | `[8, 3, 3, 8, 1]` |
| `a[1] = 6` | `[8, 6, 3, 8, 1]` |

Затем `n = 5`. Перемещены три старых элемента: `4 − 1 = 3`. Запись 6 — отдельное действие, не четвёртое перемещение.

Удаляем первый элемент из **полученного** `[8, 6, 3, 8, 1]`:

| Действие | Первые пять физических ячеек |
| --- | --- |
| `a[0] = a[1]` | `[6, 6, 3, 8, 1]` |
| `a[1] = a[2]` | `[6, 3, 3, 8, 1]` |
| `a[2] = a[3]` | `[6, 3, 8, 8, 1]` |
| `a[3] = a[4]` | `[6, 3, 8, 1, 1]` |

Уменьшаем `n` до 4. Действующая последовательность — `[6, 3, 8, 1]`. Последняя физическая единица в неё не входит. Перемещены четыре элемента: `5 − 0 − 1 = 4`. Вместимость всё время остаётся равной 8.

Порядок сохраняется: при вставке каждый элемент правой части перемещён на одну позицию вправо; при удалении следующий за удалённым занимает его место, и так далее.

</details>

## M01-P3

<details>
<summary>Подсказка 1</summary>

Перед любыми изменениями проверь позицию и свободное место. Какое старое значение будет потеряно, если сначала записать новый элемент прямо в `a[pos]`?

</details>

<details>
<summary>Подсказка 2</summary>

Первая ячейка назначения — `a[n]`. Пока индекс назначения больше `pos`, копируй туда левую соседнюю ячейку и двигайся влево. Длину увеличь после заполнения освободившегося места.

</details>

<details>
<summary>Полный разбор</summary>

```cpp
bool insert_at(std::array<int, CAPACITY>& a, int& n, int pos, int x) {
    if (pos < 0 || pos > n || n == CAPACITY) {
        return false;
    }
    for (int j = n; j > pos; --j) {
        a[j] = a[j - 1];
    }
    a[pos] = x;
    ++n;
    return true;
}
```

Разберём новый пример `[4, 7, 2]`, вставка 9 на позицию 1. При достаточной вместимости выполняем `a[3] = a[2]`, затем `a[2] = a[1]`, затем `a[1] = 9`. Результат — `[4, 9, 7, 2]`.

Если ошибочно двигаться слева направо, первая запись `a[2] = a[1]` заменит исходную двойку семёркой. Следующая запись `a[3] = a[2]` снова скопирует семёрку. После записи 9 получится `[4, 9, 7, 7]`: двойка потеряна. Это контрпример правильности неверного варианта.

У правильного варианта элементы до `pos` не меняются. Каждый элемент начиная с `pos` копируется на одну позицию вправо раньше, чем его исходная ячейка может быть перезаписана. Поэтому старые значения не теряются, а новый элемент занимает освободившееся место. Цикл заканчивается, потому что `j` каждый раз уменьшается на 1 до `pos`.

Перемещений ровно `n − pos` для исходного `n`, плюс одна запись `x`. Вставка в конец выполняет ноль перемещений, но всё ещё записывает `x` и увеличивает длину. Новая ячейка `a[n]` допустима, поскольку перед циклом установлено `n < CAPACITY`.

| До вызова | Вставка | Результат |
| --- | --- | --- |
| `[]`, `n = 0` | позиция 0, значение 5 | `[5]`, `n = 1`, `true` |
| `[2, 3]` | позиция 0, значение 5 | `[5, 2, 3]` |
| `[2, 3]` | позиция 1, значение 5 | `[2, 5, 3]` |
| `[2, 3]` | позиция 2, значение 5 | `[2, 3, 5]` |
| восемь элементов | любая допустимая позиция | отказ, массив и `n` прежние |
| `[2, 3]` | позиция −1 или 3 | отказ, массив и `n` прежние |

`int& n` в параметрах нужен, чтобы изменение длины осталось после возвращения функции. Если передать длину обычным `int n`, внутри функции изменится только её локальная копия.

</details>

## M01-P4

<details>
<summary>Подсказка 1</summary>

Для каждого случая спроси: что приходит в запросе? Нужна ли позиция по номеру, проверка наличия или значение по ключу?

</details>

<details>
<summary>Подсказка 2</summary>

В телефонной книге результат зависит от имени. Для страниц важен факт посещения. Для принтера важно, какое задание поступило раньше остальных ещё не выполненных.

</details>

<details>
<summary>Полный разбор</summary>

| Ситуация | Данные и операция | Запрос | Результат |
| --- | --- | --- | --- |
| Телефонная книга | Найти номер | Уникальное имя | Номер либо отсутствие записи |
| Телефонная книга | Записать/изменить номер | Имя и номер | Одна актуальная запись для этого имени |
| Телефонная книга | Удалить | Имя | Удалённая запись либо сообщение об отсутствии |
| Посещённые страницы | Проверить наличие | Адрес | Да/нет |
| Посещённые страницы | Добавить | Адрес | Адрес присутствует; повтор не увеличивает число разных адресов |
| Принтер | Добавить задание | Данные нового задания | Оно становится последним среди ожидающих |
| Принтер | Получить следующее | Запрос без позиции | Самое раннее из ожидающих либо пустота |
| Принтер | Проверить пустоту | Запрос без аргументов | Есть ли ожидающие задания |

Телефонная книга имеет интерфейс словаря, посещённые адреса — множества, принтер — очереди с выдачей по поступлению. Эти названия описывают поведение. Они ещё не выбирают между массивом, списком, хеш-таблицей или деревом.

</details>

## M01-P5

<details>
<summary>Подсказка 1</summary>

Добавление увеличивает длину. Увеличение вместимости само по себе длину не меняет. Перед вторым добавлением свободная ячейка ещё есть?

</details>

<details>
<summary>Подсказка 2</summary>

После первого добавления длина станет 4. Чтобы добавить пятый элемент по учебному правилу, сначала получи буфер вместимости 8 и перенеси все четыре уже действующих элемента.

</details>

<details>
<summary>Полный разбор</summary>

| Состояние после действия | Последовательность | Длина | Вместимость | Переносов старых элементов |
| --- | --- | --- | --- | --- |
| Начало | `[7, 1, 4]` | 3 | 4 | — |
| Добавить 9 | `[7, 1, 4, 9]` | 4 | 4 | 0 |
| Добавить 2 с нужным расширением | `[7, 1, 4, 9, 2]` | 5 | 8 | 4 |

Каждое добавление отдельно записывает своё новое значение. Во втором шаге четыре переноса нужны для старых данных; новая двойка не является пятым переносом старого элемента.

После `v.reserve(10)` в части b размер равен 3, вместимость не меньше 10. Равенство вместимости десяти не гарантируется. `v[3] = 9` недопустимо, поскольку действующих элементов всего три и четвёртый ещё не существует.

Правильно: `v.push_back(9);`. После этого размер равен 4 и `v[3] == 9`. Перераспределение памяти для этого добавления не требуется: имеющейся вместимости достаточно. Обещание конкретного коэффициента роста здесь не нужно.

</details>

## M01-P6 ★

<details>
<summary>Подсказка 1</summary>

При отсутствии требования о порядке нужно сохранить оставшиеся значения. Можно ли закрыть освободившееся место одним уже существующим элементом?

</details>

<details>
<summary>Подсказка 2</summary>

Возьми значение последней действующей ячейки `a[n − 1]`, запиши в `a[pos]`, затем уменьши `n`. Сначала убедись, что `pos` обозначает существующий элемент.

</details>

<details>
<summary>Полный разбор</summary>

```cpp
bool erase_unordered(std::array<int, CAPACITY>& a, int& n, int pos) {
    if (pos < 0 || pos >= n) {
        return false;
    }
    a[pos] = a[n - 1];
    --n;
    return true;
}
```

Для `[3, 7, 2, 8]`, `pos = 1` получим `[3, 8, 2]`. Удаление с сохранением порядка дало бы `[3, 2, 8]`. В обоих случаях удалена одна семёрка, остальные значения сохранены, длина уменьшена на один. Их порядок в первом варианте изменился.

При `pos = n − 1` происходит запись элемента в ту же ячейку, после чего она исключается из последовательности. При единственном элементе `pos = 0`, новая длина равна нулю. При `n = 0` ни один индекс не проходит проверку, поэтому чтения `a[n − 1]` нет.

Объём перестройки не зависит от длины: не более одной записи значения и изменение `n`. Но если требуется удалить именно значение 7, а его позиция неизвестна, сначала понадобится поиск. Нельзя переносить цену изменения по известному индексу на весь запрос по значению.

</details>
