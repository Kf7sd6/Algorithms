# M05. Практика

Здесь **только четыре исходных задания M05-P1–P4**, уточнённых до самостоятельных условий. Все они авторские, из [паспорта](outline.md), а не заимствованы из упражнений учебника. Исходные данные P1 и соотношения P2/P3 сохранены. Для ранее открытого P4 добавлена конкретная сломанная функция.

За занятие достаточно одного задания или одного пункта P2. Условия не требуют заранее уверенно писать на C++: сначала допустимы рисунок, псевдокод и связное объяснение. Код нужен при исправлении P4; полный синтаксис маленькой функции уже показан в конспекте.

| Порядок | ID | После чтения | Что проверяем |
| --- | --- | --- | --- |
| 1 | M05-P1 | §1–2 | Ручные вызовы, ожидающие состояния и возвраты |
| 2 | M05-P4 | §3, затем §4 для оценки | Ошибка уменьшения, исправление, завершение |

Продолжение §6–8 входит в тему. Оно не создаёт дополнительного большого листка. После собственной попытки можно открыть [постепенные подсказки](help.md).

## M05-P1. Вызовы суммы

Дан массив `[4,1,3]`, индексы с нуля. Используй функцию `sum_suffix(a,i)` из §1: при `i=n` вернуть 0, иначе вычислить сумму хвоста с `i+1` и добавить `a[i]`. Начальный вызов — `sum_suffix(a,0)`.

1. Выпиши все входы в функцию с индексами и соответствующими участками.
2. В момент входа в самый глубокий вызов перечисли активные кадры снизу вверх. Для каждого ожидающего вызова укажи, какое сложение ещё предстоит; ответ вложенного вызова до возврата не считай полученным.
3. Выпиши все возвраты: откуда пришёл ответ, что прибавлено и какое число возвращено.
4. Посчитай всего вызовов, максимальное число активных кадров и число сложений элементов. Базовый вызов учитывается; `main` не учитывается.
5. Коротко объясни, что произойдёт на пустом массиве и на `[0,−2]`. Ноль среди элементов не является условием завершения.

Нужны таблицы или аккуратный рисунок; программа не требуется. Это исходный P1 с явными соглашениями о состоянии и подсчёте.

## M05-P2. Три соотношения

Каждая строка задаёт **свою функцию стоимости**, не возвращаемую сумму массива. Во всех строках база **`T(1)=1`**; рекурсивная формула действует при `n≥2` в указанной области.

| Пункт | Соотношение | Область размеров |
| --- | --- | --- |
| a | `T(n)=T(n−1)+1` | Все целые `n≥1` |
| b | `T(n)=T(n/2)+1` | `n=2^k`, целое `k≥0` |
| c | `T(n)=2T(n/2)+n` | `n=2^k`, целое `k≥0` |

Для **одной строки за раз**:

1. Раскрой соотношение до базы или составь таблицу дерева по уровням. В пункте c явно учти листья.
2. Получи точную формулу и Θ-оценку при росте `n`.
3. Проверь формулу на `n=1,2,4,8`. Эти вычисления проверяют согласованность, но не заменяют обоснование для всех допустимых размеров.
4. Для c заверши проверку формулы индукцией: база и подстановка на `n/2`. Можно свериться со схемой §6, используя константы **этого** условия.

Исходные три соотношения сохранены. Цена `+1` здесь точная, а не условное обозначение всей работы программы. `n=0` в области этих трёх функций не задан; придумывать значение базы не нужно.

## M05-P3. Условия теоремы

**a.** Дано `T(1)=1`, `T(n)=2T(n/2)+n²` для степеней двойки `n≥2`. Используй базовую трёхслучайную версию основной теоремы из §7.

- Назови `a`, `b`, `f(n)` и `p=log_b a`.
- Выбери случай и явно укажи положительную постоянную `ε`.
- Если нужна регулярность, подставь `f(n/b)` и найди допустимую постоянную `q<1`.
- Сделай вывод о времени. Поясни его деревом в 2–3 предложениях.

**b.** Дано `U(1)=1`, `U(n)=U(n−1)+n` для всех целых `n≥2`.

- Объясни, почему выбранную основную теорему применять нельзя.
- Найди точную формулу раскрытием и Θ-оценку.
- Проверь базу и первые два небазовых значения.

Это обе части исходного P3. Они относятся к продолжению темы и не выдаются до чтения §7.

## M05-P4. В одной ветви размер не меняется

Функция задумывалась как число целочисленных делений неотрицательного `n` на 2 до получения значения не больше 1. Например, для `n=9` цепочка `9→4→2→1`, требуемый ответ 3. В базе для 0 и 1 ответ равен 0.

Дан **ошибочный** фрагмент C++17. Его нельзя запускать на входе, который приводит к бесконечной цепочке вызовов: достаточно ручного следа.

```cpp
int half_steps(int n) {
    if (n <= 1) {
        return 0;
    }
    if (n % 2 == 0) {
        return 1 + half_steps(n); // здесь есть ошибка
    }
    return 1 + half_steps(n / 2);
}
```

`n % 2 == 0` означает, что остаток от деления на 2 равен нулю, то есть `n` чётное. Вход: целое `0≤n≤10⁹` на среде с `int`, вмещающим `10⁹`.

1. Укажи вход, на котором ошибка проявляется сразу, и выпиши первые три вызова. Затем найди нечётный вход, который позже попадает в ту же ошибку.
2. Исправь переход. После исправления можно убрать ставшее ненужным ветвление.
3. Объясни базу, правильность возвращаемого числа и строгое уменьшение аргумента.
4. Проверь вручную `n=0,1,2,3,9,16`; затем можно проверить исправленный код.
5. Оцени число вызовов и память стека. Не используй `log₂0`.

Это исходный P4, конкретизированный до одной небольшой функции. Новый самостоятельный алгоритм поверх исходного набора не добавляется.
