## 1. Сначала сумма на маленьком массиве

Дан массив `[6,−2,5]`. Требуется сумма всех элементов: `9`. Циклом мы добавляли элементы по очереди. Другой способ — сначала узнать сумму хвоста `[-2,5]`, затем добавить к ней `6`. Чтобы узнать сумму хвоста, узнаём сумму `[5]` и добавляем `−2`. В конце остаётся пустой хвост, сумма которого равна `0`.

Обозначим `S(i)` сумму элементов от индекса `i` до конца одного фиксированного массива `a` длины `n`. Тогда:

\[
S(n)=0,\qquad S(i)=a[i]+S(i+1)\quad(0\le i<n).
\]

Здесь `i+1` больше `i`, но **размер оставшейся задачи** `n−i` уменьшается. Требование относится к размеру задачи, а не обязательно к числу, записанному в параметре.

**Рекурсивная функция** вызывает ту же функцию для меньшей задачи. **База** — случай, в котором ответ возвращается сразу, без нового вызова. Здесь база `i=n`, то есть пустой участок. Ноль в массиве не является базой: после него могут быть другие элементы.

### Алгоритм и небольшой C++17-код

Допустимые данные для исполнимого учебного примера: `0 ≤ n ≤ 512`, целые элементы от `−10¹²` до `10¹²`, начальный индекс `0 ≤ i ≤ n`. Массив не меняется. При `i=n` функция не читает ни одного элемента.

```text
СУММА_ХВОСТА(a, i):
    если i = длина(a):
        вернуть 0
    хвост ← СУММА_ХВОСТА(a, i + 1)
    вернуть a[i] + хвост
```

```cpp
long long sum_suffix(const std::vector<long long>& a, int i) {
    int n = static_cast<int>(a.size());
    if (i == n) {
        return 0;
    }
    long long tail = sum_suffix(a, i + 1);
    return a[i] + tail;
}
```

Для этого фрагмента нужен `<vector>`; [полная программа](recursion.cpp) содержит заголовки и `main`. Вызов всей суммы — `sum_suffix(a, 0)`.

`const ...& a` передаёт один и тот же массив без копирования и запрещает менять его через этот параметр. `i` передаётся по значению: у каждого вызова свой индекс. `static_cast<int>` явно переводит длину в `int`; оговорённый предел 512 позволяет это сделать. Тип `long long` нужен и элементам, и сумме. Любая частичная сумма по модулю не превосходит `512·10¹² = 512000000000000`, что помещается в этот тип. Отрицательные числа и нули не меняют алгоритм.

Сначала исполняется присваивание `tail`, включая весь вложенный вызов, и только потом строка с `return`. Когда запускается вложенный вызов, предыдущий ждёт его результата; он не исчезает.

## 2. Что находится в стеке и как приходят ответы

Для `[6,−2,5]` порядок входов таков:

| Вход в вызов | Его участок | Что он делает до ожидания |
| --- | --- | --- |
| `S(0)` | `[6,−2,5]` | Запускает `S(1)`, затем должен добавить 6 |
| `S(1)` | `[−2,5]` | Запускает `S(2)`, затем должен добавить −2 |
| `S(2)` | `[5]` | Запускает `S(3)`, затем должен добавить 5 |
| `S(3)` | `[]` | Возвращает 0 по базе |

В момент входа в `S(3)` активны четыре вызова: от самого старого `S(0)` до текущего `S(3)`. Это порядок **снизу вверх** в модели стека. В ожидающих вызовах значение `tail` ещё не получено; приписывать ему ответ заранее нельзя.

| Возвращается вызов | Полученный ответ меньшей задачи | Действие | Возвращаемое значение |
| --- | --- | --- | --- |
| `S(3)` | Не нужен | База | 0 |
| `S(2)` | 0 | `5 + 0` | 5 |
| `S(1)` | 5 | `−2 + 5` | 3 |
| `S(0)` | 3 | `6 + 3` | 9 |

Стек работает по правилу «последним вошёл — первым вышел». **Кадр вызова** — сохранённое состояние одного вызова: параметры, локальные данные и место, куда продолжить после возврата. Здесь это полезная модель обычного исполнения, а не обещание точного устройства машинной памяти стандартом C++.

**Глубину** дальше считаем числом одновременно активных вызовов нашей функции, включая базовый. `main` и библиотечные функции не считаем. Для хвоста длины `m` глубина равна `m+1`; рёбер между этими кадрами `m`. В нашем примере глубина 4.

Если исходный массив пуст, запускается один базовый вызов и возвращается 0. Если в нём только `[-7]`, сначала вызывается пустой хвост и затем получается `−7`. Отрицательный ответ не признак ошибки.

## 3. Почему рекурсия правильна и заканчивается

Докажем: для любого допустимого `i` функция возвращает сумму участка `[i,n)` и не меняет массив. Используем индукцию по длине участка `m=n−i`.

1. **База `m=0`.** Участок пуст, функция возвращает 0. Это требуемая сумма; обращения к массиву нет.
2. **Предположение.** Для участка длины `m−1` вызов правильно возвращает сумму его элементов.
3. **Шаг `m>0`.** Индекс `i<n` допустим. Вызов с `i+1` получает участок длины `m−1` и по предположению возвращает его сумму. Мы добавляем единственный оставшийся элемент `a[i]`. Получается сумма всех и только элементов `[i,n)`. Записей в массив нет.

Это доказывает правильность результата, **если вложенные вызовы завершаются**. Завершение проверяем отдельно: неотрицательное целое `n−i` на каждом переходе уменьшается на 1 и доходит до 0. База немедленно возвращает ответ, затем заканчиваются все ожидающие сложения.

### Ошибки, которые база сама не исправляет

- Вызвать `sum_suffix(a,i)` снова с тем же `i`: при непустом хвосте база никогда не приблизится.
- Сначала читать `a[i]`, а потом проверять `i==n`: пустой хвост уже приводит к недопустимому чтению.
- Завершать при `a[i]==0`: на `[0,8]` получим 0 вместо 8.
- Передавать целую копию массива при каждом вызове: это меняет стоимость и память; наши оценки предполагают передачу по ссылке.

Уменьшение должно быть **в каждой доступной ветви**. На входах, которые случайно обходят сломанную ветвь, ошибка может не проявиться. Это предмет M05-P4.

## 4. Соотношение результата и соотношение работы

В §1 запись `S(i)=a[i]+S(i+1)` описывает **возвращаемое число**. Для `[6,−2,5]` оно равно 9. Цена вычисления зависит прежде всего от длины, а не от этой суммы: у `[0,0,0]` тоже четыре вызова.

Считаем работу в модели M02: чтение элемента, операция над оговорёнными машинными числами и служебная работа одного вызова имеют постоянную цену. Ввод массива считаем отдельно. Для хвоста длины `m`:

\[
T(0)=\Theta(1),\qquad T(m)=T(m-1)+\Theta(1).
\]

Символ Θ(1) означает ограниченную сверху и снизу постоянную работу, а не ровно одну машинную инструкцию. Для **точного** числа вызовов введём отдельное обозначение:

\[
C(0)=1,\qquad C(m)=C(m-1)+1,\qquad C(m)=m+1.
\]

Итак, время Θ(m+1), дополнительная память обычной реализации Θ(m+1) кадров. Для непустых растущих входов принято писать Θ(m). При нулевой длине всё равно есть базовый вызов.

### Раскрытие: уменьшаем размер на один

Рассмотрим точную учебную модель `A(0)=2`, `A(n)=A(n−1)+3` при целых `n≥1`. Три единицы — выбранная цена шага.

\[
A(n)=A(n-2)+6=\dots=A(n-j)+3j.
\]

До базы нужно `j=n` переходов. Значит, `A(n)=2+3n`. Для `n=4`: `A(4)=A(3)+3=A(2)+6=A(1)+9=A(0)+12=14`. Время линейное. Если цена каждого шага лежит между двумя положительными константами, сумма `n` таких цен тоже даёт Θ(n).

### Раскрытие: делим размер пополам

Теперь `B(1)=2`, `B(n)=B(n/2)+4` для `n=2^k`, `k≥1`. После `j` раскрытий:

\[
B(n)=B(n/2^j)+4j.
\]

База достигается при `n/2^j=1`, то есть `j=log₂n`. Поэтому `B(n)=2+4log₂n`. При `n=8` размеры `8→4→2→1`, три перехода и ответ 14.

Логарифм `log_b n` отвечает на вопрос, в какую степень нужно возвести `b`, чтобы получить `n`. При каждом уменьшении в `b` раз нужно `log_b n` переходов, если `n` — степень `b`. Менять основание логарифма в Θ можно: это только постоянный множитель.

В двоичном поиске M04 после сравнения продолжается **одна** из двух частей. Две возможные ветви условия не означают два исполненных рекурсивных вызова. Для верхней оценки его худшего пути подходит уменьшение размера примерно вдвое; при раннем совпадении работа может закончиться раньше.

Остановка: выполни первые две строки M05-P2. В них другая точная база и цена шага.

## 5. Дерево рекурсии: работы на уровне бывает много

Представим обработку массива: разделить его пополам, обработать **обе** части, потом выполнить объединение с линейной ценой. Так будет устроена сортировка слиянием M06. Полный алгоритм сортировки здесь пока не нужен; анализируем явно заданную модель работы.

Пусть `D(1)=2`, `D(n)=2D(n/2)+3n`, `n=2^k`. Для `n=8`:

| Глубина от корня | Число узлов | Размер одной задачи | Дополнительная работа одного узла | Вся работа уровня |
| --- | --- | --- | --- | --- |
| 0 | 1 | 8 | 24 | 24 |
| 1 | 2 | 4 | 12 | 24 |
| 2 | 4 | 2 | 6 | 24 |
| 3, листья | 8 | 1 | 2 по базе | 16 |

Внутренний узел соответствует вызову вне базы; его надпись — только **собственная** работа без дочерних вызовов. Иначе одна работа будет посчитана несколько раз. Лист — базовый вызов без детей.

На глубине `j<k` есть `2^j` задач длины `n/2^j`. Их собственная работа:

\[
2^j\cdot3(n/2^j)=3n.
\]

Небазовых уровней `k=log₂n`; листьев `2^k=n`, каждый стоит 2. Складываем:

\[
D(n)=3n\log_2n+2n.
\]

При `n=8` это `24+24+24+16=88`. Для линейной собственной работы между `αn` и `βn` результат Θ(n log n), а не Θ(log n): глубина — только число уровней, нужно ещё учесть цену каждого уровня.

### Общая схема дерева

Для `T(n)=aT(n/b)+f(n)` на степенях `b`, с постоянной положительной ценой базы `T(1)=d`:

| Что считаем | Значение |
| --- | --- |
| Высота в рёбрах | `k=log_b n` |
| Число узлов на глубине `j` | `a^j` |
| Размер задачи в узле | `n/b^j` |
| Работа небазового уровня | `a^j f(n/b^j)` |
| Число листьев | `a^k=n^(log_b a)` |

Отсюда точное равенство при точно заданном `f`:

\[
T(n)=\sum_{j=0}^{k-1}a^j f(n/b^j)+d\,a^k.
\]

Если `k=0`, сумма пуста и остаётся `T(1)=d`. Стоимость листьев нельзя забывать: иногда именно она определяет ответ.

Нужный минимум о геометрической сумме: для постоянного `q≠1` сумма `1+q+...+q^h=(q^{h+1}−1)/(q−1)`. Это получается вычитанием исходной суммы из суммы, умноженной на `q`. При `0<q<1` сумма ограничена константой, при `q>1` имеет порядок последнего слагаемого, а при `q=1` равна `h+1`. Эти три возможности объясняют основную теорему в §7.

## 6. Продолжение: подстановка и полное доказательство оценки

Дерево помогает **найти** ответ. Метод подстановки проверяет выбранную формулу или оценку индукцией: предполагаем утверждение только для меньших размеров и подставляем его в исходное соотношение. Проверка нескольких чисел не заменяет этот шаг.

Для точной модели §5 предположим, что для `n/2` верна формула `D(n/2)=3(n/2)log₂(n/2)+2(n/2)`. Тогда:

\[
\begin{aligned}
D(n)&=2D(n/2)+3n\\
&=3n(\log_2n-1)+2n+3n\\
&=3n\log_2n+2n.
\end{aligned}
\]

База: при `n=1` формула даёт `0+2=2=D(1)`. Уменьшение показателя `k` в `n=2^k` гарантирует, что предположение относится к меньшей задаче. Так мы доказали точную формулу на всех степенях двойки.

### Если известна только линейная цена объединения

Пусть теперь `T(1)=d>0` и `T(n)=2T(n/2)+w(n)`, где для всех степеней двойки `n≥2` выполнено `αn≤w(n)≤βn`, `0<α≤β`. Константы включают всю служебную работу. Докажем обе оценки с явными константами:

\[
c\,n(\log_2n+1)\le T(n)\le C\,n(\log_2n+1),
\qquad c=\min(d,\alpha),\quad C=\max(d,\beta).
\]

**База:** при `n=1` получаем `c≤d≤C`, что верно по выбору констант.

**Верхний шаг:** если верхняя оценка верна на `n/2`, то

\[
T(n)\le2C(n/2)(\log_2(n/2)+1)+\beta n
=Cn\log_2n+\beta n\le Cn(\log_2n+1).
\]

Последний переход использует `C≥β`.

**Нижний шаг:** из нижней оценки на `n/2` аналогично:

\[
T(n)\ge2c(n/2)(\log_2(n/2)+1)+\alpha n
=cn\log_2n+\alpha n\ge cn(\log_2n+1),
\]

поскольку `c≤α`. Это полная индукция по `k`: доказаны база и оба перехода. Значит, `T(n)=Θ(n(log n+1))`, или Θ(n log n) при `n≥2`.

Нельзя просто написать «предположим `T(n)≤Cn log n`» и забыть базу: при `n=1` правая часть равна нулю, хотя `T(1)>0`. Добавка `+1` внутри скобок позволяет одной формуле охватить и базу.

## 7. Продолжение: основная теорема и её условия

Теорема экономит раскрытие стандартных соотношений, но применима не к любой рекурсии. Возьмём **базовую трёхслучайную версию**, достаточную для этой темы.

Рассматриваем `T(n)=aT(n/b)+f(n)` на размерах `n=b^k`, где `a≥1` и `b≥2` — постоянные целые числа, `T(1)=d>0`, а `f(n)≥0`. Обозначим `p=log_b a`. Время базы — положительная константа; функция `f` — работа вне рекурсивных вызовов. Ограничение на степени здесь намеренное; целочисленные размеры отдельно разбираем в §8.

| Случай | Что требуется для достаточно больших размеров | Вывод |
| --- | --- | --- |
| 1. Работа уровней смещена к листьям | `f(n)=O(n^(p−ε))` для некоторой **постоянной** `ε>0` | `T(n)=Θ(n^p)` |
| 2. Работа распределена по уровням | `f(n)=Θ(n^p)` | `T(n)=Θ(n^p log n)` |
| 3. Работа сосредоточена у корня | `f(n)=Ω(n^(p+ε))` для некоторой постоянной `ε>0`, **и** `a f(n/b)≤q f(n)` для постоянной `0<q<1` | `T(n)=Θ(f(n))` |

Во всех строках речь о неотрицательной работе, а в третьей неравенство должно действовать на всех достаточно больших размерах из области, не на одном примере. Последнее условие называется **регулярностью**: суммарная работа следующего уровня не превосходит постоянной доли текущей.

Это ограниченная версия: в MIT также приведён расширенный второй случай с множителем `(log n)^k`, `k≥0`. Здесь им не пользуемся. Утверждение теоремы берём как опорное; механизм её случаев объясняем суммами уровней. Полное доказательство общего утверждения для произвольной функции `f` не требуется. Полное индукционное доказательство нужной оценки уже есть в §6.

### Три примера с одинаковым делением

Во всех трёх примерах `a=4`, `b=2`, поэтому `p=2`, `T(1)=1`, размеры — степени двойки.

1. `T(n)=4T(n/2)+n`. Здесь `f(n)=n=n^(2−1)`, подходит `ε=1`, случай 1. Ответ Θ(n²). На уровнях работа `n·2^j` растёт; листьев `n²`.
2. `T(n)=4T(n/2)+n²`. Здесь `f(n)=n^p`, случай 2. Каждый небазовый уровень стоит `n²`, таких уровней `log₂n`, листья тоже стоят `n²`. Ответ Θ(n² log n).
3. `T(n)=4T(n/2)+n³`. Полиномиальный зазор есть с `ε=1`. Проверяем регулярность: `4f(n/2)=4(n/2)³=n³/2`, можно взять `q=1/2<1`. Случай 3 даёт Θ(n³). Уровни стоят `n³, n³/2, n³/4,...`, сумма имеет порядок первого слагаемого.

### Когда применять нельзя

**Не та форма.** В `T(n)=T(n−1)+2n` размер уменьшается на один, а не в постоянное число раз. Постоянного `b>1`, для которого `n−1=n/b` на всех больших `n`, нет. При `T(0)=1` раскрытие даёт:

\[
T(n)=1+2(1+2+\dots+n)=1+n(n+1)=\Theta(n^2).
\]

Формула суммы получается сложением ряда с тем же рядом в обратном порядке: `n` пар по `n+1`, после чего делим на 2.

**Нет полиномиального зазора.** В `2T(n/2)+n log₂n` функция `f` больше `n`, но не на степень `n^ε`. Базовый случай 2 тоже не подходит: `f` не Θ(n). Это ограничение выбранной версии, а не невозможность решить соотношение: дерево или расширенная теорема дают другой путь. Базу тут задаём при `n=1`, а формулу — при `n≥2`.

**Не выполнена регулярность.** Пусть `a=b=2` и на `n=2^k` задана цена `f(n)=n²` при чётном `k`, `f(n)=n³` при нечётном `k`. Она всегда не меньше `n²`: полиномиальный зазор относительно `n^p=n` есть. Но для больших чётных `k`:

\[
2f(n/2)=2(n/2)^3=n^3/4,
\]

что не ограничено `q n²` ни при каком постоянном `q<1`. Более того, на этих размерах уже работа детей `T(n)≥2f(n/2)=n³/4`, так что вывод `T(n)=Θ(f(n))=Θ(n²)` был бы неверен. Поэтому одну проверку зазора нельзя выдавать за проверку третьего случая.

Остановка: M05-P3 проверяет те же навыки на других соотношениях.

## 8. Продолжение: округления и реальные размеры

В точном соотношении размер 5 нельзя молча превратить в два массива по 2,5 элемента. Если программа делит целые числа, нужно записать её действительные размеры.

`⌊x⌋` означает округление вниз, `⌈x⌉` — вверх. В C++ для неотрицательного целого `n` выражение `n/2` равно `⌊n/2⌋`. Так, `5/2` даёт 2.

### Один вызов

При базе `n≤1` и переходе `⌊n/2⌋` размер 13 проходит путь `13→6→3→1`. Число переходов — `⌊log₂n⌋` для `n≥1`: после `j` шагов остаётся `⌊n/2^j⌋`, и впервые значение 1 получается при таком `j`. Вызовов на один больше. При `n=0` сразу база: один вызов, переходов нет; логарифм нуля не используем.

Для перехода `⌈n/2⌉` при той же базе размеры 13 проходят `13→7→4→2→1`: `⌈log₂n⌉` переходов. При `n≥2` оба варианта строго уменьшают размер. База только `n=0` с округлением **вверх** была бы опасна: из `n=1` снова получится 1.

### Две части без потери элементов

Для участка длины `n≥2` берём части длины `⌊n/2⌋` и `⌈n/2⌉`. Например, `5=2+3`, затем `2=1+1`, `3=1+2`. Обе части короче исходной, их сумма ровно `n`. Участок разбивается на `[l,mid)` и `[mid,r)`, где `mid=l+(r−l)/2`.

Линейное объединение даёт точную форму

\[
T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+w(n),\qquad T(1)=d>0,
\]

где `αn≤w(n)≤βn` при `n≥2`. Пустой исходный массив обрабатываем отдельной постоянной базой `T(0)`.

Почему оценка Θ(n log n) сохраняется **для всех целых `n≥2`**? Положим `L=⌊log₂n⌋`, `H=⌈log₂n⌉`.

- На глубинах от 0 до `L−1` все части ещё имеют длину хотя бы 2. Это `L` полных небазовых уровней, длины частей на каждом суммируются в `n`. Работа каждого такого уровня не меньше `αn`.
- Небазовых уровней не больше `H`. На любом из них суммарная длина обрабатываемых частей не превосходит `n`, поэтому их работа не больше `βn`.
- Каждый лист содержит один исходный элемент, листьев ровно `n`. Их цена `dn`.

Получаем `αnL+dn≤T(n)≤βnH+dn`. Это Θ(n log n). Мы обосновали округления для этой формы, а не объявили их безвредными в произвольной рекурсии.

## 9. Один ответ можно вычислить с другой глубиной

Сумму `[6,−2,5]` можно считать и двумя частями: `[6]` даёт 6; `[−2,5]` делится на `[−2]` и `[5]`, даёт 3; затем `6+3=9`. Здесь три элемента обрабатываются так же, но ожидающие вызовы образуют более короткий путь.

```text
СУММА_ЧАСТЕЙ(a, l, r):
    если l = r: вернуть 0
    если r − l = 1: вернуть a[l]
    mid ← l + (r − l) / 2
    левая ← СУММА_ЧАСТЕЙ(a, l, mid)
    правая ← СУММА_ЧАСТЕЙ(a, mid, r)
    вернуть левая + правая
```

```cpp
long long sum_balanced(const std::vector<long long>& a, int l, int r) {
    if (l == r) {
        return 0;
    }
    if (r - l == 1) {
        return a[l];
    }
    int mid = l + (r - l) / 2;
    long long left = sum_balanced(a, l, mid);
    long long right = sum_balanced(a, mid, r);
    return left + right;
}
```

Предусловие: `0≤l≤r≤n≤512`, элементы в диапазоне §1. Целую сумму получаем через `sum_balanced(a,0,n)`. Сначала полностью заканчивается левый вызов, потом запускается правый: порядок явно задан двумя отдельными строками.

**Правильность.** Базы возвращают сумму пустого или одноэлементного участка. Для длины хотя бы 2 разбиение сохраняет все элементы и не дублирует их; обе части меньше исходной. По индукции их суммы верны, значит, верна и сумма результатов. Это одновременно задаёт меру завершения: целая длина `r−l` строго уменьшается в каждом дочернем вызове.

**Цена.** Внутренний вызов складывает только два числа, а не проходит массив заново. Поэтому на степенях двойки здесь `T(n)=2T(n/2)+Θ(1)`, **не** `+Θ(n)`. Всего для непустого участка `n` листьев и `n−1` внутренних вызовов, то есть `2n−1` вызовов: это следует индукцией из `C(n)=C(⌊n/2⌋)+C(⌈n/2⌉)+1`, `C(1)=1`. Время Θ(n).

Максимальный путь содержит `⌈log₂n⌉+1` активных кадров при `n≥1`. Массив не копируется, в кадре постоянное число значений. Память стека Θ(log(n+1)); пустой массив требует один кадр. Всё дерево вызовов целиком в памяти не хранится: законченная левая ветвь уже освобождена во время обработки правой.

| Алгоритм, `n≥2` | Работа без ввода | Максимальная дополнительная память | Причина |
| --- | --- | --- | --- |
| Сумма хвоста | Θ(n) | Θ(n) | Цепочка длины `n+1` |
| Сумма двумя частями | Θ(n) | Θ(log n) | Все элементы, но короткий активный путь |
| Один путь с делением размера пополам и постоянным шагом | Θ(log n) | Θ(log n) при рекурсивной реализации | Одна ветвь, а не всё дерево |
| Две половины и линейное объединение | Θ(n log n) | Из одного соотношения времени не следует | Нужно отдельно знать хранимые буферы; стек обычного последовательного обхода — Θ(log n) |

Рекурсия не обязательна для суммы: цикл решает её за Θ(n) времени и Θ(1) дополнительной памяти. Здесь она нужна как простой пример вызовов и анализа. C++ не гарантирует универсально допустимую глубину рекурсии или устранение вызовов оптимизатором. Предел 512 выбран для учебной программы и проверен в рабочей среде; для больших массивов в этой задаче разумно использовать цикл или вариант с короткой глубиной.

## 10. Почему число Фибоначчи не равно цене его вычисления

Короткое сравнение, без нового обязательного задания. Числа заданы как `F(0)=0`, `F(1)=1`, `F(n)=F(n−1)+F(n−2)`. Наивное рекурсивное вычисление делает **оба** вызова; одинаковые подзадачи вычисляются повторно.

Для `n=5` результат равен 5. Но число вызовов `C(0)=C(1)=1`, `C(n)=C(n−1)+C(n−2)+1` даёт `1,1,3,5,9,15` на `n=0…5`. В частности, 15 вызовов ради ответа 5. Дополнительная единица учитывает текущий вызов.

Точная связь `C(n)=2F(n+1)−1` проверяется двумя базами и подстановкой. Это не соотношение `2T(n/2)`: размеры детей `n−1` и `n−2`, а глубина — линейная. Сохранение ранее вычисленных ответов будет отдельной идеей; здесь достаточно не путать возвращаемое значение с объёмом работы. Ни код, ни сложное доказательство экспоненциальной оценки Фибоначчи в этот пакет не добавляются.
