# M05. Подсказки и разборы

Сначала открой только первый намёк. Если его мало, переходи ко второму или к полному разбору. После чтения решения полезно повторить метод на другом коротком входе.

Все обозначения и условия — из [практики](practice.md). Глубина здесь всегда включает базовый вызов, но не `main`.

## M05-P1

<details>
<summary>Подсказка 1</summary>

Какой индекс обозначает пустой хвост? Пока он не достигнут, каждый вызов ждёт ещё одного ответа.

</details>

<details>
<summary>Подсказка 2</summary>

Сначала выпиши индексы `0,1,2,3`, потом иди обратно. У ожидающего вызова известен свой элемент, но ещё не известно значение `tail`.

</details>

<details>
<summary>Полный разбор</summary>

Пусть `S(i)=sum_suffix(a,i)` для данного `[4,1,3]`.

| Вызов | Участок | Состояние в момент достижения самого глубокого вызова |
| --- | --- | --- |
| `S(0)` | `[4,1,3]` | Ждёт `S(1)`, затем прибавит 4 |
| `S(1)` | `[1,3]` | Ждёт `S(2)`, затем прибавит 1 |
| `S(2)` | `[3]` | Ждёт `S(3)`, затем прибавит 3 |
| `S(3)` | `[]` | Текущий кадр, база |

Кадры перечислены снизу вверх. У трёх ожидающих кадров `tail` ещё не получен. Возвраты:

| Возврат | Вычисление | Ответ |
| --- | --- | --- |
| `S(3)` | База | 0 |
| `S(2)` | `3+0` | 3 |
| `S(1)` | `1+3` | 4 |
| `S(0)` | `4+4` | 8 |

Всего 4 вызова, максимум 4 одновременно активных кадра, 3 сложения элементов. Для пустого массива один вызов, один кадр, ноль сложений, ответ 0. Для `[0,−2]` индексы `0→1→2`, возвраты `0→−2→−2`: ответ −2, а не 0.

Правильность следует из разбиения «первый элемент плюс хвост»; завершение — из уменьшения длины хвоста на 1. Для длины `n` работа и память обычного исполнения Θ(n+1). Сумма чисел и число вызовов — разные величины.

</details>

## M05-P2

<details>
<summary>Подсказка 1</summary>

В a посчитай переходы от `n` к 1; в b — от `2^k` к 1. В c на одном уровне задач становится вдвое больше, но каждая вдвое короче.

</details>

<details>
<summary>Подсказка 2</summary>

В a получается `T(1)+(n−1)`. В b после `j` шагов — `T(n/2^j)+j`. В c отдельно сложи работу небазовых уровней и цену `n` листьев.

</details>

<details>
<summary>Полный разбор</summary>

**a.** Для целого `n≥1` раскрываем до `T(1)`:

\[
T(n)=T(n-1)+1=T(n-2)+2=\dots=T(1)+(n-1)=n.
\]

Значит, Θ(n). При `n=1` раскрытий нет, формула всё равно даёт 1.

**b.** Для `n=2^k` получаем `T(n)=T(n/2^j)+j`. При `j=k=log₂n` достигнута база. Поэтому `T(n)=1+log₂n`. Это Θ(log n) для растущих `n≥2`; с базой можно писать Θ(1+log n).

**c.** На небазовой глубине `j` есть `2^j` узлов размера `n/2^j`; общая собственная работа — `n`. Небазовых уровней `k=log₂n`, листьев `n` по цене 1. Следовательно,

\[
T(n)=n\log_2n+n=n(\log_2n+1).
\]

Оценка Θ(n log n) при `n≥2`; формула верна и при `n=1`.

**Индукционная проверка c.** База `T(1)=1=1·(0+1)`. Предположим формулу на меньшем размере `n/2`. Тогда

\[
\begin{aligned}
T(n)&=2T(n/2)+n\\
&=2\,(n/2)(\log_2(n/2)+1)+n\\
&=n\log_2n+n.
\end{aligned}
\]

Это шаг индукции по `k`, где `n=2^k`. Предположение не используется для самого доказываемого размера. Конечность дерева следует из уменьшения `k` до 0.

| `n` | a: `n` | b: `1+log₂n` | c: `n(log₂n+1)` |
| --- | --- | --- | --- |
| 1 | 1 | 1 | 1 |
| 2 | 2 | 2 | 4 |
| 4 | 4 | 3 | 12 |
| 8 | 8 | 4 | 32 |

Это функции стоимости из условия, а не количества вызовов всех возможных программ. Например, в c собственная работа узла стоит его размер, поэтому число узлов само по себе ещё не полный ответ. Сведения о памяти из одних этих соотношений времени не следуют без описания сохраняемого состояния.

</details>

## M05-P3

<details>
<summary>Подсказка 1</summary>

Сначала прочитай размер дочерней задачи, а не только число вызовов. Для a сравни `n²` с числом листьев. Для b выпиши слагаемые, которые накапливаются при уменьшении аргумента на 1.

</details>

<details>
<summary>Подсказка 2</summary>

В a `p=1`; проверь отношение `2(n/2)²/n²`. В b попробуй сумму `1+2+...+n`; не забудь, какое первое значение уже задано базой.

</details>

<details>
<summary>Полный разбор</summary>

**a.** `a=2`, `b=2`, `f(n)=n²`, `p=log₂2=1`. Имеем `f(n)=Ω(n^(p+ε))` с `ε=1`. Для третьего случая нужна регулярность:

\[
a f(n/b)=2(n/2)^2=n^2/2\le q f(n),\qquad q=1/2<1.
\]

Оба условия выполнены; `T(n)=Θ(n²)` на заданных степенях двойки.

Проверка деревом: работа глубины `j` равна `2^j(n/2^j)²=n²/2^j`. Геометрическая сумма небазовых уровней меньше `2n²`, и уже корень стоит `n²`. Листьев `n`, цена каждого 1, что оценки не меняет. Даже точная формула доступна: для `n=2^k`

\[
T(n)=n+\sum_{j=0}^{k-1}\frac{n^2}{2^j}=2n^2-n.
\]

База `n=1` даёт 1; для 2 и 4 получаются 6 и 28. Точная формула не обязательна по условию, но проверяет подсчёт листьев.

**b.** Для `U(n)=U(n−1)+n` нет постоянного `b>1`, которое превращает все размеры `n−1` в `n/b`. Поэтому основная теорема выбранной формы неприменима.

Раскрываем при `n≥2`:

\[
U(n)=U(1)+2+3+\dots+n=1+2+\dots+n=\frac{n(n+1)}2.
\]

Следовательно, `U(n)=Θ(n²)`. Проверки: `U(1)=1`, `U(2)=1+2=3`, `U(3)=3+3=6`; формула даёт те же числа. Раскрытие заканчивается за `n−1` переходов, так как размер целый и на каждом шаге уменьшается на 1. Совпадение Θ-оценок у a и b не означает совпадения формы рекурсии или метода её решения.

</details>

## M05-P4

<details>
<summary>Подсказка 1</summary>

Проверь не только условие базы, но и аргумент в каждом вызове. Что меняется в ветви чётного `n>1`?

</details>

<details>
<summary>Подсказка 2</summary>

Возьми чётный вход 2. Затем нечётный 5: после первого деления он попадает в 2. Какой аргумент нужен, чтобы действительно посчитать ещё одно деление на 2?

</details>

<details>
<summary>Полный разбор</summary>

При `n=2` исходный код порождает `half_steps(2)→half_steps(2)→half_steps(2)→...`. Каждый вызов ждёт следующего; ни один не дошёл до базы. При `n=5` сначала получается 2, а затем та же бесконечная цепочка. Наличие базы не доказывает её достижимость.

В чётной ветви нужно передать `n/2`. После исправления обе ветви совпадают, поэтому можно оставить:

```cpp
int half_steps(int n) {
    if (n <= 1) {
        return 0;
    }
    return 1 + half_steps(n / 2);
}
```

Этот эталон есть и в [исполняемом файле](recursion.cpp). Условия: неотрицательный `int`, в этой задаче до `10⁹`; деление целочисленное.

**Правильность.** Для 0 и 1 делений не требуется, возвращаем 0. Если `n>1`, выполняем одно деление и остаётся ровно та же задача для `⌊n/2⌋`. По индукции по `n` вложенный вызов правильно считает оставшиеся деления, добавленная единица учитывает первое. Для `n≥2` имеем `0≤⌊n/2⌋<n`, значит, все цепочки конечны.

| `n` | Цепочка размеров исправленной функции | Делений, то есть результат | Вызовов и максимальных кадров |
| --- | --- | --- | --- |
| 0 | `0` | 0 | 1 |
| 1 | `1` | 0 | 1 |
| 2 | `2→1` | 1 | 2 |
| 3 | `3→1` | 1 | 2 |
| 9 | `9→4→2→1` | 3 | 4 |
| 16 | `16→8→4→2→1` | 4 | 5 |

Для `n≥1` результат `⌊log₂n⌋`, вызовов на один больше; для 0 ответ и число вызовов заданы отдельно. При постоянной работе кадра время и дополнительная память обычной рекурсивной реализации Θ(log(n+1)). Для `n=10⁹` ответ 29 и одновременно не больше 30 кадров. Большие числа в таблицу руками подставлять не требуется.

Ошибка исходного кода не «очень медленная рекурсия»: на указанных входах он не достигает результата вообще. Его успешное выполнение и оценку O(log n) заявлять нельзя. Испорченный вариант проверялся ручной трассой, запускать бесконечную рекурсию для обнаружения ошибки не нужно.

</details>
