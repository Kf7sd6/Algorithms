# M00. Как читать и выполнять программу

Пусть компьютер получил числа `6, −4, 0, 3`. Мы хотим получить их сумму: сначала 6, затем 2, снова 2 и наконец 5. Компьютеру нужно объяснить, откуда брать очередное число, что запоминать и когда остановиться. С этого и начнём.

После модуля ты сможешь вручную выполнить небольшую программу, написать подсчёт суммы и функцию подсчёта положительных чисел. Уверенное владение C++ не требуется: сначала разбираем действия, потом их запись.

## Перед началом

Достаточно складывать целые числа, в том числе отрицательные, и сравнивать их с нулём. Последовательность — несколько значений в определённом порядке; повторяющиеся значения занимают отдельные места. Например, в `2, 2, −1` три числа.

Если ещё не было [стартовой проверки](../../practice/00-diagnostic.md), начни с её части A. Она помогает выбрать глубину чтения. Уже понятные действия можно подтвердить короткой собственной попыткой и двигаться дальше.

## 1. Входные данные и требуемый результат

### Сначала конкретный ввод

Даны два числа: `8` и `−3`. Нужно вывести одно число — их сумму `5`.

| Часть задачи | В этом примере | В общем случае |
| --- | --- | --- |
| Входные данные | 8 и −3 | Два целых числа `a` и `b` |
| Требуемый результат | 5 | Одно целое число `a + b` |
| Допустимые значения | Оба подходят | Каждое число от −1 000 000 000 до 1 000 000 000 включительно |

Ограничения — часть условия. Числа вне этого диапазона в этой задаче не рассматриваются. Вход считаем корректным: оба числа действительно предоставлены.

**Алгоритм** задаёт точные действия для всех допустимых входов. **Программа** записывает эти действия на языке программирования. Один удачный пример ещё не показывает, что программа справится со всеми разрешёнными данными.

Здесь достаточно прочитать первое число, прочитать второе, сложить их и вывести сумму. Важно именно сложить значения: запись подряд символов `8` и `−3` не даст сумму.

### Псевдокод и программа

**Псевдокод** — запись действий без большинства правил конкретного языка. Имена `a`, `b`, `result` обозначают запоминаемые значения. Стрелка `←` читается «сохранить в переменной слева результат справа».

```text
прочитать a
прочитать b
result ← a + b
вывести result
```

Тот же алгоритм на C++17:

```cpp
#include <iostream>

int main() {
    long long a = 0;
    long long b = 0;
    std::cin >> a >> b;
    long long result = a + b;
    std::cout << result << '\n';
    return 0;
}
```

Как прочитать незнакомые записи:

- `#include <iostream>` подключает средства ввода и вывода.
- Выполнение начинается в `main`. Фигурные скобки `{ ... }` объединяют её команды. Обычно команда заканчивается `;`.
- `long long` — тип для целых чисел с достаточно большим диапазоном. Здесь он вмещает и вход, и сумму; расчёт диапазона разберём в §6.
- `long long a = 0;` создаёт переменную `a` с начальным значением 0. Следующая команда ввода заменит это значение прочитанным числом.
- `std::cin >> a >> b;` читает очередное число в `a`, затем следующее в `b`. Пробелы и переводы строк между числами подходят одинаково. `std::` указывает на средства стандартной библиотеки.
- `std::cout << result << '\n';` выводит результат и перевод строки. Подписи вроде «Введите число» для этих задач не нужны.
- `return 0;` завершает `main` с кодом успешного завершения. Этот ноль — не ответ задачи; ответ уже выведен через `std::cout`.

После чтения `a` равно 8, `b` равно −3. Сложение даёт 5, и именно это значение выводится. Для любого разрешённого ввода выполняется то же сложение двух полученных чисел. Повторений нет: после двух чтений, сложения и вывода программа заканчивается.

## 2. Переменная, значение и присваивание

### Как меняются значения

Начнём с числа 6. Уменьшим его на 2, запомним получившееся отдельно, затем увеличим первое число на 3.

| Выполненная команда | Значение `x` | Значение `saved` |
| --- | --- | --- |
| Создать `x` со значением 6 | 6 | ещё не создана |
| Сохранить в `x` результат `x − 2` | 4 | ещё не создана |
| Создать `saved` со значением `x` | 4 | 4 |
| Сохранить в `x` результат `x + 3` | 7 | 4 |

**Переменная** позволяет хранить значение под именем. **Значение** — конкретное число, которое хранится сейчас. Совокупность текущих значений переменных назовём **состоянием программы**. Для ручного выполнения удобно выписывать состояние после каждой команды.

**Присваивание** меняет сохранённое значение. В команде `x ← x + 3` сначала берём старое значение `x`, то есть 4, вычисляем `4 + 3`, затем записываем 7 обратно в `x`. Это не уравнение `x = x + 3`, которое нужно решить.

`saved` получает число 4, а не правило «всегда следить за `x`». Последующее изменение `x` само по себе не меняет `saved`.

```text
x ← 6
x ← x − 2
saved ← x
x ← x + 3
```

Фрагмент C++ внутри `main`:

```cpp
long long x = 6;
x = x - 2;
long long saved = x;
x = x + 3;
```

Строка с типом создаёт переменную и задаёт её начальное значение — это **инициализация**. Строка без типа с `=` меняет уже созданную переменную — это присваивание. Во всех наших примерах переменные получают начальное значение до использования.

### Присваивание и проверка равенства

| Смысл | Псевдокод этого модуля | C++ |
| --- | --- | --- |
| Записать 7 в `x` | `x ← 7` | `x = 7;` |
| Проверить, равно ли `x` семи | `x = 7` в условии | `x == 7` |
| Проверить, не равно ли `x` семи | `x ≠ 7` | `x != 7` |

При текущем `x = 4` проверка `x == 7` даёт «нет», а `x` остаётся равным 4. Присваивание `x = 7;` заменяет 4 на 7. Сравнение выдаёт логический результат: `true` означает «да», `false` — «нет».

В псевдокоде стрелка и знак равенства различаются по записи. В C++ нужно отдельно следить за `=` и `==`.

## 3. Условие и выбор ветви

### Одно из двух действий

Пусть дано `−3`. Требуется сохранить число, если оно положительное, а иначе получить 0. Положительное значит **строго больше нуля**.

Проверяем `−3 > 0`: это неверно. Значит, выбираем действие «получить 0». Для входа 4 выбрали бы «сохранить 4». Для входа 0 снова получили бы 0: ноль не положителен.

**Условие** задаёт проверку с ответом «да» или «нет». **Ветвление** выбирает, какие команды выполнить в зависимости от ответа.

```text
прочитать x
если x > 0:
    y ← x
иначе:
    y ← 0
вывести y
```

Отступ показывает, какие команды относятся к каждой ветви. В C++ это явно задают скобки:

```cpp
long long x = -3;
long long y = 0;
if (x > 0) {
    y = x;
} else {
    y = 0;
}
```

`if` читается «если», `else` — «иначе». Здесь выполнится ровно одна ветвь. Если части `else` нет и условие ложно, команды `if` пропускаются, затем выполнение продолжается после них.

Для любого целого числа есть два случая: оно либо больше нуля, либо нет. В первом случае записываем исходное число, во втором — 0. Оба случая дают требуемый результат. После выбранной ветви нет возврата к проверке, поэтому выполнение заканчивается.

| Проверка C++ | Как прочитать |
| --- | --- |
| `x > 0` | больше нуля |
| `x >= 0` | больше или равно нулю |
| `x < 0` | меньше нуля |
| `x <= 0` | меньше или равно нулю |

Ошибка `if (x = 0)` не проверяет равенство. Она записывает в `x` ноль; полученный ноль трактуется как «нет», и ветвь `if` пропускается. Для проверки равенства нужно `if (x == 0)`. Компилятор может предупредить об ошибочном присваивании в условии, но смысл записи всё равно нужно различать самому.

**Остановка:** теперь достаточно выполнить [M00-P1](practice.md#m00-p1-присваивания-и-условие). Записывай значения по строкам, не пытайся охватить программу одним взглядом.

## 4. Цикл и пошаговая сумма

### Сначала посчитаем руками

Нужно сложить последовательность `6, −4, 0, 3`. Назовём текущую сумму `sum`, а количество уже обработанных чисел — `processed`.

До первого числа ничего не сложено: `sum = 0`, `processed = 0`.

| Когда записываем состояние | Очередное число | Сумма до добавления | Сумма после добавления | Обработано чисел |
| --- | --- | --- | --- | --- |
| Начало | — | — | 0 | 0 |
| После первого числа | 6 | 0 | 6 | 1 |
| После второго числа | −4 | 6 | 2 | 2 |
| После третьего числа | 0 | 2 | 2 | 3 |
| После четвёртого числа | 3 | 2 | 5 | 4 |

На каждой строке действие одно и то же: добавить очередное число к сохранённой сумме и увеличить число обработанных элементов на 1. Ноль не изменил сумму, но **был обработан**. Отрицательное число уменьшило сумму, но тоже заняло один шаг.

### Задача и состояние

Теперь пусть числа приходят на вход программы. Сначала дано целое `n` — количество чисел. Затем идут ровно `n` целых чисел. Допускается `0 ≤ n ≤ 200 000`; каждое число от −1 000 000 000 до 1 000 000 000. Нужно вывести только сумму. Для `n = 0` сумма по договорённости равна 0. Почему тип подходит этим ограничениям — в §6.

Для примера выше полный ввод выглядит так:

```text
4
6 -4 0 3
```

Первая четвёрка задаёт длину и **не входит в сумму**. Результат — `5`.

| Имя | Что означает |
| --- | --- |
| `n` | Сколько чисел всего обещано во входе; в цикле не меняется |
| `processed` | Сколько из них уже прочитано и добавлено |
| `sum` | Сумма уже добавленных чисел |
| `x` | Одно очередное прочитанное число |

### Начало, проверка, действие, изменение

**Цикл** повторяет блок команд. Здесь перед каждым повторением проверяем, осталось ли необработанное число, то есть `processed < n`. Блок повторяемых команд называют **телом цикла**, один его проход — **итерацией**.

```text
прочитать n
processed ← 0
sum ← 0
пока processed < n:
    прочитать x
    sum ← sum + x
    processed ← processed + 1
вывести sum
```

Читаем «пока»: проверить условие → если оно истинно, выполнить всё тело сверху вниз → снова проверить условие. Если условие ложно, сразу перейти к команде после цикла.

Для `n = 4` проверка происходит так:

| Проверка перед очередным проходом | Ответ | Дальнейшее действие |
| --- | --- | --- |
| `0 < 4` | да | прочитать 6, получить `sum = 6`, `processed = 1` |
| `1 < 4` | да | прочитать −4, получить `sum = 2`, `processed = 2` |
| `2 < 4` | да | прочитать 0, получить `sum = 2`, `processed = 3` |
| `3 < 4` | да | прочитать 3, получить `sum = 5`, `processed = 4` |
| `4 < 4` | нет | ничего больше не читать, вывести 5 |

### Полная программа C++17

```cpp
#include <iostream>

int main() {
    long long n = 0;
    std::cin >> n;
    long long processed = 0;
    long long sum = 0;

    while (processed < n) {
        long long x = 0;
        std::cin >> x;
        sum = sum + x;
        processed = processed + 1;
    }

    std::cout << sum << '\n';
    return 0;
}
```

`while` означает «пока». Проверка стоит перед телом; при `n = 0` она сразу ложна. Фигурные скобки включают чтение, добавление и увеличение `processed` в один повторяемый блок. После `while (...)` перед `{` точка с запятой не ставится.

Число `x` внутри тела каждый раз получает очередное входное значение. Все прежние числа хранить не требуется: их вклад уже записан в `sum`.

### Почему сумма правильная и цикл заканчивается

До первого числа сумма равна нулю — это нужный результат для пока пустой части входа. Когда прочитано очередное число, добавляем его к сумме предыдущих. Поэтому после каждого шага `sum` содержит сумму именно тех чисел, которые уже обработаны. Ничего не пропускаем и ничего не добавляем дважды. После обработки всех `n` чисел получаем требуемую сумму.

Количество обработанных чисел начинается с 0 и увеличивается на 1 при каждом проходе независимо от знака `x`. Для конечного неотрицательного `n` оно дойдёт до `n`. Тогда проверка станет ложной. Здесь предполагается, что весь оговорённый корректный ввод предоставлен; ожидание недостающих данных — другая ситуация.

Для четырёх чисел тело выполнено четыре раза, сложение с `x` — четыре раза, а условие проверено пять раз: последняя проверка нужна для выхода. В общем случае это `n` проходов и `n + 1` проверок. Сверх самого ввода достаточно нескольких числовых переменных, длина последовательности не увеличивает их количество. Формальные обозначения стоимости появятся в M02.

### Где легко ошибиться

| Неверное действие | Что произойдёт |
| --- | --- |
| Проверять `processed <= n` при старте с 0 | Потребуется лишнее число; даже при `n = 0` тело начнёт выполняться |
| Забыть увеличение `processed` | При `n > 0` условие не приблизится к выходу; программа будет снова требовать числа |
| Обнулять `sum` внутри тела | Прежний вклад пропадёт: для `2, 3` получится 3 вместо 5 |
| Останавливаться при нулевом или отрицательном `x` | Часть допустимого входа останется необработанной |

**Остановка:** объясни последнюю ложную проверку по таблице. Затем переходи к [M00-P2](practice.md#m00-p2-сумма-последовательности). Не переписывай код до собственной попытки.

## 5. Функция считает положительные числа

### Новый пример и другой результат

В последовательности `3, −1, 0, 3, 2` нужно посчитать **количество положительных элементов**, а не их сумму. Одинаковые тройки находятся на разных местах и учитываются обе.

| Когда записываем состояние | Текущее число | Строго больше 0? | Счётчик после проверки |
| --- | --- | --- | --- |
| До прохода | — | — | 0 |
| После первого элемента | 3 | да | 1 |
| После второго элемента | −1 | нет | 1 |
| После третьего элемента | 0 | нет | 1 |
| После четвёртого элемента | 3 | да | 2 |
| После пятого элемента | 2 | да | 3 |

При успехе проверки прибавляем **единицу**, потому что найден ещё один подходящий элемент. Если прибавлять само положительное число, получится сумма положительных значений — другой ответ на другую задачу.

### Параметр, вызов и возврат

Предположим, что последовательность уже хранится под именем `data`. Подсчёт удобно оформить отдельной **функцией** — именованным блоком действий, который можно вызвать для разных данных.

Дадим функции имя `count_positive`, то есть «посчитать положительные». Её **параметр** `values` обозначает переданную последовательность внутри функции. В вызове `count_positive(data)` конкретные данные `data` являются **аргументом**. Снаружи и внутри имена могут различаться.

Функция должна **вернуть** одно число. Возвращаемое значение можно записать в переменную `answer`, затем вывести или использовать в другом вычислении. Возврат и вывод на экран — разные действия.

```text
СЧЁТ_ПОЛОЖИТЕЛЬНЫХ(values):
    count ← 0
    для каждого x из values по порядку:
        если x > 0:
            count ← count + 1
    вернуть count

data ← последовательность [3, −1, 0, 3, 2]
answer ← СЧЁТ_ПОЛОЖИТЕЛЬНЫХ(data)
вывести answer
```

`вернуть count` находится **после всего цикла**. Если вернуть результат внутри тела, функция закончит работу до проверки остальных элементов. Для пустой последовательности тело вообще не выполняется, но возврат всё равно происходит и даёт 0.

### Минимальная запись последовательности на C++

Для этого примера достаточно трёх новых записей:

- `std::vector<long long>` — готовая библиотечная последовательность целых чисел; подключается через `<vector>`. Её устройство разберём в M01. Сейчас достаточно хранить значения и проходить их по порядку.
- `const std::vector<long long>& values` — параметр, через который функция читает уже существующую последовательность без копирования. Знак `&` здесь обозначает ссылку на переданные данные, а `const` запрещает менять их через этот параметр. Подробности работы с памятью сейчас не нужны.
- `for (long long x : values)` — «для каждого числа `x` из `values`». Переход к следующему элементу и остановка в конце последовательности выполняются самой конструкцией цикла. Внутри `x` содержит копию одного текущего числа.

Запись `std::vector<long long> data{3, -1, 0, 3, 2};` создаёт последовательность с перечисленными значениями. Здесь скобки после имени содержат начальные данные; скобки после `if`, `for` или имени функции ограничивают блок команд.

```cpp
#include <iostream>
#include <vector>

long long count_positive(const std::vector<long long>& values) {
    long long count = 0;
    for (long long x : values) {
        if (x > 0) {
            count = count + 1;
        }
    }
    return count;
}

int main() {
    std::vector<long long> data{3, -1, 0, 3, 2};
    long long answer = count_positive(data);
    std::cout << answer << '\n';
    return 0;
}
```

Первое `long long` в описании функции — тип возвращаемого результата. В круглых скобках описан параметр, в фигурных — команды функции. Само описание **не запускает** подсчёт: выполнение начинается в `main`, а в функцию переходит при вызове.

При вызове для `data` создаётся свой счётчик `count = 0`, выполняется таблица выше и возвращается 3. Это число становится начальным значением `answer`; затем выполнение продолжается в `main` и печатает 3. Каждый новый вызов начинает свой подсчёт с нуля. Последовательность остаётся прежней.

### Почему подсчёт правильный и конечный

Сначала подходящих элементов ещё не проверено, поэтому счётчик равен 0. Каждый элемент проверяется ровно один раз. Положительный увеличивает число найденных на 1, неположительный не меняет его. Когда элементы закончились, посчитаны все и только положительные вхождения.

Последовательность конечна; цикл переходит к следующему элементу после каждого прохода и заканчивается после последнего. Для пяти элементов есть пять проверок `x > 0` и три увеличения счётчика. Для пустой последовательности таких проверок нет. Сама функция не создаёт новую последовательность: ей нужны счётчик, текущее число и состояние прохода; входные данные уже хранятся отдельно.

Рабочий пример с вводом `n` и затем `n` чисел есть в [count_positive.cpp](count_positive.cpp). Там `values.push_back(x)` означает «добавить прочитанное число в конец последовательности»; после заполнения вызывается та же функция. Программа выводит только количество положительных.

**Остановка:** теперь можно выполнять [M00-P3](practice.md#m00-p3-функция-подсчёта-положительных). Числа из его условия ещё не разобраны здесь.

## 6. Пустая последовательность и диапазон чисел

Эта часть дополняет те же алгоритмы и те же P2/P3. Она нужна для их корректной работы, отдельного набора упражнений нет.

### Ноль элементов и элемент со значением ноль

Ввод `0` означает: `n = 0`, после него **нет чисел последовательности**. Сумма и количество положительных равны 0. Читать ещё одно число не нужно. В C++ запись `std::vector<long long> data;` создаёт пустую последовательность.

Ввод `1 0` означает: `n = 1` и единственный элемент равен 0. Ответы снова равны 0, но один элемент должен быть прочитан и проверен. Одинаковые ответы не делают эти входы одинаковыми.

| Последовательность | Сумма | Число положительных | Что проверяет пример |
| --- | --- | --- | --- |
| `[]` | 0 | 0 | Тело цикла может не выполниться ни разу |
| `[0, 0]` | 0 | 0 | Нули являются настоящими элементами |
| `[−4, −2]` | −6 | 0 | Отрицательные участвуют в сумме |
| `[6]` | 6 | 1 | Единственный элемент не теряется |
| `[3, −3]` | 0 | 1 | Нулевая сумма не означает отсутствие положительных |

Пустую последовательность обозначаем `[]` только в объяснении. В формате ввода программы её задаёт число `n = 0`; квадратные скобки вводить не нужно.

### Почему выбран `long long`

Пусть `n ≤ 200 000`, а каждое число по модулю не больше 1 000 000 000. Модуль — величина без знака: например, модуль −4 равен 4.

Если взять 200 000 самых больших положительных чисел, сумма получится

```text
200 000 × 1 000 000 000 = 200 000 000 000 000.
```

Если все числа отрицательные с таким же модулем, получится минус эта величина. Любая промежуточная сумма тоже находится между этими границами: к этому моменту сложено не больше `n` чисел, каждое с модулем не больше миллиарда. Возможное сокращение положительных и отрицательных эту границу только уменьшает.

| Что храним | Нужный диапазон по условию | Тип в примерах |
| --- | --- | --- |
| `n`, `processed`, количество положительных | От 0 до 200 000 | `long long` |
| Одно число `x` | От −1 000 000 000 до 1 000 000 000 | `long long` |
| `sum` на любом шаге | От −200 000 000 000 000 до 200 000 000 000 000 | `long long` |

В C++17 `long long` гарантированно вмещает как минимум целые от −9 223 372 036 854 775 807 до 9 223 372 036 854 775 807. Наши числа значительно меньше. Этот тип конечен: при других ограничениях расчёт нужно сделать заново.

Распространённый 32-битный `int` вмещает числа только от −2 147 483 648 до 2 147 483 647. Три числа по миллиарду дают 3 000 000 000 — уже больше. Сам стандарт C++ не обещает, что `int` в любой среде ровно 32-битный, поэтому в примерах даже длину храним в `long long`.

Проверять только окончательный ответ недостаточно. В последовательности из трёх чисел по миллиарду и трёх чисел по минус миллиарду итог 0, но после третьего числа сумма равна 3 000 000 000. Промежуточные вычисления тоже должны помещаться в тип. Переполнение знакового целого в C++ не даёт гарантированного правильного результата; рассчитывать на «перескок через границу» нельзя. Ошибочную версию с переполнением запускать для проверки не требуется.

### Как проверять свою программу

Сначала посчитай ожидаемый ответ вручную, затем сравни с выводом. Помимо обычного смешанного входа нужны пустота, нули, отрицательные, единственный элемент и большие допустимые значения. Один правильный запуск подтверждает только этот запуск. Объяснение работы алгоритма нужно для остальных допустимых данных.

Не требуется разрабатывать обработку букв вместо чисел или неверной длины: в этих задачах ввод соответствует условию. Если программа ждёт ввод, проверь, предоставлены ли все `n` чисел и не потребовала ли она лишнее из-за ошибки границы.

## 7. Что должно получаться

- Разделять входные данные, результат и команды для его получения.
- Выписывать значения после присваивания и отличать его от проверки равенства.
- Выбирать выполняемую ветвь по текущим значениям.
- Показывать начало цикла, каждую проверку, изменения и момент остановки.
- Объяснять сумму и счётчик через уже обработанные числа.
- Различать параметр, аргумент, возврат результата и вывод на экран.
- Обрабатывать `n = 0`, нули и отрицательные числа; обосновывать тип по ограничениям.

Это критерии самопроверки, а не отметка о фактическом освоении. Следующий учебный материал — [M01 о массивах](../M01/README.md); формальные инварианты и асимптотические оценки относятся к M02.

Если компилятор уже работает, достаточно имеющейся среды с C++17. При установленном GCC файл с примером можно собрать командой `g++ -std=c++17 count_positive.cpp -o count_positive`. В Linux запуск — `./count_positive`; в Windows указывают имя полученного исполнимого файла, например `count_positive.exe`. Установка другой среды не является условием ручного разбора.
