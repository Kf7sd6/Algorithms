# M03. Подсказки и полные разборы

Сначала открой первый намёк; если его мало — второй. Полный ответ доступен отдельно. После чтения готового решения полезно повторить действие на новых данных.

Код ниже — части [structures.cpp](structures.cpp), собранные в режиме C++17. Фрагменты `Stack`/`Queue` используют `#include <array>` и `constexpr int CAPACITY = 3;`; для скобок нужны `<string>` и `<vector>`. Методы пишутся внутри соответствующей структуры.

## M03-P1

<details>
<summary>Подсказка 1</summary>

При добавлении оба правила сохраняют порядок чисел в записи. Различие возникает, когда требуется выбрать, с какого края выдавать.

</details>

<details>
<summary>Подсказка 2</summary>

После двух добавлений в записи находятся 4 и 7. В стеке следующим выдаваемым будет последний, а в очереди — первый. После каждого извлечения убери выданное число из состояния, затем продолжай команды.

</details>

<details>
<summary>Полный разбор</summary>

Стек, вершина справа:

| Команда | Возвращённое число | Состояние |
| --- | --- | --- |
| `push(4)` | — | `[4]` |
| `push(7)` | — | `[4, 7]` |
| `pop()` | 7 | `[4]` |
| `push(2)` | — | `[4, 2]` |
| `pop()` | 2 | `[4]` |
| `pop()` | 4 | `[]` |

Очередь, начало слева:

| Команда | Возвращённое число | Состояние |
| --- | --- | --- |
| `enqueue(4)` | — | `[4]` |
| `enqueue(7)` | — | `[4, 7]` |
| `dequeue()` | 4 | `[7]` |
| `enqueue(2)` | — | `[7, 2]` |
| `dequeue()` | 7 | `[2]` |
| `dequeue()` | 2 | `[]` |

Извлечения стека: 7, 2, 4; очереди: 4, 7, 2. Уже первая выдача различается: в стеке последним добавили 7, в очереди раньше поступило 4. Оба исполнения заканчиваются пустым состоянием, но это не делает порядок выдачи одинаковым.

</details>

## M03-P2.a

<details>
<summary>Подсказка 1</summary>

Первые `n` ячеек содержат стек. При добавлении нужна ещё свободная ячейка, при чтении или снятии — существующая вершина. Как эти условия выражаются через `n`?

</details>

<details>
<summary>Подсказка 2</summary>

Новая запись идёт в `a[n]`, вершина читается из `a[n−1]`. После проверки непустоты можно сначала уменьшить размер и использовать новый `n` как индекс снятого элемента. При отказе не присваивай ничего в `out`.

</details>

<details>
<summary>Полный разбор</summary>

```cpp
struct Stack {
    std::array<int, CAPACITY> a{};
    int n = 0;

    bool push(int x) {
        if (n == CAPACITY) return false;
        a[n] = x;
        ++n;
        return true;
    }

    bool pop(int& out) {
        if (n == 0) return false;
        --n;
        out = a[n];
        return true;
    }

    bool top(int& out) const {
        if (n == 0) return false;
        out = a[n - 1];
        return true;
    }
};
```

`const` у `top` означает, что размер и буфер стека не меняются. Его результат всё равно можно записать в отдельную переменную `out`.

| Команда | Успех | Выданное число | `n` | Стек |
| --- | --- | --- | --- | --- |
| `pop` | Нет | `out` остаётся 123 | 0 | `[]` |
| `push(0)` | Да | — | 1 | `[0]` |
| `push(−4)` | Да | — | 2 | `[0, −4]` |
| `push(10)` | Да | — | 3 | `[0, −4, 10]` |
| `push(25)` | Нет | — | 3 | `[0, −4, 10]` |
| `top` | Да | 10 | 3 | `[0, −4, 10]` |
| `pop` | Да | 10 | 2 | `[0, −4]` |
| `pop` | Да | −4 | 1 | `[0]` |
| `pop` | Да | 0 | 0 | `[]` |
| `pop` | Нет | `out` остаётся 0 | 0 | `[]` |
| `push(−7)` | Да | — | 1 | `[−7]` |
| `top` | Да | −7 | 1 | `[−7]` |

При `n < 3` добавление пишет в свободный допустимый индекс и увеличивает `n` не выше 3. При `n > 0` снятие уменьшает его не ниже нуля. Элементы хранятся по порядку добавления, извлекается последний действующий. Отказы происходят до изменений. Обычный пример 12, −5 выдаёт −5, затем вершина 12. Ноль успешно извлекается: признак успеха задан отдельно.

Каждая команда выполняет постоянное число действий, Θ(1) в худшем случае, циклов и сдвигов нет. Буфер размера `C` требует Θ(C) места и Θ(C) работы при показанном обнулении; служебный размер — Θ(1). Для конкретного `C = 3` оба ограничены константой. Рост памяти здесь отсутствует.

</details>

## M03-P2.b

<details>
<summary>Подсказка 1</summary>

Позиция начала меняется после извлечения. Не перемещай сами оставшиеся числа. Отдельно храни, сколько действующих элементов осталось, иначе два разных состояния могут иметь одинаковые индексы.

</details>

<details>
<summary>Подсказка 2</summary>

Логический элемент с номером `k` лежит в `(head+k) % 3`. Следующий добавляемый получает номер `n`. Перед этим проверь `n < 3`; после успешного извлечения увеличь `head` по кругу и уменьши `n`.

</details>

<details>
<summary>Полный разбор</summary>

```cpp
struct Queue {
    std::array<int, CAPACITY> a{};
    int head = 0;
    int n = 0;

    bool enqueue(int x) {
        if (n == CAPACITY) return false;
        a[(head + n) % CAPACITY] = x;
        ++n;
        return true;
    }

    bool dequeue(int& out) {
        if (n == 0) return false;
        out = a[head];
        head = (head + 1) % CAPACITY;
        --n;
        return true;
    }

    bool front(int& out) const {
        if (n == 0) return false;
        out = a[head];
        return true;
    }
};
```

| Команда | `head` | `n` | `tail` | Логическая очередь | Результат |
| --- | --- | --- | --- | --- | --- |
| `dequeue` | 0 | 0 | 0 | `[]` | Отказ, `out = 123` |
| `enqueue(10)` | 0 | 1 | 1 | `[10]` | Успех |
| `enqueue(0)` | 0 | 2 | 2 | `[10, 0]` | Успех |
| `enqueue(−4)` | 0 | 3 | 0 | `[10, 0, −4]` | Успех |
| `enqueue(25)` | 0 | 3 | 0 | `[10, 0, −4]` | Отказ |
| `dequeue` | 1 | 2 | 0 | `[0, −4]` | 10 |
| `enqueue(7)` | 1 | 3 | 1 | `[0, −4, 7]` | Успех |
| `front` | 1 | 3 | 1 | `[0, −4, 7]` | 0 |
| `dequeue` | 2 | 2 | 1 | `[−4, 7]` | 0 |
| `dequeue` | 0 | 1 | 1 | `[7]` | −4 |
| `dequeue` | 1 | 0 | 1 | `[]` | 7 |
| `dequeue` | 1 | 0 | 1 | `[]` | Отказ, `out = 7` |
| `enqueue(−8)` | 1 | 1 | 2 | `[−8]` | Успех |
| `dequeue` | 2 | 0 | 2 | `[]` | −8 |

После добавления 7 физический буфер содержит `[7, 0, −4]`. Следующий выдаваемый — 0 из ячейки 1, затем −4 из ячейки 2, затем 7 из ячейки 0. Переход головы 2 → 0 происходит при извлечении −4. При `head = tail = 0` были и пустое состояние, и полное с тремя элементами; их различает размер.

Инвариант из §3 конспекта выполняется в начале. При добавлении свободная позиция номера `n` становится новой последней; при удалении элемент с новым номером `k` имеет прежний номер `k+1`. Остальные остаются на местах и сохраняют порядок. Проверки не допускают чтения из пустоты и перезаписи при полноте. После опустошения голова не обязана быть нулём: последующая вставка −8 корректно использует ячейку 1.

Каждая команда конечна и занимает Θ(1) в худшем случае. Хранение — Θ(C), служебные индексы — Θ(1), начальное обнуление — Θ(C), отдельно от команд. Для проверки 12, −5 очередь выдаёт 12, затем `front` читает −5 без удаления.

</details>

## M03-P3.a

<details>
<summary>Подсказка 1</summary>

На рисунке отмечай имена узлов отдельно от их чисел. При удалении узел исчезает, а оставшийся путь от головы должен обходить его. Где находится входящая в удаляемый узел связь?

</details>

<details>
<summary>Подсказка 2</summary>

Для B входящая связь — `A.next`. Для A это уже внешний `head`. Перед освобождением прочитай `next` удаляемого узла. В единственном C его `next` равен `nullptr`.

</details>

<details>
<summary>Полный разбор</summary>

| Удаление | Сначала сохранить | Изменить | Затем освободить | Результат |
| --- | --- | --- | --- | --- |
| B, значение 7 | `victim = A.next`, продолжение C | `A.next = C` | B | Голова A, значения 4, 2 |
| A, значение 4 | `victim = head`, продолжение C | `head = C` | A | Голова C, значение 2 |
| C, значение 2 | `victim = head`, продолжение `nullptr` | `head = nullptr` | C | Пустой список |

У C до последнего удаления `next = nullptr`. Дополнительные обратные связи не меняются: в этой реализации их нет. После освобождения нельзя читать поля `victim` или пользоваться прежним указателем на удалённый узел.

При известном A для исключения B нужна одна запись в поле связи `A.next` плюс постоянная служебная работа. Это Θ(1) в модели освобождения одного узла за O(1). Если дано только значение 7, сначала требуется найти нужное место: в этом маленьком примере достаточно проверить 4 и затем 7. В общем списке из `n` узлов поиск может пройти всю цепочку — Θ(n+1) в худшем случае. Последующее изменение связи остаётся постоянным.

Сам указатель на последний узел не сообщает его предшественника: последний содержит только `value` и `next = nullptr`. Чтобы изменить входящую связь, в общем случае нужно искать от головы. Для единственного узла голова уже задаёт нужный особый случай, но это не даёт постоянной оценки для произвольного списка. Подмена значения не решает заявленную задачу удаления конкретного последнего объекта.

</details>

## M03-P4

<details>
<summary>Подсказка 1</summary>

Какая незавершённая открывающая скобка должна получить ближайшую закрывающую? Нужна ли информация обо всех уже завершённых парах?

</details>

<details>
<summary>Подсказка 2</summary>

Открывающую положи на вершину. Для закрывающей сначала проверь непустоту, затем вид вершины, затем сними её. После последнего символа одного отсутствия раннего отказа ещё недостаточно: проверь оставшийся стек.

</details>

<details>
<summary>Полный разбор</summary>

Например, правильная строка `()[[]]` содержит соседнюю круглую пару и вложенную квадратную. Три причины неправильности:

| Строка | Причина |
| --- | --- |
| `][` | В первом символе закрывающая не имеет открывающей слева |
| `(]` | Вершина открывает круглую пару, а закрывается квадратная |
| `(()` | После конца остаётся незавершённая открывающая |

Другие самостоятельно подобранные строки с этими разными причинами тоже подходят.

```cpp
bool brackets_ok(const std::string& s) {
    std::vector<char> pending;
    pending.reserve(s.size());
    for (char c : s) {
        if (c == '(' || c == '[') {
            pending.push_back(c);
        } else if (c == ')' || c == ']') {
            if (pending.empty()) return false;
            const char expected = (c == ')') ? '(' : '[';
            if (pending.back() != expected) return false;
            pending.pop_back();
        } else {
            return false;
        }
    }
    return pending.empty();
}
```

`std::string` — строка символов. Цикл `for (char c : s)` берёт их по порядку. `pending.empty()` проверяет пустоту; `back()` читает последний символ, `pop_back()` удаляет его без возвращаемого значения. Выражение `(c == ')') ? '(' : '['` выбирает ожидаемую открывающую по виду закрывающей. Его можно заменить обычным `if`.

Для `()[[]]` состояния стека: пуст → `(` → пуст → `[` → `[[` → `[` → пуст. Для `([])[]` алгоритм также завершится пустотой, для пустой строки цикл не исполняется и результат сразу истинен. Ветвь для постороннего символа защитно возвращает `false`; по контракту упражнения таких символов нет.

Инвариант: стек содержит в порядке появления все ещё не закрытые открывающие скобки обработанной части. Новое открытие добавляет ровно такую скобку. Закрытие обязано соответствовать вершине, иначе никакое продолжение уже не исправит порядок этой пары. Успешное закрытие удаляет одну незавершённую скобку, сохраняя инвариант. После конца пустой стек вместе с отсутствием ошибок означает, что все пары завершены и вложены правильно. Непустой стек означает оставшиеся открытия. Цикл проходит конечные `m` символов или возвращает раньше, поэтому заканчивается.

После `reserve(m)` на обработку символа нужно постоянное число действий без перераспределений. В худшем случае читаются все символы: время Θ(m+1), включая линейную верхнюю границу подготовки буфера в принятой модели выделения. Дополнительная память O(m+1), включая запас `vector`, даже при раннем отказе. Пустая строка требует постоянной служебной работы. Условие длины 200 000 позволяет проверять предел без произвольной длинной арифметики; размером контейнера управляет библиотека.

Примеры проверок: пустота, одна скобка, соседние пары, вложенные пары разных видов, скрещённое вложение, максимальная глубина. Одинаковое число открытий и закрытий само по себе правильность не доказывает.

</details>

## M03-P3.b

<details>
<summary>Подсказка 1</summary>

Сначала реши отдельно два вопроса: где будет находиться новая голова и кто отвечает за старый узел? Начни с добавления в пустоту и удаления единственного элемента.

</details>

<details>
<summary>Подсказка 2</summary>

Для удаления сохрани `victim`, прочитай из него продолжение и перенаправь голову или связь предшественника. Только после этого вызови `delete`. В очистке повторяй удаление головы, пока она не станет `nullptr`; размер очереди или счётчик здесь не нужен.

</details>

<details>
<summary>Полный разбор</summary>

Минимальный вариант для требуемых операций:

```cpp
struct Node {
    int value;
    Node* next;
};

struct SinglyList {
    Node* head = nullptr;

    SinglyList() = default;
    SinglyList(const SinglyList&) = delete;
    SinglyList& operator=(const SinglyList&) = delete;
    ~SinglyList() { clear(); }

    void push_front(int x) {
        head = new Node{x, head};
    }

    // Membership is a precondition; it is not checked by a traversal.
    bool erase_after(Node* p) {
        if (p == nullptr || p->next == nullptr) return false;
        Node* victim = p->next;
        p->next = victim->next;
        delete victim;
        return true;
    }

    bool pop_front(int& out) {
        if (head == nullptr) return false;
        Node* victim = head;
        out = victim->value;
        head = victim->next;
        delete victim;
        return true;
    }

    void clear() {
        while (head != nullptr) {
            Node* victim = head;
            head = victim->next;
            delete victim;
        }
    }
};
```

Деструктор вызывает очистку; запрет копирования не позволяет двум владельцам освободить одну цепочку. Поля узла имеют те же определения, что в конспекте. В полном исполнимом файле дополнительно показаны `find` и `insert_after`: они не являются новыми обязательными заданиями.

Для проверочного набора:

| Команда | Список после команды | Результат |
| --- | --- | --- |
| `push_front(3)` | `[3]` | — |
| `push_front(8)` | `[8, 3]` | — |
| `push_front(−1)` | `[−1, 8, 3]` | — |
| `erase_after(head)` | `[−1, 3]` | Успех, освобождён узел 8 |
| `pop_front(out)` | `[3]` | Успех, `out = −1` |
| `pop_front(out)` | `[]` | Успех, `out = 3` |
| `pop_front(out)` | `[]` | Отказ, `out` остаётся 3 |

`erase_after(nullptr)` отказывает до разыменования; `erase_after` для последнего отказывает до освобождения. Очистка пустого списка не выполняет ни одной итерации. Очистка `[0, 0, −2]` освобождает три разных узла, несмотря на повтор значений, и заканчивается пустой головой. Повторный `clear()` и последующий деструктор уже не освобождают их повторно.

Инвариант конечной цепочки живых узлов сохраняется: добавление присоединяет новый узел перед старой головой, удаление исключает один и сохраняет продолжение. При очистке за шаг число узлов уменьшается на один, поэтому она заканчивается и освобождает каждый один раз. Остальные функции не содержат циклов.

Изменение известной связи требует Θ(1), с оговорённой ценой выделения/освобождения одного узла; очистка — Θ(n+1). Вспомогательная память операций и очистки — Θ(1), хранение самих узлов — Θ(n). Поиск предшественника по значению или индексу может отдельно стоить Θ(n+1). Передавать чужой или освобождённый ненулевой указатель нельзя: проверка на `nullptr` не проверяет владение.

</details>
