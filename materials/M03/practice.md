## M03-P1. Одинаковые команды, разный порядок

Начальный стек пуст. Выполни исходную последовательность:

```text
push(4), push(7), pop(), push(2), pop(), pop()
```

После каждой команды запиши состояние стека; для `pop` — возвращённое значение. Вершину помещай справа. Вместимость здесь достаточна для всех добавлений.

Затем начни с пустой очереди и повтори те же добавления и извлечения по правилу FIFO: замени `push` на `enqueue`, `pop` на `dequeue`. Первым в записи очереди ставь следующий выдаваемый элемент. Укажи одно место, где результаты извлечения различаются, и объясни причину.

Нужны две ручные таблицы. Это исходный P1 без изменения чисел и команд.

## M03-P2.a. Стек вместимости 3

Реализуй стек целых чисел на `std::array<int, 3>` с отдельным размером `n`, изначально 0. Все входные числа помещаются в `int`. Нужны операции:

- `push(x)`: вернуть `true` и добавить число; при заполнении вернуть `false`;
- `pop(out)`: при непустоте вернуть `true` и записать удалённое число в `out`;
- `top(out)`: так же прочитать вершину, сохранив стек.

При пустоте последние две операции возвращают `false`. При любом отказе структура и `out` не меняются. Вместимость фиксирована: расширения нет. Не используй особое число вместо признака ошибки.

Проверь такой протокол, фиксируя успех, выданное число и состояние:

```text
pop, push(0), push(-4), push(10), push(25), top,
pop, pop, pop, pop, push(-7), top
```

Для первого `pop` возьми `out = 123`: после отказа должно сохраниться 123. Обычная проверка: добавление 12 и −5 в новый пустой стек, затем снятие возвращает −5, после чего вершина равна 12. Граничные случаи — пустота, четвёртое добавление, повторное использование освободившегося места.

Коротко объясни сохранение `0 ≤ n ≤ 3`, почему нет сдвигов и какова худшая стоимость одной команды. Это первая часть исходного P2.

## M03-P2.b. Кольцевая очередь вместимости 3

Реализуй очередь на таком же массиве, храня только `head` и `n`, изначально оба 0. Индекс следующей записи вычисляй по ним. Нужны `enqueue(x)`, `dequeue(out)`, `front(out)` с теми же соглашениями об успехе и неизменности при отказе. `front` читает следующий выдаваемый элемент, сохраняя очередь.

Последовательно выполни:

```text
dequeue, enqueue(10), enqueue(0), enqueue(-4), enqueue(25),
dequeue, enqueue(7), front, dequeue, dequeue, dequeue, dequeue,
enqueue(-8), dequeue
```

Для первого отказа возьми `out = 123`. После каждой команды запиши `head`, `n`, расчётный `tail` и логическую очередь. Покажи хотя бы один переход индекса через конец массива и одно полное состояние с `head = tail`.

Обычная проверка на новом объекте: добавь 12, −5; первое извлечение должно вернуть 12, `front` после него — −5. Граничные случаи: отказ при полноте и пустоте, удаление единственного элемента, новое добавление после полного опустошения.

Объясни, почему порядок оставшихся элементов сохраняется и почему одной проверки `head = tail` недостаточно. Разрешается использовать инвариант адреса логического элемента из §3. Назови время команды и память буфера, учитывая подготовку отдельно. Это вторая часть исходного P2; два контейнера не считаются одной маленькой работой.

## M03-P3.a. Сначала рисунок

Исходный односвязный список имеет три разных узла: A со значением 4, B со значением 7, C со значением 2. Голова — A, связи ведут A → B → C, после C стоит `nullptr`.

1. Удали средний B; затем из получившейся цепочки первый A; затем последний C. Не начинай каждый раз с исходного списка.
2. Для каждого удаления выпиши изменившееся поле или `head`, а также какой объект освобождается. Покажи состояние пустого списка.
3. Предположим, для первого удаления уже известен A. Сколько связей нужно изменить? Как изменится стоимость, если изначально дано только значение 7 и поиск надо выполнить по цепочке?
4. Можно ли в общем случае удалить последний узел односвязного списка за O(1), зная только указатель на него? Обоснуй ответ; не используй подмену значения вместо удаления самого узла.

Код пока не нужен. Это первая часть исходного P3 с сохранением чисел и порядка удалений. Размер для оценки — произвольное `n`; рисунок из трёх узлов служит примером, не основанием назвать всякий поиск постоянным.

## M03-P4. Проверка скобок

Напиши C++17-функцию `bool brackets_ok(const std::string& s)` для строки длины от 0 до 200 000. Допустимы только `(`, `)`, `[`, `]`. Правильная строка состоит из согласованных по виду вложенных или соседних пар. Пустая строка правильна.

Сначала придумай собственную правильную строку и три строки с **разными** причинами неправильности; поясни каждую причину. Затем запиши алгоритм со стеком и реализуй его. Не используй стек фиксированной вместимости 3 для произвольной допустимой длины. Можно взять `std::vector<char>` с предварительным `reserve(s.size())`, как объяснено в §6.

Две проверки интерфейса: `brackets_ok("([])[]")` возвращает `true`, `brackets_ok("")` тоже `true`. Для неправильно вложенной строки ответ должен быть `false`; сам такой пример подбери отдельно. Программа ввода не требуется, поэтому пустую строку можно передать прямо аргументом функции.

Обоснуй, что хранит стек после прочитанной части, почему нужна его вершина и что означает состояние после конца строки. Объясни завершение и худшие время/память через длину `m`; заранее запрошенный буфер входит в учёт памяти. Это исходный P4 с явным контрактом и коротким обоснованием, без новых задач сверху.

## Продолжение: M03-P3.b. Один маленький список

Это вторая часть **того же** исходного P3. Реализуй один односвязный список целых чисел с головой `head`; двусвязный список и дерево писать дополнительно не нужно. Копирование владельца запрети или используй готовую оболочку `SinglyList` из конспекта, оставив тела перечисленных операций себе.

Сначала сделай `push_front(x)` и `pop_front(out)`; в отдельный подход добавь `erase_after(p)` и `clear()`. Здесь нет требования написать всё за один присест.

Контракты:

- Пустая голова равна `nullptr`. Числа помещаются в `int`, выделение памяти предполагается успешным.
- `push_front` создаёт узел через `new` и делает его головой.
- `pop_front` при непустоте выдаёт число и освобождает прежнюю голову; при пустоте возвращает `false`, сохраняя `out`.
- `erase_after(p)` удаляет узел после `p`, возвращая успех. Если `p == nullptr` или следующего узла нет, верни `false`. Непустой `p` заранее является живым узлом этого списка: проверка принадлежности не требуется.
- `clear` освобождает все принадлежащие списку узлы; повторная очистка допустима. После неё `head == nullptr`. Очистка также вызывается при уничтожении владельца.

Обычная проверка на **новом** наборе: добавления в начало 3, 8, −1 дают `[−1, 8, 3]`; удаление после головы даёт `[−1, 3]`. Снятие головы выдаёт −1, следующее — 3, ещё одно отказывает. Отдельно проверь `erase_after(nullptr)`, удаление после последнего, очистку непустого и уже пустого списка. Ноль и повторы также допустимы.

Поясни порядок «сохранить продолжение → изменить входящую связь → освободить», владельца узлов и условие завершения очистки. Отдельно назови стоимость поиска предшественника и изменения уже известной связи. Для отладки можно рисовать узлы и проверять отсутствие потери цепочки; запускать заведомое обращение к освобождённой памяти не нужно.
