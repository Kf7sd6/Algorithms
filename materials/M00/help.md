# M00. Подсказки и разборы

Сначала открой только первый намёк. Второй подсказывает следующий ход; полный разбор доступен отдельно. После чтения решения полезно отложить его и повторить действие на новых коротких данных.

Все ограничения и форматы — из [практики](practice.md). Ввод считаем корректным. Здесь решения задач автора, а не подтверждённые работы пользователя.

## M00-P1

<details>
<summary>Подсказка 1</summary>

Не пытайся воспринимать `x = x + 3` как уравнение. Какое значение было у `x` непосредственно перед этой командой? Что получится, если подставить его только справа?

</details>

<details>
<summary>Подсказка 2</summary>

Заведи таблицу «команда — значение до — значение после». В строке `if` используй уже изменённое значение. Сама проверка `x > 5` ничего не записывает в `x`.

</details>

<details>
<summary>Полный разбор</summary>

| Команда | Что происходит | `x` после команды |
| --- | --- | --- |
| `x = 4;` | Сохраняем 4 | 4 |
| `x = x + 3;` | Справа используем старую четвёрку: `4 + 3 = 7`; сохраняем 7 | 7 |
| Проверка `x > 5` | `7 > 5` истинно; сама проверка `x` не меняет | 7 |
| `x = x - 2;` | Выбранная ветвь выполняется: `7 − 2 = 5` | 5 |

Итог — 5. Ветвь не проверяет условие повторно после уменьшения `x`: это один `if`, а не цикл. В момент выбора ветви значение было 7.

Присваивание `x = 5;` сохраняет число. Проверка `x == 5` отвечает на вопрос о равенстве. В условии `x > 5` используется другая проверка — строгое неравенство.

Команды выполняются по порядку, повторений нет, поэтому после ветви выполнение заканчивается.

</details>

## M00-P2

<details>
<summary>Подсказка 1</summary>

Что должна хранить сумма до первого элемента? Как отличить количество уже обработанных чисел от значения очередного числа? Ноль и отрицательные числа тоже занимают место во входе.

</details>

<details>
<summary>Подсказка 2</summary>

Начни сумму и число обработанных элементов с нуля. Пока обработано меньше `n`, прочитай одно число, добавь к сумме и увеличь число обработанных на 1. Для типа оцени сумму 200 000 чисел с наибольшим разрешённым модулем.

</details>

<details>
<summary>Полный разбор</summary>

Алгоритм словами: прочитать длину; начать с нулевой суммы; ровно `n` раз прочитать очередное число и добавить к сохранённому результату; вывести сумму.

```text
прочитать n
processed ← 0
sum ← 0
пока processed < n:
    прочитать x
    sum ← sum + x
    processed ← processed + 1
вывести sum
```

Трасса самостоятельного примера `7, 0, −5, 2`:

| Когда | Число | Сложение | `sum` после шага | `processed` после шага |
| --- | --- | --- | --- | --- |
| Начало | — | — | 0 | 0 |
| Первый проход | 7 | `0 + 7` | 7 | 1 |
| Второй проход | 0 | `7 + 0` | 7 | 2 |
| Третий проход | −5 | `7 + (−5)` | 2 | 3 |
| Четвёртый проход | 2 | `2 + 2` | 4 | 4 |

Следующая проверка `4 < 4` ложна: ни чтения, ни добавления больше нет. Ответ — 4.

Полная программа C++17:

```cpp
#include <iostream>

int main() {
    long long n = 0;
    std::cin >> n;
    long long processed = 0;
    long long sum = 0;

    while (processed < n) {
        long long x = 0;
        std::cin >> x;
        sum = sum + x;
        processed = processed + 1;
    }

    std::cout << sum << '\n';
    return 0;
}
```

Правильность: изначально чисел ещё нет, их сумма по принятой договорённости 0. Каждый шаг прибавляет одно очередное число к сумме прежних. Сразу после него `sum` — сумма всех уже обработанных элементов. По окончании обработаны все `n` элементов; значит, выведена сумма всей последовательности.

Завершение: `processed` начинает с 0, растёт на 1 при каждом проходе и доходит до `n`. Ни ноль, ни отрицательное значение `x` не мешают этому изменению. При `n = 0` первая проверка ложна, и ответ 0 выводится сразу.

По ограничениям модуль любой промежуточной суммы не больше `200 000 × 1 000 000 000 = 200 000 000 000 000`. Тип `long long` вмещает и эту величину, и отрицательную границу. Все сложения выполняются с переменными этого типа; тип выбирается заранее. Его же используем для длины и счётчика, чтобы не предполагать конкретную ширину `int`.

Ответы проверок из условия:

| Последовательность | Сумма |
| --- | --- |
| `[7, 0, −5, 2]` | 4 |
| `[0, 0, 0]` | 0 |
| `[−8, −1, −2]` | −11 |
| `[9]` | 9 |
| Четыре числа по 1 000 000 000 | 4 000 000 000 |
| `[]` | 0 |

Для примера формата: `−6 + 1 + 2 = −3`. При максимально допустимой длине и всех числах по миллиарду ответ равен 200 000 000 000 000; для всех минус миллиардов — отрицание этой величины.

Для длины 4 выполнены четыре добавления и пять проверок условия. В общем случае — `n` добавлений и `n + 1` проверок. Храним несколько числовых переменных, а не все элементы входа. Это конкретный счёт действий; формальная асимптотика пока не нужна.

Ошибка `processed <= n` при старте с 0 разрешает проход и для `processed = n`. В частности, при пустом входе программа ошибочно попытается прочитать элемент. Поэтому правильная граница — строго `< n`.

</details>

## M00-P3

<details>
<summary>Подсказка 1</summary>

Считается число подходящих мест в последовательности. Чем должно отличаться действие при числе 5 от прибавления пятёрки к сумме? Подходит ли ноль под слово «положительное»?

</details>

<details>
<summary>Подсказка 2</summary>

Перед проходом поставь счётчик в 0. Увеличивай его на 1 только при `x > 0`. Возвращать результат нужно после всего прохода — в том числе когда элементов вообще нет.

</details>

<details>
<summary>Полный разбор</summary>

Функция получает последовательность, проверяет каждый элемент и возвращает число успешных проверок:

```text
СЧЁТ_ПОЛОЖИТЕЛЬНЫХ(values):
    count ← 0
    для каждого x из values по порядку:
        если x > 0:
            count ← count + 1
    вернуть count
```

В C++17:

```cpp
long long count_positive(const std::vector<long long>& values) {
    long long count = 0;
    for (long long x : values) {
        if (x > 0) {
            count = count + 1;
        }
    }
    return count;
}
```

`values` — имя параметра внутри функции; конкретная последовательность при вызове — аргумент. Запись `const ...&` позволяет читать переданную последовательность без её копирования и изменения. `for` выдаёт по очереди каждый элемент в `x`. Первая строка функции задаёт тип возвращаемого числа — `long long`.

Трасса исходного примера `[-2, 0, 5, 5]`:

| Когда | `x` | Результат `x > 0` | Изменение `count` | Значение после |
| --- | --- | --- | --- | --- |
| До прохода | — | — | начальное значение | 0 |
| Первый элемент | −2 | нет | не меняется | 0 |
| Второй элемент | 0 | нет | не меняется | 0 |
| Третий элемент | 5 | да | `0 + 1` | 1 |
| Четвёртый элемент | 5 | да | `1 + 1` | 2 |

Функция возвращает 2. Число 10 получилось бы суммированием двух пятёрок, что не отвечает условию.

Другие проверки:

| Последовательность | Возвращаемый результат |
| --- | --- |
| `[]` | 0 |
| `[0, −6, 0]` | 0 |
| `[4, 1, 9]` | 3 |
| `[-2, 0, 5, 5]` при повторном вызове | снова 2 |

Счётчик создаётся внутри каждого вызова и начинает с нуля. После каждого проверенного элемента он равен числу положительных среди уже просмотренных. Увеличиваем его ровно тогда, когда добавился ещё один подходящий элемент. Поэтому в конце получаем число всех положительных. Конечная последовательность проходится по одному элементу до конца; для пустой цикл сразу пропускается и возвращается начальный ноль.

Если длина равна `n`, проверка `x > 0` выполняется `n` раз, а увеличение счётчика — столько раз, сколько в последовательности положительных. Сам результат находится между 0 и `n`, то есть не превышает 200 000 и помещается в `long long`. Новую последовательность функция не создаёт; данные для чтения уже переданы извне.

**Возврат не печатает:** `long long answer = count_positive(values);` сохраняет результат, и лишь `std::cout << answer;` выводит его. Если перенести `return count;` внутрь цикла, функция завершится слишком рано. Например, для `[-2, 0, 5, 5]` возврат сразу после первого элемента дал бы 0 вместо 2. Для пустого входа такой код ещё и не достиг бы возврата результата после прохода.

Полная запускаемая программа — [count_positive.cpp](count_positive.cpp). Её `main` только читает `n` и затем `n` чисел в последовательность через `values.push_back(x)`, вызывает эту функцию и выводит результат. Отдельно сохранённая последовательность нужна здесь для передачи в функцию; в задаче на сумму её хранить не требовалось. Пример ввода для исходной трассы:

```text
4
-2 0 5 5
```

Вывод:

```text
2
```

Для `0` программа выводит `0`, ничего не добавляя в последовательность. Для `3 0 -6 0` ответ тоже `0`. В обоих случаях результат соответствует формату задачи, без промежуточных сообщений.

</details>
