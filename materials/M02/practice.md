## M02-P1. Сколько сравнений сделал поиск

Дан массив `[9, −2, 6, 4, 7]`, `n = 5`. Алгоритм проверяет элементы слева направо и возвращает индекс при первом совпадении; если совпадений нет, возвращает `−1`. Индексы от 0 до `n−1`. Посчитай **только сравнения элемента с искомым значением**:

1. Ищем 9 — элемент на первом месте.
2. Ищем 7 — элемент на последнем месте.
3. Ищем 5 — его в массиве нет.

Для каждого случая укажи проверенные индексы, результат и число сравнений. Затем запиши формулы при произвольном `n ≥ 1`: первое совпадение на индексе `j`, совпадение на последнем месте, отсутствие значения. Объясни лучший и худший случаи; после §3 добавь точные по порядку оценки Θ.

Отдельно: при `n = 0` сколько сравнений **элементов** будет и что вернёт функция? Почему это не означает, что функция вообще не выполнила действий? Проверки `i < n` не входят в выбранный счёт.

Происхождение: исходное M02-P1 с тем же размером 5; явно заданы данные, метрика, индексация и пустота. Нужен письменный разбор, новая реализация не требуется.

## M02-P2.a. Что означает порядок роста

Пусть число действий описано функцией `f(n) = 6n + 5`, где `n` — положительное целое.

Докажи `f(n) = Θ(n)`: выбери положительные постоянные `c₁`, `c₂` и целый порог `n₀`, затем запиши неравенство, верное для **всех** `n ≥ n₀`. Объясни, почему из него следуют также O(n) и Ω(n). Достаточно любых подходящих констант; пределы не нужны.

Можно ли для той же функции написать O(n²)? Будет ли это означать Θ(n²)? Поясни отличие. Разрешены определения из §3 и обычные неравенства для положительных целых.

Происхождение: короткая подготовительная часть исходного M02-P2 об объяснении оценок; конкретная линейная функция добавлена для проверки смысла обозначений. Это не отдельный новый ID сверх P2. Исходные четыре суммы сохранены в P2.b.

## M02-P3. Ошибка начала и доказательство максимума

Дан алгоритм для целочисленного массива:

```text
best ← 0
для каждого элемента x массива:
    если x > best:
        best ← x
вернуть best
```

Допустимы **непустые** массивы длины до 200 000, значения от −1 000 000 000 до 1 000 000 000.

Сначала подбери свой допустимый массив, на котором результат неверен, и покажи ошибку по шагам. Затем исправь начало. Запиши псевдокод или C++17-функцию, которая возвращает значение максимума и не меняет вход; опиши её предусловие. Если пишешь C++, можно использовать параметр `const std::vector<long long>& a` из конспекта.

Для исправленного алгоритма:

1. Выполни трассу на `[-8, −3, −11]`, записывая число обработанных элементов и `best`.
2. Сформулируй инвариант с точным обработанным участком. Докажи начало, сохранение и получение ответа при выходе.
3. Отдельно докажи завершение через неотрицательную целую величину, уменьшающуюся при каждом проходе.
4. Укажи число сравнений значений, время и дополнительную память в принятой машинной модели.

Проверь один элемент `[-12]`, повторы `[2, 2, 2]`, ноль среди отрицательных `[-4, 0, −1]` и крайние значения `[−1 000 000 000, 1 000 000 000]`. Для пустого массива объясни допустимое поведение вызывающей программы; сам максимум пустоты не определяется. Не надо запускать функцию, нарушая её предусловие.

Разрешённые факты: сравнимость целых, смысл максимума конечного непустого набора, обычные свойства неравенств и невозможность бесконечного строгого уменьшения неотрицательного целого. Готовое доказательство из §4 можно использовать как образец структуры, но утверждение запиши для своей реализации.

Происхождение: исходное M02-P3, сохранены ошибка `best = 0`, исправление и доказательство. Трасса и ограничения уточняют тот же алгоритм, не добавляют новую крупную задачу.

## M02-P2.b. Четыре суммы действий

Это исходное M02-P2, продолжение после §5. Для каждой строки нужно: посчитать действия при `n = 8`, затем вывести Θ-оценку при росте `n`, объяснив верхнюю и нижнюю границы. Размер `n` — положительное целое; для четвёртой строки `n ≥ 2`. Одно выделенное действие имеет постоянную цену. Не нужно писать четыре программы.

| Строка | Сколько раз выполняется выделенное действие | Уточнение |
| --- | --- | --- |
| A | `n` | Один проход |
| B | `1 + 2 + … + n` | Последовательные блоки размеров от 1 до `n` |
| C | `n + n/2 + n/4 + …` | При `n = 2ʰ` заканчиваем слагаемым 1; в общем случае округляем каждое слагаемое вниз и заканчиваем последним положительным |
| D | `n` повторений по `log₂n` действий | Для целого счёта на произвольном `n` имеется в виду `n⌊log₂n⌋`; при степенях двойки округления не нужны |

Разрешены определения Θ и выводы арифметической и геометрической сумм из §5. Можно записать псевдокод соответствующих циклов, но оценка без объяснения не считается законченным ответом. Для C важно обосновать и случай, когда `n` не степень двойки. Для D поясни, почему внутренний процесс начинается заново в каждом из `n` повторений.

Это четыре короткие части одного исходного упражнения; разбирай их по мере чтения, а не как дополнительный листок на одно занятие.

## M02-P4. Сколько новой памяти

Входной массив из `n ≥ 1` целых уже хранится и передаётся без копирования. Сравни два варианта:

- A: дополнительно выделить массив ровно из `n` целых и хранить постоянное число служебных переменных.
- B: хранить только три целые переменные, не создавая новый массив и не вызывая рекурсию.

Укажи дополнительную память в ячейках и в Θ-обозначениях. Отдельно укажи порядок общего объёма вместе с исходным массивом. Сформулируй предположение о размере одного числа: когда допустимо считать его постоянным, а когда длина записи числа становится дополнительным параметром?

Для численного примера возьми `n = 10` и **условно** 8 байт на каждое целое; посчитай полезные ячейки дополнительного массива и трёх переменных без накладных расходов. Значения в пределах ячейки, индексы и длина представимы. Само выделение не объявляется бесплатным; оценка памяти не определяет автоматически время всех действий.

Происхождение: исходное M02-P4, уточнены учёт входа, отсутствие скрытого копирования и модель постоянного размера числа.
