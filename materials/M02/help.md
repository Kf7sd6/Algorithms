# M02. Подсказки и разборы

Сначала попробуй решить [задачу](practice.md) самостоятельно. Здесь для каждого шага два намёка и полный ответ. Ответы автора не являются результатами работы пользователя. После чтения полного разбора нужна новая короткая самостоятельная попытка, чтобы проверить владение.

## M02-P1

<details>
<summary>Подсказка 1</summary>

На какой строке алгоритм возвращает ответ? Продолжает ли он после неё проверять оставшиеся элементы? Не смешивай сравнение значения с проверкой границы цикла.

</details>

<details>
<summary>Подсказка 2</summary>

Выпиши индексы с нуля до первого совпадения включительно. Количество индексов от 0 до `j` равно `j + 1`. Если совпадения нет, исключить надо все допустимые позиции.

</details>

<details>
<summary>Полный разбор</summary>

| Ищем | Проверенные индексы | Результат поиска | Сравнения элементов |
| --- | --- | --- | --- |
| 9 | 0 | 0 | 1 |
| 7 | 0, 1, 2, 3, 4 | 4 | 5 |
| 5 | 0, 1, 2, 3, 4 | −1 | 5 |

При первом совпадении на индексе `j` получаем `j + 1` сравнение. На последнем индексе `n − 1` это `n`; при отсутствии тоже `n`. Для `n ≥ 1` лучший случай имеет стоимость 1, худший — `n`. Соответствующие оценки Θ(1) и Θ(n). Для нижней и верхней границ числа сравнений можно взять множитель 1: соответствующие функции здесь известны точно.

При `n = 0` проверять элементы нельзя и не требуется. Функция делает ноль сравнений элементов и возвращает `−1`. Но проверка `i < n` и возврат выполняются: полное время постоянно. Это другая метрика, чем число сравнений значений.

Поиск заканчивается либо ранним возвратом, либо увеличением индекса до `n`. Ранее просмотренные элементы не равны искомому; поэтому найденное совпадение первое, а после полного просмотра ответ об отсутствии верен.

</details>

## M02-P2.a

<details>
<summary>Подсказка 1</summary>

Чтобы получить Θ, нужны две границы для одной и той же функции. Как избавиться от добавки 5, заменив её сверху некоторым кратным `n` при `n ≥ 1`?

</details>

<details>
<summary>Подсказка 2</summary>

Снизу можно отбросить положительную добавку. Сверху используй `5 ≤ 5n`. Для сравнения с `n²` вспомни `n ≤ n²`, но отдельно проверь, есть ли квадратичная нижняя граница.

</details>

<details>
<summary>Полный разбор</summary>

При всех `n ≥ 1`:

$$
6n \le 6n+5 \le 6n+5n = 11n.
$$

Подходят `c₁ = 6`, `c₂ = 11`, `n₀ = 1`. Левое неравенство доказывает Ω(n), правое — O(n); вместе они дают Θ(n).

Также `6n + 5 ≤ 11n ≤ 11n²` при `n ≥ 1`. Поэтому O(n²) верно, но менее точно. Для Θ(n²) потребовалась бы положительная константа `c`, при которой `c n² ≤ 6n + 5` для всех больших `n`. Однако `(6n + 5)/n² = 6/n + 5/n²` уменьшается к нулю. Можно обойтись без пределов: при `n ≥ 1` это отношение не больше `11/n`; выбрав `n > 11/c`, получим отношение меньше `c`. Значит, любая предложенная положительная нижняя константа нарушится на достаточно большом размере. Θ(n²) неверно.

Проверка нескольких размеров полезна для поиска арифметической ошибки, но само доказательство — неравенство для всех размеров после одного порога. Константу нельзя менять вместе с `n`.

</details>

## M02-P3

<details>
<summary>Подсказка 1</summary>

Обязан ли максимум разрешённого массива быть неотрицательным? Может ли алгоритм, который увеличивает `best` начиная с нуля, вообще вернуть отрицательное число?

</details>

<details>
<summary>Подсказка 2</summary>

Возьми первый настоящий элемент как начальный максимум. Он уже обработан, поэтому следующий индекс — 1. Сформулируй утверждение «`best` — максимум первых `i` элементов» именно перед проверкой цикла; для остановки посчитай, сколько элементов осталось.

</details>

<details>
<summary>Полный разбор</summary>

Контрпример: массив `[-5, −2]`. Начальное `best = 0`. Проверки `−5 > 0` и `−2 > 0` ложны, поэтому алгоритм возвращает 0. Но наибольший элемент массива равен −2; нуля во входе даже нет. Алгоритм ошибается на допустимом входе. Ошибка не связана с переполнением или размером массива.

Исправление: начать с первого элемента. Предусловие — массив непустой, длина и значения в заданных пределах. Постусловие — возвращено наибольшее значение входа, массив не изменён.

```text
best ← a[0]
i ← 1
пока i < n:
    если a[i] > best:
        best ← a[i]
    i ← i + 1
вернуть best
```

Функция C++17, заголовок `<vector>`:

```cpp
long long maximum_nonempty(const std::vector<long long>& a) {
    long long n = static_cast<long long>(a.size());
    long long best = a[0];
    long long i = 1;
    while (i < n) {
        if (a[i] > best) {
            best = a[i];
        }
        i = i + 1;
    }
    return best;
}
```

Параметр читает существующие данные без копирования. Приведение длины к `long long` безопасно при `n ≤ 200 000`; значения тоже помещаются в него. Арифметики над значениями, кроме сравнений, здесь нет.

Трасса для `[-8, −3, −11]`:

| Состояние перед проверкой `i < n` | `i`, число обработанных | `best` | Обработанный префикс |
| --- | --- | --- | --- |
| После начала | 1 | −8 | `[-8]` |
| После сравнения `−3 > −8` и увеличения индекса | 2 | −3 | `[-8, −3]` |
| После сравнения `−11 > −3` и увеличения индекса | 3 | −3 | Весь массив |

При `i = 3` условие ложно, возвращается −3.

Инвариант перед каждой проверкой: `1 ≤ i ≤ n`, `best` — максимум элементов участка `[0, i)`. Вход остаётся прежним.

- **Начало:** `i = 1`; первый элемент и есть максимум одноэлементного префикса. Непустота обеспечивает `i ≤ n`.
- **Сохранение:** при `i < n` элемент `a[i]` существует. Если он больше прежнего максимума, выбираем его; иначе сохраняем прежний максимум. В обоих случаях получен максимум прежнего префикса вместе с новым элементом. Увеличение `i` делает этот расширенный участок новым `[0, i)`; граница не превышает `n`.
- **Ответ:** ложность `i < n` и граница `i ≤ n` вместе дают `i = n`; следовательно, префикс стал всем массивом и `best` — нужный максимум.
- **Завершение:** `n − i` — неотрицательное целое; при каждом выполнении тела уменьшается на 1. Поэтому тело не может выполняться бесконечно. Уже при `n = 1` оно пропускается.

Получены и правильность ответа, и конечность процесса. Тело выполняется `n − 1` раз; сравнений значений тоже `n − 1`. Время Θ(n) при растущем `n`, дополнительная память Θ(1): длина, индекс и лучшее значение. Вход занимает отдельно линейную память. На каждом шаге лишь ограниченное число действий; снизу для `n ≥ 2` одних сравнений не меньше `n/2`.

| Проверка | Результат | Что показывает |
| --- | --- | --- |
| `[-12]` | −12 | Нет проходов цикла, но первый элемент возвращается |
| `[2, 2, 2]` | 2 | Строгое сравнение не мешает повторяющемуся максимуму |
| `[-4, 0, −1]` | 0 | Ноль допустим как настоящее значение |
| `[−1 000 000 000, 1 000 000 000]` | 1 000 000 000 | Оба края диапазона допустимы |

Для пустого массива вызов нарушил бы предусловие: читать `a[0]` нельзя. Вызывающая программа сначала проверяет длину и сообщает `EMPTY`, либо использует другой заранее согласованный признак отсутствия. Условный ноль нельзя выдавать за математический максимум пустоты. В [исполняемом примере](analysis_examples.cpp) пустота обработана до вызова.

</details>

## M02-P2.b

<details>
<summary>Подсказка 1</summary>

Для каждой строки выпиши действия при `n = 8`. Отличается ли «каждый раз новый блок из `log₂n` действий» от «блок каждый раз вдвое короче предыдущего»?

</details>

<details>
<summary>Подсказка 2</summary>

Для B сложи прямую и обратную записи суммы. Для C первое слагаемое уже даёт нижнюю границу, а сумма без округлений ограничивает сверху. Для D перемножаются число внешних повторений и одинаковая длина каждого внутреннего процесса.

</details>

<details>
<summary>Полный разбор</summary>

| Строка | При `n = 8` | Θ-оценка |
| --- | --- | --- |
| A | 8 | Θ(n) |
| B | `1 + 2 + 3 + 4 + 5 + 6 + 7 + 8 = 36` | Θ(n²) |
| C | `8 + 4 + 2 + 1 = 15` | Θ(n) |
| D | `8·log₂8 = 8·3 = 24` | Θ(n log n) |

**A.** Число действий равно `n`: верхняя и нижняя константы 1 при `n ≥ 1`.

**B.** Две записи суммы дают `2S = n(n + 1)`. Для `n ≥ 1`: `n²/2 ≤ S ≤ n²`, так как `n ≤ n + 1 ≤ 2n`. Подходят `c₁ = 1/2`, `c₂ = 1`, `n₀ = 1`.

**C.** При `n = 2ʰ` удвоение и вычитание дают `S = 2n − 1`. Для произвольного положительного целого `n` сумма с округлением вниз не меньше первого слагаемого `n`. Если без округления оставить те же `r + 1` слагаемых, их сумма `2n(1 − 1/2ʳ⁺¹) < 2n`. Значит `n ≤ S < 2n`; можно выбрать нижнюю константу 1 и верхнюю 2. При `n = 5` блоки были бы 5, 2, 1, всего 8, а не `2n − 1 = 9`: точная формула для степеней двойки не переносится без оговорки. Оценка Θ(n) сохраняется.

**D.** Если `n` — степень двойки, каждый внутренний процесс делает `log₂n` действий и запускается заново `n` раз. При общем `n ≥ 2` счёт из условия — `n⌊log₂n⌋`. Для `y ≥ 1` выполняется `y/2 ≤ ⌊y⌋ ≤ y`: при `1 ≤ y < 2` целая часть 1, а при `y ≥ 2` она больше `y − 1 ≥ y/2` либо равна подходящей границе. Поэтому

$$
\frac12 n\log_2n \le n\lfloor\log_2n\rfloor \le n\log_2n.
$$

Подходят `c₁ = 1/2`, `c₂ = 1`, `n₀ = 2`. Если внутреннюю величину не восстановить перед каждым внешним проходом, получится другой процесс: нельзя по одной вложенности объявить произведение.

Во всех четырёх строках стоимость выделенных действий выведена с двух сторон. В соответствующих простых циклах проверки границ и изменения счётчиков добавляют не больший порядок работы. На пустом размере в вариантах, где он разрешён программой, тело не выполняется; наличие постоянной подготовки рассматривается отдельно от суммы действий.

</details>

## M02-P4

<details>
<summary>Подсказка 1</summary>

Сколько новых значений хранится **одновременно**? Сколько раз переменная меняется, не определяет, сколько ячеек она занимает. Вход уже существует до работы сравниваемых вариантов.

</details>

<details>
<summary>Подсказка 2</summary>

Пусть одна ячейка занимает `b` байт и `b` не зависит от `n`. Тогда полезный объём нового массива — `bn`, а трёх чисел — `3b`. Добавь вход отдельно и проверь, какой член растёт.

</details>

<details>
<summary>Полный разбор</summary>

| Вариант | Дополнительные ячейки | Дополнительная память | Общая память с входом |
| --- | --- | --- | --- |
| A | `n` плюс постоянное число служебных | Θ(n) при `n ≥ 1` | Θ(n) |
| B | 3 | Θ(1) | Θ(n) |

Для A имеется нижняя граница `n` ячеек, а сверху `n + k ≤ (1 + k)n` при `n ≥ 1`, где постоянное `k` учитывает служебные переменные. Для B число новых ячеек всегда 3. Если включить исходный массив, оба варианта требуют линейную память, но это не отменяет разницы в дополнительной памяти.

В условном примере при `n = 10`, `b = 8` новый массив содержит `10·8 = 80` байт полезных ячеек; три переменные — `3·8 = 24` байта. Служебные данные и накладные расходы выделения в эти числа не включены. Они не меняют указанный порядок в названной модели с постоянными накладными расходами на объект/выделение.

Предположение: число, индекс и адрес помещаются в постоянное число машинных слов; в одной рассматриваемой реализации тип имеет фиксированный размер. Если разрешить целые с произвольно растущим числом цифр, размер числа и стоимость арифметики надо учитывать отдельно. Нельзя считать, что хранение такого целого всегда требует одну фиксированную ячейку.

Из оценки памяти не следует время Θ(1): инициализация всего нового массива требует `n` записей. Аналогично несколько переменных могут многократно использоваться в очень длинном вычислении, оставаясь постоянной дополнительной памятью.

</details>
