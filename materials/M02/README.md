# M02. Стоимость алгоритма и первые доказательства

В массиве `[8, 2, 8, 6]` ищем число 6. Проверяем четыре значения. Если искать 8, остановимся после первой проверки. Алгоритм тот же, длина та же, а количество работы разное. Научимся точно говорить, сколько работы требуется, и объяснять, почему результат верен на любом допустимом входе.

## Перед началом

Нужны три умения из [M00](../M00/README.md) и [M01](../M01/README.md): выполнять присваивание и цикл; читать `a[i]`; различать длину `n` и индексы `0…n−1`. Вспомни: у массива длины 3 последний индекс 2, а полуинтервал `[0, 3)` содержит все три элемента. Если это пока мешает, вернись к соответствующей небольшой части M01.

Код — C++17, но рассуждения можно сначала выполнить словами. Массив уже находится в памяти. Для программ здесь `0 ≤ n ≤ 200 000`, значения и искомое число — целые от −1 000 000 000 до 1 000 000 000. У максимума будет дополнительное требование `n ≥ 1`.

## 1. Что именно считаем

### Один поиск по шагам

Ищем первое вхождение 6 в `[8, 2, 8, 6]`. Результат — индекс первого совпадения, а при отсутствии возвращаем `−1`, как в M01.

| Индекс | Значение | Сравнение с 6 | Что дальше |
| --- | --- | --- | --- |
| 0 | 8 | не равно | перейти к 1 |
| 1 | 2 | не равно | перейти к 2 |
| 2 | 8 | не равно | перейти к 3 |
| 3 | 6 | равно | вернуть 3 |

Здесь четыре сравнения **значений**. Сравнение `i < n` — другое действие; его нельзя молча прибавлять к этим четырём, сохраняя прежнее название метрики.

**Размер входа** в этой задаче — число элементов `n`. **Стоимость** — число выбранных действий. Например, `C(a, x)` обозначит количество сравнений элементов с искомым значением для конкретных данных `a` и `x`. Если учитывать все основные действия с постоянной ценой, будем говорить о времени `T` в принятой модели.

**Модель вычислений** — договорённость о цене действий. Считаем чтение или запись одной ячейки, сравнение, сложение и изменение индекса действиями постоянной стоимости. Значение, индекс и промежуточный результат помещаются в машинное целое. Одно такое число занимает постоянное количество ячеек. Эта модель не делает сложение чисел с миллионом цифр одним действием. Для теоретического роста `n` предполагается, что машинное слово достаточно велико для адреса и счётчика; конкретная программа дополнительно ограничена своим диапазоном типов.

Миллисекунды зависят от компьютера, компилятора и ввода. Здесь мы их не измеряем. Асимптотический анализ будет описывать рост числа действий; он не обещает время запуска на твоём компьютере.

### Точная запись и короткий код

Стрелка в псевдокоде — присваивание, знак равенства в условии — сравнение.

```text
ПОИСК_ПЕРВОГО(a, n, x):
    i ← 0
    пока i < n:
        если a[i] = x:
            вернуть i
        i ← i + 1
    вернуть −1
```

```cpp
long long find_first(const std::vector<long long>& a, long long x) {
    long long n = static_cast<long long>(a.size());
    long long i = 0;
    while (i < n) {
        if (a[i] == x) {
            return i;
        }
        i = i + 1;
    }
    return -1;
}
```

`std::vector<long long>` и читающий параметр `const ...&` знакомы по M00: массив передаётся без копирования. Для него нужен `<vector>`. `a.size()` даёт длину; `static_cast<long long>(...)` явно переводит её к типу нашего индекса. При указанном пределе длины перевод точен. В теле читается `a[i]` только при `0 ≤ i < n`. Полная запускаемая программа — [analysis_examples.cpp](analysis_examples.cpp).

Пример читает `n`, искомое `x`, затем `n` чисел. В первой строке выводит индекс или `−1`, во второй — максимум или слово `EMPTY` для пустоты. Ввод `5 9 4 -2 9 9 1` даёт две строки: `2` и `9`. Ввод `0 5` даёт `-1` и `EMPTY`. При установленном GCC: `g++ -std=c++17 analysis_examples.cpp -o analysis_examples`; в Linux запуск `./analysis_examples`, в Windows — имя полученного `.exe`. Новая среда для ручного разбора не требуется.

До проверки индекса `i` все более ранние ячейки просмотрены и не содержат `x`. Первое совпадение поэтому даёт первое вхождение; при выходе с `i = n` исключены все места. Каждый неуспешный шаг увеличивает индекс, а успешный сразу возвращает ответ: выполнение закончится. При `n = 0` возвращается `−1` без чтения элемента.

### Счёт действий с учётом раннего возврата

Пусть первое совпадение находится на индексе `j`.

| Действие | Найдено на индексе `j` | Значения нет |
| --- | --- | --- |
| Проверка `a[i] == x` | `j + 1` | `n` |
| Проверка `i < n` | `j + 1` | `n + 1` |
| Увеличение `i` | `j` | `n` |

При совпадении на последнем месте проверок границы `n`, поскольку `return` завершает функцию до увеличения индекса и следующей проверки. При отсутствии есть заключительная ложная проверка. Два этих входа имеют одинаковые `n` сравнений значений, но разные точные счёты остальных действий.

## 2. Какой случай оцениваем

### Одинаковая длина, разные входы

В массиве из начала текста поиск 8 делает одно сравнение значений, поиск 6 — четыре, поиск 5 — тоже четыре. Для непустых массивов произвольной длины:

- **Лучший случай:** минимальная стоимость среди допустимых входов длины `n`; первое значение совпало, `C_best(n) = 1`.
- **Худший случай:** максимальная стоимость среди таких входов; совпадение только на последнем месте или его нет, `C_worst(n) = n`.

При `n = 0` сравнений элементов нет, но сама функция всё равно выполняет проверку и возврат. Нулевое число выбранных сравнений не означает отсутствие всей работы.

**Средний случай** требует договориться, какие входы и с какими вероятностями возникают. Возьмём явно ограниченную модель: значения массива различны, искомое заведомо присутствует, каждое из `n` мест одинаково вероятно. При `n = 4` число сравнений бывает 1, 2, 3 или 4 с одинаковой вероятностью; среднее равно `(1 + 2 + 3 + 4)/4 = 2,5`. Для произвольного `n` получится `(n + 1)/2`; сумму выведем в §5. Это среднее число сравнений в названной модели, а не обещание «половина массива» на каждом запуске. При другой вероятности отсутствия или расположения ответ может измениться. Например, если нужное значение всегда первое, среднее равно 1.

### Ожидаемая стоимость и амортизация

Пока достаточно различать источники усреднения:

| Что обсуждаем | По чему усредняем | Что обязательно назвать |
| --- | --- | --- |
| Средний случай по входам | По распределению допустимых входов | Какие входы вероятны и с какими вероятностями |
| Ожидаемая стоимость случайного алгоритма | По его внутренним случайным выборам, даже на фиксированном входе | Какие выборы случайны |
| Амортизированная стоимость | По операциям одной последовательности, через её общую стоимость | Какую серию рассматриваем и как ограничена её сумма |

Пример последнего различия: если серия из 6 действий стоит `1, 1, 7, 1, 1, 1`, её сумма 12, а среднее по этой серии 2. Случайность здесь не нужна; одно действие всё же стоило 7. Для амортизированной гарантии надо ограничить стоимость всех допустимых серий нужного вида; одна приведённая серия её не доказывает. Полный метод — M18. Вероятностные доказательства будут вводиться перед соответствующими алгоритмами.

**Остановка:** выполни M02-P1. Сначала подпиши, что считаешь; только затем записывай число.

## 3. От числа действий к порядку роста

### Сначала несколько размеров

В таблице приведены значения функций, а не измеренные времена. Логарифм пока посчитаем на степенях двойки: `log₂4 = 2`, потому что `2² = 4`.

| `n` | `1` | `log₂n` | `n` | `n log₂n` | `n²` |
| --- | --- | --- | --- | --- | --- |
| 4 | 1 | 2 | 4 | 8 | 16 |
| 8 | 1 | 3 | 8 | 24 | 64 |
| 16 | 1 | 4 | 16 | 64 | 256 |

Линейная функция увеличивается примерно во столько раз, во сколько увеличился `n`; квадратичная — примерно в квадрат этого числа раз. Функция `4n + 9` не равна `n`, но растёт линейно: постоянная добавка становится менее существенной по сравнению с растущей частью.

**Асимптотическая оценка** описывает поведение при достаточно больших размерах. Вместо точного числа рассматриваем верхние и нижние границы роста, допуская постоянные множители. Оценка не обязана точно описывать несколько маленьких размеров. Граничные случаи программы всё равно проверяются отдельно.

### Три обозначения с явными условиями

Рассматриваем неотрицательную функцию стоимости `f(n)` и функцию сравнения `g(n)`, положительную при достаточно больших `n`. Размеры — целые. Константы ниже выбираются один раз и **не зависят от `n`**; `n₀` — порог, начиная с которого требуется неравенство.

| Запись | Точное условие для всех `n ≥ n₀` | Смысл |
| --- | --- | --- |
| `f(n) = O(g(n))` | существуют `c > 0` и `n₀`: `0 ≤ f(n) ≤ c·g(n)` | Верхняя оценка |
| `f(n) = Ω(g(n))` | существуют `c > 0` и `n₀`: `0 ≤ c·g(n) ≤ f(n)` | Нижняя оценка |
| `f(n) = Θ(g(n))` | существуют `c₁, c₂ > 0` и `n₀`: `0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n)` | Совпадающий порядок по верхней и нижней оценкам |

O читается «о большое», Ω — «омега», Θ — «тета». Формально `O(g(n))` — класс функций, а запись с `=` означает принадлежность классу; это общепринятое сокращение, не обычное равенство двух чисел. **Точная по порядку** оценка Θ не даёт точного количества операций.

Для `f(n) = 4n + 9` при `n ≥ 1`:

$$
4n \le 4n + 9 \le 4n + 9n = 13n.
$$

Выбраны `c₁ = 4`, `c₂ = 13`, `n₀ = 1`. Получены обе оценки, значит `4n + 9 = Θ(n)`. Не нужно подбирать самые маленькие константы: достаточно подходящих.

### Где легко подменить смысл

`4n + 9 = O(n²)` тоже верно: при `n ≥ 1` имеем `4n + 9 ≤ 13n ≤ 13n²`. Но это менее точная верхняя оценка, а утверждение `4n + 9 = Θ(n²)` неверно: отношение `(4n + 9)/n²` становится сколь угодно малым, поэтому положительная постоянная нижняя граница вида `c·n²` невозможна.

Нельзя доказать `n² = O(n)`, выбрав `c = n`: это не константа. Для любой фиксированной `c` при `n > c` выполняется `n² > c·n`.

O не означает худший случай, а Ω не означает лучший. Сначала выбираем **функцию случая**, затем оцениваем её:

| Линейный поиск, `n ≥ 1` | Верхняя оценка | Нижняя оценка | Итог |
| --- | --- | --- | --- |
| Лучшее число сравнений `1` | `O(1)` | `Ω(1)` | `Θ(1)` |
| Худшее число сравнений `n` | `O(n)` | `Ω(n)` | `Θ(n)` |

Для всех основных действий поиска вывод аналогичен: лучший случай занимает постоянное время, худший — линейное. Сверху на один просмотренный элемент приходится ограниченное число действий; снизу в худшем случае уже одних сравнений `n`. Поэтому **худшее время — Θ(n)**. Это доказательство оценки конкретного алгоритма; нижняя граница для всех возможных алгоритмов — отдельный вопрос.

Оценки не заменяют сравнения на конкретном размере. Условные стоимости `100n` и `n²` при `n = 10` равны 1000 и 100; при `n = 1000` — 100 000 и 1 000 000. Асимптотически линейная функция растёт медленнее, но на первом размере её значение больше. Одинаковая Θ-оценка также не определяет победителя по секундам.

**Остановка:** M02-P2.a — одно короткое доказательство с константами. Продолжение P2.b можно оставить до §5.

## 4. Первое полное доказательство: максимум

### Данные и ход работы

В массиве `[4, −2, 9, 9, 1]` требуется вернуть наибольшее **значение**. Массив непустой. Повторы допустимы; выбирать индекс одного из равных максимумов не требуется.

Запомним первый элемент, затем сравним каждый следующий с текущим сохранённым максимумом.

| Обработанный участок | С чем сравнили | `best` после шага | Сколько элементов обработано |
| --- | --- | --- | --- |
| `[4]` | Начальное значение из `a[0]` | 4 | 1 |
| `[4, −2]` | `−2 > 4` — нет | 4 | 2 |
| `[4, −2, 9]` | `9 > 4` — да | 9 | 3 |
| `[4, −2, 9, 9]` | `9 > 9` — нет | 9 | 4 |
| Весь массив | `1 > 9` — нет | 9 | 5 |

Состояние — `best` и индекс `i` следующего элемента. **Префикс** — начальный участок массива; обработанный префикс здесь `[0, i)`. Первый элемент уже учтён при начальном присваивании, поэтому цикл начинается с `i = 1`.

```text
МАКСИМУМ(a, n):
    требуется n ≥ 1
    best ← a[0]
    i ← 1
    пока i < n:
        если a[i] > best:
            best ← a[i]
        i ← i + 1
    вернуть best
```

```cpp
// Предусловие: 1 <= a.size() <= 200000.
long long maximum_nonempty(const std::vector<long long>& a) {
    long long n = static_cast<long long>(a.size());
    long long best = a[0];
    long long i = 1;
    while (i < n) {
        if (a[i] > best) {
            best = a[i];
        }
        i = i + 1;
    }
    return best;
}
```

### Что именно доказываем

**Предусловие** описывает допустимый вход: массив существует, непуст, его длина и значения удовлетворяют ограничениям. **Постусловие** описывает требуемый результат: возвращено значение одного из элементов, не меньшее любого элемента массива; сам массив не изменён.

**Инвариант цикла** — утверждение о состоянии, которое верно в выбранной точке перед каждой проверкой условия. Здесь:

> `1 ≤ i ≤ n`, а `best` — наибольшее значение среди первых `i` элементов, то есть на участке `[0, i)`.

Инвариант относится к обработанной части. Фраза «`best` уже максимум всего массива» слишком сильна для промежуточных шагов. Фраза «`best` — какое-то число» слишком слаба, чтобы вывести ответ.

1. **Начало.** Перед первой проверкой `i = 1`, `best = a[0]`. Среди одного элемента максимум равен ему самому. Граница `1 ≤ i ≤ n` верна из непустоты.
2. **Сохранение.** Пусть утверждение верно и `i < n`. Можно прочитать `a[i]`. Если новое значение больше прежнего `best`, оно становится максимумом расширенного участка; иначе прежний максимум остаётся наибольшим. После `i ← i + 1` обработанный участок содержит ровно на один элемент больше. В его пределах снова находится сохранённый максимум, и граница индекса не превышает `n`. Массив мы не меняли.
3. **Результат при выходе.** Условие `i < n` ложно, значит `i ≥ n`; инвариант даёт `i ≤ n`. Следовательно, `i = n`, обработан весь массив и `best` — требуемое значение.
4. **Завершение.** Число оставшихся элементов `n − i` — неотрицательное целое. При выполнении тела оно положительно и уменьшается ровно на 1. Бесконечно уменьшаться так оно не может. При `i = n` цикл заканчивается. Эта величина называется **мерой завершения**; сам инвариант ещё не гарантирует остановку.

Первые три пункта объясняют: *если* цикл закончился, ответ верен. Четвёртый убирает это «если». Вместе они дают полную корректность при предусловии. Проверки на примерах полезны для поиска ошибок, а доказательство относится ко всем допустимым непустым массивам.

### Время, память и пустота

Сравнений `a[i] > best` ровно `n − 1`, проверок `i < n` ровно `n`, увеличений индекса `n − 1`. Это верно при любом порядке значений. При `n = 1` сравнений значений нет, но начальное чтение и возврат есть. Число обновлений `best` зависит от значений, однако на проход приходится постоянное число действий. Для `n ≥ 2` имеем `n/2 ≤ n − 1 ≤ n`; значит, время Θ(n) по верхней и нижней границам, дополнительная память Θ(1).

У пустого массива нет наибольшего элемента. Возвращать 0 как будто это его максимум нельзя. Наша функция имеет явное предусловие непустоты; вызывающая программа сначала проверяет длину и для пустого входа выводит `EMPTY`. Другой интерфейс мог бы возвращать отдельный признак отсутствия, но он тоже должен быть оговорён.

Начальное значение должно иметь обоснование для всего разрешённого диапазона, включая отрицательные числа. Проверь чужой вариант `best = 0` в M02-P3: сначала найди контрпример, потом напиши собственное доказательство исправления.

## 5. Продолжение: логарифм, суммы и формы циклов

В этой части считаем выполнения выделенной команды `действие`. Она имеет постоянную стоимость. Полное время включает также проверки и управление циклами; для приведённых циклов они не меняют полученный порядок при растущем `n`. Цикл «от l до r» перебирает целые с шагом 1, включая обе границы; если `l > r`, тело не выполняется.

### Деление пополам и логарифм

Пусть `m = 12`. Пока `m > 1`, делим его на 2 с отбрасыванием дробной части: `12 → 6 → 3 → 1`. Сделаны три деления. Для `m = 16`: `16 → 8 → 4 → 2 → 1`, четыре деления.

`log₂n` — число, в степень которого нужно возвести 2, чтобы получить `n`. На степенях двойки это ровно число делений пополам до 1. Знак `⌊y⌋` означает округление вниз до целого. Для произвольного целого `n ≥ 1` описанный цикл делает `⌊log₂n⌋` делений: обозначим это целое через `h`, тогда `2ʰ ≤ n < 2ʰ⁺¹`, и после `h` целочисленных делений останется 1. При `n = 1` делений ноль. Для `n = 0` логарифм здесь не определён; поведение программы рассматриваем отдельно.

```text
m ← n
пока m > 1:
    действие
    m ← ⌊m / 2⌋
```

Процесс конечен: при `m > 1` новое положительное целое строго меньше старого. Для `n ≥ 2` число повторений имеет порядок Θ(log n). С учётом постоянной работы вне тела можно писать Θ(1 + log n) для `n ≥ 1`. Все логарифмы в наших оценках двоичные; замена основания на другое фиксированное число больше 1 меняет лишь постоянный множитель, поскольку `log_b n = log₂n / log₂b`.

### Треугольная сумма

Рассмотрим четыре прохода: на первом одно действие, затем два, три и четыре. Всего `1 + 2 + 3 + 4 = 10`. Для произвольного `n` запишем сумму в двух порядках:

$$
S = 1 + 2 + \cdots + n,\qquad
S = n + (n-1) + \cdots + 1.
$$

При сложении строк каждая из `n` пар равна `n + 1`. Поэтому `2S = n(n + 1)` и

$$
S = \frac{n(n+1)}2.
$$

Знак `Σ` — сокращение для суммы: `Σ` по `i = 1…n` величин `i` означает ту же запись `1 + … + n`. При `n = 0` пустая сумма равна 0. Для `n ≥ 1`:

$$
\frac12 n^2 \le \frac{n(n+1)}2 \le n^2.
$$

Значит, число действий Θ(n²), хотя точное число не равно `n²`.

```text
для i от 0 до n−1:
    для j от 0 до i включительно:
        действие
```

### Убывающая геометрическая сумма

Пусть последовательно выполняются блоки по 8, 4, 2 и 1 действию. Всего 15. Если `n = 2ʰ`, то

$$
G = n + n/2 + \cdots + 1 = 2n - 1.
$$

Чтобы увидеть формулу, удвоим сумму: в `2G − G` все промежуточные слагаемые сократятся, останется `2n − 1`. Эквивалентная растущая запись: `1 + 2 + … + 2ʰ = 2ʰ⁺¹ − 1`.

Для произвольного целого `n ≥ 1` используем **конечную** сумму `n + ⌊n/2⌋ + ⌊n/4⌋ + …` до последнего положительного слагаемого. Снизу она не меньше первого слагаемого `n`. Сверху она меньше `2n`: без округлений сумма первых `r + 1` членов равна `2n(1 − 1/2ʳ⁺¹) < 2n`, а округления могут лишь уменьшить её. Поэтому получаем Θ(n), а не Θ(n log n).

```text
m ← n
пока m > 0:
    выполнить действие ровно m раз
    m ← ⌊m / 2⌋
```

При `n = 6` блоки имеют размеры 6, 3, 1, всего 10. При `n = 0` действий нет, остаётся постоянная работа проверки. Не надо заменять округление вниз округлением вверх в этом цикле: значение 1 тогда не уменьшится, и условие `m > 0` не станет ложным.

### Когда вложенность даёт произведение, а когда сумму

Сравним точные формы. Во всех случаях счётчики начинают заново так, как явно записано.

| Форма | Число выполнений `действие` | Порядок при растущем `n` |
| --- | --- | --- |
| Два последовательных прохода по `n` действий | `n + n` | Θ(n) |
| Для каждого из `n` значений `i` новый проход `j = 0…n−1` | `n·n` | Θ(n²) |
| Для каждого `i = 0…n−1` новый проход `j = 0…i` | `n(n + 1)/2` | Θ(n²) |
| Для каждого из `n` значений `i` заново установить `m = n` и делить до 1 | `n⌊log₂n⌋` | Θ(n log n), `n ≥ 2` |
| Один общий `j = 0`; во вложенном цикле увеличивать его до `n`, больше не обнулять | `n` во всех внутренних циклах вместе | Θ(n), включая внешний проход |

Последняя строка записывается так:

```text
j ← 0
для i от 0 до n−1:
    пока j < n:
        действие
        j ← j + 1
```

Внутренний цикл целиком выполняется при первом `i`. Затем `j = n`, и остальные проверки сразу ложны. Всего `n` внутренних действий; внешний цикл делает `n` проходов. Оба вида работы линейны, вместе они дают Θ(n). Число вложенных циклов само по себе не определяет оценку: важны их границы и изменения переменных.

Для четвёртой строки при `n = 4` каждый внутренний проход делает два деления, всего восемь действий. При `n = 1` действий ноль, но управление программой стоит постоянное время. Чтобы последовательно умножать `n` на логарифмическую стоимость, надо действительно начинать внутренний процесс заново для каждого внешнего прохода.

**Остановка:** теперь M02-P2.b. Сначала выпиши слагаемые или число повторений на маленьком размере; затем найди обе границы.

## 6. Продолжение: время и дополнительная память

### Что считать новым хранилищем

Пусть входной массив из `n` чисел уже передан функции. Если создать внутри второй массив из `n` чисел, потребуются ещё `n` числовых ячеек. Если хранить только текущий индекс, длину и лучшее значение, достаточно трёх ячеек. Размер каждого числа считаем постоянным в выбранной машинной модели.

**Дополнительная память** — наибольший объём памяти, используемой алгоритмом сверх оговорённых входных данных. Считаем одновременно живущие значения, а не сумму всех записей за время работы. Один и тот же индекс может измениться миллион раз и всё равно занимать одну ячейку.

| Вариант обработки уже сохранённого входа | Дополнительная память | Вместе с входом |
| --- | --- | --- |
| Поиск или максимум без копии массива | Θ(1) | Θ(n + 1) |
| Новый массив из `n` чисел и несколько счётчиков | Θ(n + 1), обычно пишут Θ(n) при `n ≥ 1` | Θ(n + 1) |

Пример: для `n = 6` буфер на 6 чисел при условных 8 байтах на число требует 48 байт полезных ячеек; три числа — 24 байта. Это подсчёт содержимого, не обещание о служебных накладных расходах конкретного контейнера. Инициализация всех `n` ячеек нулями занимает Θ(n) записей в нашей модели; цена одного запроса после подготовки считается отдельно.

Наша полная программа сначала читает и сохраняет вход: этот этап уже требует линейной работы и линейной памяти для данных. Поэтому лучший случай **вызова поиска в готовом массиве** — Θ(1), но весь запуск с чтением `n` чисел имеет время Θ(n + 1). Функция получает `const ...&`, поэтому скрытой копии входа при вызове нет.

При рекурсии учитывают также одновременно незавершённые вызовы: они хранят параметры и место продолжения. Если таких вызовов `d` и каждому нужно постоянное число ячеек, это Θ(d) дополнительной памяти. Сама рекурсия и примеры появятся в M05; здесь достаточно помнить, что эти данные тоже занимают место.

**Остановка:** M02-P4. Обязательно подпиши, что уже было входом и в каких единицах измеряешь память.
