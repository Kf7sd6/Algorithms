## Объяснение и порядок разбора

Эта ветка требует аккуратных определений, логики и знакомых графов. B-деревья, строки и сложные кучи не являются её предпосылками. В основном порядке она стоит поздно, но при интересе её можно начать после M13 и повторения доказательств.

Сначала формулируем задачу распознавания с ответом «да/нет». Важен размер **записи** входа: число, записанное двоично, занимает логарифмическое число битов относительно своего значения. Алгоритм, линейный по значению числа, не обязательно полиномиален по длине входа.

Класс P включает задачи распознавания с полиномиальным детерминированным алгоритмом. Для задач NP ответ «да» подтверждается сертификатом полиномиальной длины, проверяемым за полиномиальное время. NP не означает «неполиномиальные» и не исключает P; верно P⊆NP. Сертификат и алгоритм его поиска — разные вещи.

Запись `A≤pB` означает: любой вход A за полиномиальное время преобразуется во вход B с сохранением ответа. Тогда быстрый алгоритм для B дал бы быстрый алгоритм для A. Чтобы доказать трудность новой задачи B, сводим к ней уже известную трудную A. Обратное направление не доказывает нужной трудности B.

NP-полная задача одновременно принадлежит NP и NP-трудна относительно выбранного полиномиального сведения. NP-трудная задача может не входить в NP. Факт существования NP-полных задач и теорему Кука — Левина сначала принимаем как опорную теорему с объяснением идеи; воспроизведение технического доказательства с кодированием вычисления — отдельная явно отмеченная глубина.

Практический первый пример: CLIQUE сводится к INDEPENDENT SET дополнением графа; затем независимое множество связывается с вершинным покрытием дополнением множества вершин. Проверяем обе стороны «тогда и только тогда», размер преобразования и проверяемость сертификата. После этого читаем цепочку из главы: выполнимость схем/формул, 3-CNF-SAT и примеры классических NP-полных задач.

NP-полнота не означает доказанную невозможность быстрого алгоритма: вопрос P=NP остаётся открытым. Для оптимизационной задачи отдельно формулируем её пороговую задачу распознавания. Псевдополиномиальные оценки упоминаем на числовом примере; большой модуль динамического программирования ради этого пока не добавляем.

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M21-P1.** Для задачи «есть ли в графе клика размера не менее k» задать сертификат, его длину и алгоритм проверки. Отдельно описать полный перебор кандидатов.

**M21-P2.** Доказать CLIQUE≤pINDEPENDENT SET через дополнение графа, затем связь с VERTEX COVER. Проверить преобразование на графе из 5 вершин.

**M21-P3.** Заполнить схему: B∈NP; A уже NP-полна; построено A≤pB. Объяснить, что именно доказано и что сломается при обратном направлении сведения.

**M21-P4.** Выбрать один пример из главы 34, составить полное доказательство NP-полноты с двумя направлениями. Доказательство общей теоремы о выполнимости схем отметить отдельно, если оно пока прочитано только обзорно.

## Частые ошибки

- Расшифровывать NP как «задачи без полиномиального решения».
- Менять направление сведения.
- Объявлять P≠NP доказанным или требовать экспоненциального времени без дополнительных оснований.
