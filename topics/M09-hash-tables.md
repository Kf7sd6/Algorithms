**Место в программе:** Приоритет по зелёной стрелке.  
**Главы по изображению:** 11.  
**Вход:** [M03](M03-elementary-data-structures.md), [M02](M02-complexity-and-correctness.md).  
**Ориентир:** 6–10 часов первичного разбора и практики; темп уточняется по работе.

## Объяснение и порядок разбора

Для словаря задаём операции: записать значение по ключу, найти его, изменить и удалить. Например, `ученик_id → помещение`. Множество поддерживает наличие ключа без отдельного значения. Сначала реализуем такой интерфейс простым списком пар, затем улучшим поиск.

**Хеш-функция** переводит ключ в номер ячейки таблицы. Разные ключи могут попасть в одну ячейку — это коллизия. Равенство хешей не означает равенства ключей. В методе цепочек каждая ячейка хранит несколько элементов; для ответа сравниваем настоящие ключи.

При n элементах и m ячейках коэффициент заполнения `α=n/m`. При подходящих предположениях о распределении хешей ожидаемая стоимость поиска с цепочками O(1+α). Если α ограничена постоянной, это ожидаемое O(1), но худший случай всё ещё O(n). Перед анализом разбираем вероятность попадания в ячейку и ожидание длины цепочки; знания полного курса теории вероятностей не требуем.

При **открытой адресации** элементы размещены прямо в таблице. Коллизия запускает последовательность проб. После удаления нельзя бездумно объявлять ячейку «никогда не занятой»: поиск может преждевременно остановиться. Нужна согласованная стратегия, например метка удалённой позиции. Заполнение должно оставлять свободные ячейки и не приближаться неконтролируемо к 1.

Рехеширование создаёт таблицу нового размера и заново размещает элементы. Один такой шаг может быть линейным, хотя расширения при геометрическом росте можно распределить по серии вставок. Разбираем прямую адресацию, метод деления/умножения, цепочки и пробы; затем идею универсального семейства и совершенного хеширования для статического набора. Доказательства последних возвращаем на углублённом проходе, если вероятность пока не освоена.

В C++ сравниваем `unordered_map`/`unordered_set` с требуемым интерфейсом. Готовый контейнер полезен для прикладных задач, а учебную таблицу сначала строим самостоятельно.

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M09-P1.** В таблице из 5 ячеек с h(x)=x mod 5 разместить 2,7,12,3 методом цепочек. Выполнить поиск и удаление, считая реальные сравнения.

**M09-P2.** Реализовать словарь целый ключ → счётчик методом цепочек, включая обновление существующего ключа и рехеширование.

**M09-P3.** Построить пример, на котором удаление в открытой адресации простым очищением ломает поиск. Показать исправление с меткой.

**M09-P4.** Подсчитать частоты идентификаторов и сравнить хранение всех событий со словарём частот. Отдельно назвать зависимость памяти от числа различных ключей.

## Когда можно двигаться дальше

- [ ] Различаю ключ, значение, хеш и номер ячейки.
- [ ] Объясняю коллизии, α и предпосылки ожидаемой оценки.
- [ ] Понимаю, когда расширение даёт редкую дорогую операцию.

## Частые ошибки

- Называть хеш уникальным идентификатором.
- Считать худшую стоимость операций гарантированно константной.
- Терять элементы при рехешировании или удалении.
