## Объяснение и порядок разбора

Сначала выбираем размер входа n и считаем понятные действия: сравнения, чтения, записи. Затем смотрим, как число действий растёт с n. Время в миллисекундах зависит и от компьютера; оценка числа операций помогает сравнивать алгоритмы независимо от конкретного запуска.

Для поиска x слева направо лучшее расположение — первый элемент: одно сравнение. В худшем случае проверяем n элементов. Эти утверждения относятся к разным входам одинаковой длины. Для «среднего случая» необходимо определить, какие входы и с какими вероятностями встречаются.

Запись `T(n)=O(g(n))` означает верхнюю оценку: для всех достаточно больших n величина T(n) не превышает `c*g(n)` с некоторой постоянной c>0. `Ω` даёт нижнюю оценку, `Θ` — обе. Например, `3n+7=Θ(n)`. Буква O сама по себе не означает худший случай: можно оценивать лучшую, худшую или ожидаемую стоимость.

Полезные суммы: `1+…+n=n(n+1)/2`; `1+2+4+…+2^k=2^(k+1)-1`. Двоичный логарифм отвечает на вопрос, сколько делений пополам нужно до размера 1. Два вложенных цикла не всегда означают n²: надо посчитать число реальных повторений внутреннего действия. Отдельно считаем дополнительную память, включая стек рекурсивных вызовов.

Корректность начинаем с короткого утверждения о ходе работы. При поиске максимума после обработки первых k элементов переменная best содержит максимум именно этих элементов. Это **инвариант**: он верен перед началом следующего шага и сохраняется шагом. Проверяем начало, сохранение, связь с ответом и завершение. Для непустого массива best удобно инициализировать первым элементом, а для пустого заранее определить допустимое поведение.

Метод доказательства не нужно заучивать до первого примера. Сначала проговариваем утверждение на 3–5 числах, затем записываем его с k. Полная индукция понадобится в M05; вероятность — короткой вставкой перед ожидаемыми оценками M06/M08/M09.

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M02-P1.** Посчитать число сравнений линейного поиска для первого, последнего и отсутствующего элемента при n=5. Затем дать оценки для произвольного n.

**M02-P2.** Оценить суммы действий: n; 1+2+…+n; n+n/2+n/4+…; n повторений по log₂n действий. Каждую оценку объяснить, а не только назвать.

**M02-P3.** Алгоритм максимума начинает с best=0. Подобрать вход, на котором он ошибается, исправить начало и доказать инвариант для непустого массива.

**M02-P4.** Сравнить выделение массива из n элементов и хранение трёх целых переменных. Указать дополнительную память и явно назвать модель постоянного размера числа.

## Когда можно двигаться дальше

- [ ] Различаю верхнюю оценку и точный порядок роста.
- [ ] Отдельно называю размер входа, случай, время и память.
- [ ] Доказываю корректность линейного поиска или максимума через одно утверждение о пройденной части.

## Частые ошибки

- Считать O(n) точным числом операций.
- Говорить «в среднем O(1)», не называя предположений.
- Путать амортизированную оценку серии операций со средним по случайным входам.
