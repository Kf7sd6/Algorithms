# M06. Простые сортировки, слияние и быстрая сортировка

**Вход:** [M05](M05-recursion-and-recurrences.md).  
**Ориентир:** 8–12 часов первичного разбора и практики; темп уточняется по работе.

## Объяснение и порядок разбора

Сортировка переставляет элементы в требуемый порядок и сохраняет их количество. Сначала разбираем **вставки**: перед шагом отсортирован префикс, очередной элемент вставляется в нужное место со сдвигом. Затем **выбор**: находим минимум ещё не обработанной части и ставим на её начало. Это первые ясные примеры инварианта и квадратичной работы.

При **слиянии** уже упорядоченных частей достаточно сравнивать их первые ещё не взятые элементы. Оба указателя движутся только вперёд. Сортировка слиянием рекурсивно получает такие части; обычная версия занимает Θ(n log n) времени и O(n) дополнительной памяти для элементов. Рекурсивный стек учитываем отдельно, он O(log n).

У **быстрой сортировки** сначала выполняется разбиение относительно опорного элемента. Выбираем одну конкретную схему, например разбиение Ломуто с опорным в конце. Её границы и возвращаемый индекс разбираем полностью, прежде чем писать рекурсивные вызовы. Схемы Ломуто, Хоара и трёхчастное разбиение имеют разные договорённости; смешивать их нельзя.

Для разных ключей случайный выбор опорного даёт ожидаемое Θ(n log n), но худший случай остаётся Θ(n²). Двухчастное разбиение может плохо работать на множестве одинаковых ключей даже при случайном опорном; отдельно смотрим трёхчастный вариант. Простая рекурсивная реализация тратит O(log n) памяти при сбалансированных разбиениях и O(n) в худшем случае. Разбиение «на месте» не устраняет стек вызовов. Рекурсия только в меньшую часть с циклом по большей ограничивает стек O(log n).

Перед ожидаемой оценкой вводим случайный выбор, математическое ожидание и линейность ожидания на коротком примере. Устойчивость проверяем на парах `(ключ, исходный_номер)`. Для сравнительных сортировок худшая оценка Ω(n log n) получается из числа различимых перестановок; предпосылка — решение на основе сравнений.

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M06-P1.** Проследить вставки, выбор, слияние и одно разбиение на [5,2,4,2,1]. Для каждого шага назвать уже гарантированное свойство.

**M06-P2.** Самостоятельно реализовать четыре сортировки. Сравнить результаты с библиотечной сортировкой на коротких массивах; отдельно проверить сохранение всех элементов и устойчивость там, где она заявлена.

**M06-P3.** Для quicksort с последним опорным построить плохие входы: возрастающий массив и массив из равных ключей. Объяснить дерево вызовов и расход памяти.

**M06-P4.** Составить собственную таблицу времени, памяти и устойчивости конкретных реализаций. Каждое свойство подкрепить рассуждением или контрпримером.

## Частые ошибки

- Выдавать случайный опорный за гарантию O(n log n).
- Называть всю рекурсивную быструю сортировку O(1) по памяти.
- Делать вывод о корректности только по одному отсортированному примеру.
