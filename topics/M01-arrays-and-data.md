## Объяснение и порядок разбора

Структура данных задаёт способ хранить данные и связи между ними, чтобы выполнять операции. Сначала всегда выясняем, что требуется: получить элемент, найти значение, добавить, удалить, пройти по всем элементам. Одинаковый набор значений можно хранить по-разному, и стоимость операций получится разной.

**Массив** удобно представлять как подряд расположенные ячейки одного типа. У массива `[8, 3, 8, 1]` четыре элемента с индексами 0, 1, 2, 3. Длина — 4; последнего индекса 4 нет. Значение 8 встречается в двух местах: значение и индекс — разные вещи. Интервал `[l, r)` включает l и не включает r; его длина `r-l`.

Если размер элемента одинаков, адрес элемента с индексом i вычисляется из адреса начала и i. Поэтому доступ по известному индексу не требует просматривать предыдущие ячейки в обычной модели оперативной памяти. Поиск значения — другая операция: его местоположение нам неизвестно.

Вставим 6 на позицию 1 в `[8, 3, 8, 1]`, сохраняя порядок. Получится `[8, 6, 3, 8, 1]`: элементы справа пришлось сдвинуть. Чтобы удалить элемент на позиции 1, сдвигаем следующие влево. Если порядок не нужен, удаление по известному индексу можно выполнить заменой последним элементом и уменьшением длины; поиск индекса при этом всё ещё отдельная работа.

Динамический массив умеет менять длину. У `std::vector` различаем число занятых элементов (`size`) и выделенную вместимость (`capacity`). Наличие метода `push_back` не делает каждое добавление бесплатным: иногда нужен новый участок памяти и перенос элементов. Сейчас достаточно проследить этот перенос; общий анализ серии добавлений будет в M02 и M18.

**Множество** поддерживает наличие различных элементов; **словарь** связывает ключ со значением, например идентификатор ученика с именем. Это описания требуемых операций. Хеш-таблица и дерево поиска — способы их реализовать; их устройство появится позже. Для выбора структуры будем заполнять таблицу «операция → что происходит в памяти → сколько действий».

## Самостоятельная практика

Все задания ниже составлены для этой программы. Начинать с первого; остальные выполнять после соответствующего разбора. Готовое решение до собственной попытки не требуется.

**M01-P1.** Для [8, 3, 8, 1] выписать пары «индекс, значение», затем массив после вставки 6 на позицию 1 и после удаления первого элемента. Указать число перемещённых элементов.

**M01-P2.** Написать поиск первого вхождения x в массиве. Если элемента нет, вернуть -1. Для пустого массива, повторов и отсутствующего значения придумать отдельные проверки.

**M01-P3.** Реализовать вставку в заданную позицию массива с заранее достаточной вместимостью: сначала нарисовать сдвиги, потом написать код. Объяснить, почему сдвигать надо с конца.

**M01-P4.** Для телефонной книги, множества посещённых страниц и очереди к принтеру перечислить нужные операции. Пока не выбирать сложную реализацию.

## Когда можно двигаться дальше

- [ ] Не путаю индекс, значение, длину и вместимость.
- [ ] Прослеживаю вставку и удаление, сохраняя порядок.
- [ ] Могу объяснить, почему доступ по индексу и поиск значения требуют разной работы.

## Частые ошибки

- Выходить за правую границу [0, n).
- Сдвигать элементы вправо от начала и затирать ещё не перенесённые данные.
- Считать множество отдельным обязательным способом размещения ячеек.
